## 一、通用基础概念

### 1. Chamfer Distance（CD，倒角距离）
衡量**两个 3D 形状有多像**。算法是：从形状 A 表面撒 10000 个点，从形状 B 表面也撒 10000 个点；对 A 上每个点，找 B 上离它最近的点，算距离；反过来再算一遍；最后取所有距离的平均值。

- **越低越好**（0 表示两个形状完全重合）
- 直觉：CD 小 = 两个形状基本叠在一起；CD 大 = 长得不像
- 缺点是只测"表面离得近不近"，测不出拓扑、内部结构、关节对不对

### 2. F1@τ（距离阈值 τ 下的 F1）
把 CD 变成"分类准确率"的指标。设定一个距离阈值 τ，如果 A 上的一个点在 B 上有距离 < τ 的近邻，就算"命中"。然后算：
- **Precision**：A 的点命中 B 的比例
- **Recall**：B 的点命中 A 的比例
- **F1** = Precision 和 Recall 的调和平均

- **越高越好**（最高 1.0）
- 直觉：CD 是"平均差多少"，F1 是"有多少点已经足够近"

### 3. IoU / mIoU（Intersection over Union，交并比）
- **IoU**：两个形状/两个分割区域的重叠面积（或体积）除以并集面积。**越高越好**，1.0 = 完全重合。
- **mIoU**：多个类别（比如多个 part）分别算 IoU 再取平均。**mean IoU 的缩写**。
- 在 articulated 评测里，mIoU 用来衡量"你的部件分割和 GT 部件分割对得准不准"。

### 4. ICP 对齐（Iterative Closest Point）
算 CD/IoU 之前先把两个 mesh 旋转平移对齐到最佳位置。否则两个形状完全相同、只是朝向不同，也会被算成 CD 很大。ICP 就是自动找这个"最佳摆放"的算法。

### 5. 匈牙利匹配（Hungarian Matching）
当你有 5 个预测部件、5 个 GT 部件，需要**一一配对**。匈牙利算法就是自动找最优配对（让总距离最小）。配对后才能算每个部件的 CD/IoU。直觉：先确定"你的门对 GT 的门、你的抽屉对 GT 的抽屉"，再分别比较。

### 6. 水密（Watertight）
一个 mesh 是完全封闭的——没有洞、没有裂缝、每条边恰好被两个面共享。类比：一个气球是水密的（能装水），一张纸不是。

- 水密是仿真、3D 打印、体积计算的前置条件
- 报告"水密率" = 生成结果里水密的比例

### 7. 自相交（Self-Intersection）
一个 mesh 的面和自己身体穿插了（比如手指插进了自己的手掌）。**SIR（Self-Intersection Ratio）** 就是自相交面的占比，**越低越好**，0 = 无自相交。自相交的模型在仿真和制造中都会出问题。

### 8. 实体合法性（Solid validity）
B-Rep / STEP 模型在 CAD 内核（如 OpenCASCADE）里必须是合法实体：没有开口壳体、没有自相交、拓扑完整。类比：一个"合法实体"才能被机床/仿真器无歧义地理解。

### 9. 欧拉示性数（Euler Characteristic, χ）
拓扑学里的一个不变量，公式 **χ = V − E + F**（顶点数 − 边数 + 面数）。它反映形状的"孔洞数/壳数"：球是 2，环面（甜甜圈）是 0，两个球是 4。
**EECM（Exact Euler Characteristic Match）**：预测模型和 GT 的 χ 是否完全一致（二值：1 一致，0 不一致）。直觉：GT 有一个洞，你生成两个洞，χ 就对不上。

### 10. 球度（Sphericity）
衡量"物体多接近球体"：球度为 1，越复杂的形状球度越低。
**SD（Sphericity Discrepancy）**：预测物体和 GT 的球度差，**越低越好**。它从整体上衡量紧凑度差异，但比较粗略。

### 11. 离散平均曲率（Discrete Mean Curvature）
曲率描述表面弯曲程度：平面的曲率是 0，小球面曲率大。
**DMCD**：预测和 GT 的平均曲率差，**越低越好**。它衡量"表面细节的凹凸程度"像不像——比如你生成的物体太光滑（丢失螺纹/凹槽），曲率就偏低。

### 12. 悬挂边（Dangling Edge）
被少于两个面共享的边——也就是"翘出来的一片"的边。水密模型没有悬挂边。
**DangEL（Dangling Edge Length）**：所有悬挂边的总长度，**越低越好**。

### 13. 通量封闭误差（Flux Enclosure Error, FluxEE）
衡量 mesh 是否有效围出一个封闭体积的指标。可以理解为"有多少'气流'从模型内部漏出来"。**越低越好**，0 = 完美封闭。

## 二、Articulated（关节物体）专属名词

### 14. URDF（Unified Robot Description Format）
描述机器人/关节物体的标准文件格式，内容包含：link（部件）、joint（关节）、每个 joint 的 parent/child、type、origin、axis、limit、mesh 引用、惯性参数。它是"能进仿真器"的标准门票。

### 15. Link（部件/连杆）
关节物体的一个刚体部件，比如门、抽屉、柜体。

### 16. Joint（关节）
连接两个 link 的运动副。常见类型：
- **Revolute**：旋转关节（门铰链、笔记本转轴）
- **Prismatic**：平移关节（抽屉、滑轨）
- **Fixed**：固定连接（不动的连接，通常评测时合并掉）
- **Continuous**：无限旋转关节（轮子）

### 17. Parent / Child（父/子）
关节有方向性：child 相对 parent 运动。比如柜体是 parent，门是 child。这个父子关系构成一个树状图，就是后面 Graph Acc 的内容。

### 18. Joint Origin / Axis / Limit
- **Origin**：关节在 3D 空间中的位置（铰链装在哪）
- **Axis**：关节运动轴的方向（门绕竖直轴转，抽屉沿前后方向滑）
- **Limit**：运动范围（门最多开 120°，抽屉最多拉 30cm）

### 19. Exec%（URDF 解析成功率）
生成的 URDF 能被标准解析器成功加载、引用的 mesh 文件都存在。**这是第一道关卡**，URDF 都解析不了后面全免谈。目标 ≥95%。

### 20. Count Acc（部件数量准确率）
预测的非固定 link 数量和 GT 一致的比例。比如 GT 是"柜体 + 2 扇门 + 1 个抽屉 = 4 个 link"，你也得是 4 个。多一个少一个都算错。

### 21. Part mIoU
建立 part 对应后，逐 part 算 IoU 再平均。衡量"你的每个部件在几何位置上是否和 GT 对应部件重合"。**越高越好**。

### 22. Joint Type Acc（关节类型准确率）
匹配后，预测关节类型和 GT 一致的比例。GT 是旋转，你预测成平移，就算错。

### 23. Graph Acc（结构图准确率）
把所有 link 和 joint 看成一个有向图（parent→child），预测图与 GT 图完全一致的比例。这是最严格的结构指标——父子关系、连接方式全对才行。

### 24. Axis Err（轴误差）
预测的关节轴方向与 GT 轴方向的夹角，单位是弧度。**越低越好**，0 = 方向完全一致。本文档采用的成功线是 <0.25 rad（约 14.3°，Articulate-Anything 的先例）。

### 25. Origin Err（原点误差）
预测的关节安装位置与 GT 位置的欧氏距离，单位是米。**越低越好**，成功线 <50mm。

### 26. Limit IoU / Limit Err
预测的运动范围与 GT 范围的交并比（IoU）或绝对误差。比如 GT 门开 0°–120°，你预测 0°–100°，IoU 就是 100/120≈0.83。**越高越好**。

### 27. Physical Executability（物理可执行性）
把 URDF 加载进物理仿真器（SAPIEN/Isaac Sim/MuJoCo），实际驱动每个关节，观察有没有"部件飞走、关节卡死、违反物理的诡异运动"。**这是 articulated 生成最重要的实际可用性指标**。通过率目标 ≥90%。

### 28. Self-collision ratio（自碰撞率）
在全关节行程里采样多个姿态（比如门开 10°、20°…120°），检测每个姿态下物体是否"自己撞自己"（门撞到柜体）。有自碰撞的姿态占比，**越低越好**，目标 ≤5%。

### 29. 静止稳定率
把物体放到仿真器的地面上，跑 120 步，看它是否保持稳定（位移 <0.2m 且旋转 <8°）。衡量"物体放得住不放得住"。目标 ≥95%。

### 30. VLM-as-judge（VLM 当评委）
让 3 个不同家族的视觉语言模型（比如 GPT、Claude、Gemini 各一个）看生成结果的多视角渲染图（含运动关键帧），按 1–5 分打分。用来弥补"没有 GT 时无法打客观分"的问题。

### 31. Krippendorff's α / ICC
- 两者都衡量**多个评委打分的一致性**。
- α 和 ICC 越高说明评委们对"好坏"的判断越统一，分数越可信。文档建议 α>0.5、ICC>0.8。

### 32. Win rate（胜率）
用户研究里，你的模型输出被参与者认为更好的比例。比如 100 次 pairwise 对比，你的场景赢了 70 次，win rate 就是 70%。**显著高于 50% 才算真的更好**（要报 p 值）。

### 33. IK（Inverse Kinematics，逆运动学）
机器人领域术语：已知目标位置（比如要把机械臂末端送到抽屉把手处），反算出各个关节需要转多少度。这里用来做下游验证——机械臂能不能用 IK 成功操作你的生成物体。

## 三、静态 CAD 专属名词

### 34. CAD command sequence（CAD 命令序列）
CAD 建模过程可以表示为一串命令，比如：`画草图 → 拉伸 → 画圆 → 挖孔`。DeepCAD 数据集就把 178K 个模型的建模过程存成这种序列。每条命令有类型（草图/拉伸/布尔运算…）和参数（坐标、尺寸、方向…）。

### 35. Sketch-extrude（草图-拉伸）
最基础的参数化 CAD 建模方式：先画 2D 草图（sketch），再拉伸（extrude）成 3D 实体。DeepCAD 的序列就是这种形式。

### 36. Command Accuracy / Parameter Accuracy
- **Command Accuracy**：你生成的命令序列和 GT 命令序列，命令类型一致的比例（该拉伸的位置你拉伸了没有）。
- **Parameter Accuracy**：命令类型对了，参数对不对（拉伸 10mm 还是 15mm）。
- 直觉：Command Acc 是"做对了几件事"，Parameter Acc 是"每件事做得有多准"。

### 37. APCS / mAP（序列级准确率）
Average Precision of CAD Sequence，参考 TransCAD 的提法。把 CAD 序列看成"检索/分类"问题，整条序列命令+参数都对才算对。比单条命令准确率更严格。

### 38. SegE（Segment Error）
预测序列的 segment/loop 数量与 GT 数量之差（缩放后的绝对值）。**越低越好**。比如 GT 有 5 个拉伸特征，你只生成 3 个，SegE 就大。

### 39. IR（Invalidity Ratio，无效比例）
生成结果中无法转换为合法 3D mesh 的比例。**越低越好**。这是 CADmium 的第一道指标——程序都跑不出来，后面指标无从谈起。

## 四、统计与实验设计名词

### 40. ID / OOD
- **ID（In-Distribution）**：训练时见过的类别/分布。
- **OOD（Out-of-Distribution）**：训练时没见过的类别。
- 评测必须分开报，因为 OOD 成绩才真正反映泛化能力。

### 41. 95% 置信区间（95% CI）
一个区间，表示"真实平均值有 95% 的概率落在这个范围内"。区间越窄，估计越可靠。用来判断你的模型和 baseline 的差距是真实的还是随机波动。

### 42. 显著性检验 / p 值
- **p 值**：假设"你的方法和 baseline 没有差别"，p 值就是这个假设成立的概率。
- **p < 0.05**：这种差距有 95% 以上把握是真实的，不是运气。论文里说"显著优于"就是这个意思。

### 43. MAD（Median Absolute Deviation）
中位数绝对偏差，衡量数据离散度。本文档用它来设定 CD 的通过线："baseline 中位数 ±1 个 MAD 范围内"。

### 44. Worst-case 值
失败样本无法算 CD/IoU 时，给它一个最差值（CD=√3、IoU=0），防止"只报成功样本"虚高成绩。这是保持评测诚实的手段。
