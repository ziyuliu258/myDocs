## 0. 先定策略：用"证据 + 一个方向"过关，而不是用"我知道所有论文"过关

老板的测试表面上是考"知道多少论文"，实际考的是：

1. 你是否有一张**结构化的领域地图**（而不是零散记忆）；
2. 别人说一个方法时，你能否在 30 秒内**定位**它；
3. 你能否从地图里**推出一个属于自己的方向**，并说清为什么它值得做。

你三周里已经完成的东西，足以支撑这三点。汇报时把它们摆出来，而不是空谈。

## 1. 方向建议（默认选择）

### 推荐方向

> **可信验证驱动的 Articulated CAD 生成：Connector-first 规范 + 不可篡改 Harness + 可归因局部修复，并配套统一 L1–L5 评测协议。**

一句话研究问题：

> 在 agentic articulated CAD 生成中，把 spec / 测试设计 / 实现三者强制分离、冻结并由不可篡改 harness 验收，能否显著提升 URDF 可执行率、运动/物理有效性，并通过"失败归因 + 局部修复"降低修复成本？

### 为什么是它（四个理由）

1. **它正好站在 2026 年主线交汇点上**：LAM、ArtiCAD、Articraft、CADSmith 都在做 agentic CAD，但没人把你的三点同时做全：
   - 无人在 articulated 任务上做 **spec/test 冻结 + 隐藏复核 + 权限隔离**；
   - ArtiCAD 有 connector-first，但无开源代码、验证粒度弱；
   - Articraft 有 compile/probe/test harness，但没有"spec 与测试不可被 coding agent 篡改"的边界，也没有系统化的失败归因；
   - 没有公开的 articulated CAD 的 L1–L5 统一验收基准。
2. **你的资产完全对齐**：《最小可信 Harness 方案》《Unified SDK/Skill/Harness 整合方案》《3D 生成模型评测验收协议》已经是这个方向的初稿。
3. **可落地、可复现**：Articraft（Apache 2.0）SDK+harness 可直接复用，build123d + MuJoCo + PartNet-Mobility 都是现成的。两周内能跑出 v0 消融结果。
4. **PhD 可扩展**：这一个方向可以长出多篇工作——系统+消融论文、可信评测基准、失败归因方法、connector/joint schema 中间表示、曲面生成专家接入。

### 三个候选方向对比（汇报备用）

| 方向 | 优点 | 风险 | 适配度 |
|---|---|---|---|
| A. 可信验证 Articulated CAD（推荐） | 与现有资产完全对齐；两周可出 v0；差异化清晰 | 需防御"是不是只是工程"的质疑 | ★★★★★ |
| B. Joint/Connector Schema 作为生成中间表示 | 更偏模型/表示，可发方法论文 | 与 ArtiCAD/ArtLLM 近，需要训练数据 | ★★★★ |
| C. 把 B-Rep/Flow Matching 模型做成 Agent 的几何专家 | 前沿、几何含量高 | GPU 重、周期长，不适合当前窗口 | ★★★ |
| D. Agentic CAD 可信评测基准 | 已有协议初稿，社区价值高 | 单独作为 PhD 主线略薄，适合作为 Phase 1 | ★★★★ |

结论：主推 A，D 作为第一阶段交付物（benchmark），B 作为第二阶段的表示层研究。

### 汇报时一句话版本

> "我建议把 articulated CAD 生成重新定义为一个受约束的程序生成 + 可信验证问题：connector/joint schema 先于几何，spec 与测试冻结后不可篡改，harness 是唯一验收层，失败通过归因做局部修复。我的三周调研和已有方案都支持这条线，接下来两周我会用 Articraft + build123d + MuJoCo 跑出 v0 消融。"

## 5. "随便讲一个方法都能定位"的 8 字段模板

听到一个方法名，按这个顺序回答：

1. 输入 → 输出
2. 表示：mesh / SDF / UDF / NURBS / B-Rep / CAD history / program / URDF / schema
3. 生成范式：自回归 / 扩散 / Flow Matching / 检索 / 优化 / Agent
4. 时间 + 发表
5. 解决的问题：生成 / 重建 / 编辑 / 关节化 / 验证
6. 最接近的前作（1–2 篇）
7. 被谁继承或改进（1–2 篇）
8. 它的短板 / 现在为什么被降级为组件

示例——别人说 "ComplexGen"：
> 点云 → B-Rep chain complex；表示是 B-Rep 拓扑+参数曲面；范式是 Transformer 预测 + 全局优化；SIGGRAPH 2022；解决逆向工程重建；前作是 ParSeNet/点云分割拟合；后来被 Point2CAD 等继承；短板是没有 design history、只能重建不能文生。

## 6. 保命原则

- 不要试图在汇报里证明"我全都会"；要证明"我有地图，且我能从地图推出一个方向"。
- 每天至少睡 6.5–7 小时，汇报前夜 7 小时以上；缺觉会直接摧毁现场提取记忆的能力。
- 每天固定两个 25 分钟休息，不刷手机，出门走 10 分钟。
- 如果情绪持续低落、惊恐或失眠超过两天，去学校心理咨询中心，这不丢人，也不是软弱。
- 老板的 deadline 是压力测试，不是对你价值的最终判决；即使最坏情况发生，你手里这份调研和方案在申请任何地方都是硬资产。
