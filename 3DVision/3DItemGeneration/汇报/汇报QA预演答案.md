# 汇报 QA 预演答案（v1，2026-08-20）

> 用法：每个答案控制在 3–5 句。汇报前读两遍，不要逐字背；现场先给结论句，再补 1 条证据 + 1 条退路。

---

## 1. 你为什么不跟 B-Rep / Flow Matching 这条线？

不是不跟，而是把它定位成系统的几何专家层，而不是我的主线。DualBrep、Flatten The Complex 解决的是连续几何与拓扑联合生成，但不解决装配关系、joint 语义、设计意图和物理正确性——而这正是 articulated CAD 的验收瓶颈。我的系统里预留了 Geometry Specialist 接口，v0 先用 build123d，后续可以直接接入这些模型做自由曲面修复。从两周可行性看，我也需要先用可执行程序 + harness 出第一组证据，而不是先训大模型。

## 2. 你的工作和 Articraft 有什么区别？是不是重复？

Articraft 是最接近的 baseline，我明确复用它，不是重复。区别有三点：一是它没有把 spec / 测试设计 / 实现分成不同 agent 并冻结权限，coder 仍可能通过代码间接绕过或迎合测试；二是它没有隐藏复核，也没有系统化地把失败归因到 spec、几何还是测试层；三是它没有统一的 L1–L5 验收协议和归因/修复成本指标。我的问题是"可信验证边界 + 归因修复是否进一步有效"，用 Articraft 做 baseline 来回答，这恰恰需要它存在。

## 3. 这是系统工作还是算法工作？novelty 在哪里？

先承认它是 systems + verification 方向的贡献，这个方向 2026 年被 CADSmith、LAM、ArtiCAD 证明是主流且可发表。Novelty 不在"用了几个 agent"，而在三个可证伪的机制：spec/test 冻结与权限隔离、不可篡改的隐藏复核、counterexample 驱动的失败归因与局部修复；外加一个可公开复用的 L1–L5 验收协议。这些都能用消融实验量化，不是讲故事。

## 4. 你怎么保证 harness 比 VLM 检查更可靠？

VLM 是概率判断，不可复现、可被生成结果迎合，不能当最终验收；harness 是确定性计算，编译、几何测量、碰撞、物理仿真都可复现。LAM 的局限已经说明只有 VLM critic 不够。我的分工是：hard harness 只做 blocking 判定并保存不可删除的反例，VLM 只做语义审查、永远没有通过权。可靠性不是靠相信 harness，而是靠"失败可复现、判定可审计"。

## 5. 失败归因凭什么能归对？归错怎么办？

我不声称归因总是正确，而是把归因本身做成可评测的对象：在已知注入错误的故障集上测归因准确率。证据设计上，spec 违反、几何错误、测试 oracle 错误会留下不同类型的 trace（约束违反 vs 测量失败 vs 测试定义矛盾），诊断 agent 只能给判断和置信度，不能直接修改任何东西。归错时多轮循环会暴露矛盾，回退到人工/高成本路径，不让错误归因静默通过。

## 6. 数据从哪来？只测 50 个物体有没有说服力？

用 PartNet-Mobility 的常见 articulated 物体（抽屉、门、盒子、夹子、剪刀、笔记本等）先做 20–50 个的机制验证，这符合系统论文首版规模，LAM/Articraft 的评测集也是这个量级。50 个物体足够区分"通过率从 40% 到 70%"这种效应，并报告失败类别分布。规模化和多样性留给 benchmark 阶段，协议已经写好，换数据集只是配置问题。

## 7. 你的评价指标会不会被你的系统自己定义、自己通过？

不会，因为协议在实验前冻结、所有系统共用同一套，并且隐藏复核的采样和阈值不暴露给任何 agent。指标本身大多来自现有工作（exec%、joint type/axis/limit 准确率、自碰撞率、物理稳定性），不是我发明的。最后把协议和反例集开源，接受第三方复现；如果我要宣传效果，必须先通过别人能跑的同一套验收。

## 8. 你第一篇文章打算投哪？什么时候？

v0 消融出来后，先投一个有 workshop 的快速反馈窗口（例如 NeurIPS 2026 workshop 或 3DV 2027 的 workshop），把系统证据和 benchmark 协议同时放出；根据结果强度决定主会投 3DV 2027 还是 ICLR 2027。时间上，9 月完成 v0 与写作框架，10 月完成完整实验，这和我拿到的 deadline 一致。

## 9. 如果 connector-first 被证明不重要，你怎么办？

Connector-first 只是我的一个假设，不是整个 thesis 的承重墙。消融里它被单独隔离：去掉它、保留 harness + 归因，系统是否退化。如果它不重要，我就诚实报告并把它降级为可选设计，主贡献仍然是可信验证边界与局部修复。可证伪的结果也是结果。

## 10. 你打算训练任何模型吗？还是只用 API？

Phase 1 只调 LLM API + 开源 SDK，不训练，目的是快速验证机制。Phase 2 有两类训练机会：一是用 harness 产生的高质量 trace 做小模型微调（Qwen3-4B LoRA 量级，参考 NURBGen）；二是把归因器做成可训练的小分类器。Harness 的真正价值之一，是它能把"修复过程"变成可复用的训练信号，这比静态数据集更有意思。

## 11. 和 CADSmith 的 programmatic validation 有什么本质区别？

CADSmith 验证的是静态单体的几何合法性，反馈来自 OCCT 测量和 VLM 三视图，没有 articulated 的运动学、碰撞和物理验证，也没有 spec/test 冻结。我的工作是 articulated + 装配 + URDF + 物理，并把验证升级成权限边界和隐藏复核。两者不冲突，我会复用 CADSmith 的 OCCT 测量思路作为几何层工具。

## 12. 为什么不直接做 benchmark，而是先做系统？

一个没有系统证据的 benchmark，容易测不到任何系统、也说明不了什么。我两者共用同一套 L1–L5 协议：先用它驱动我的系统并得到第一组证据，再把协议和反例集作为 benchmark artifact 发布。这样 benchmark 有真实 baseline，系统有第三方可复现的验收，是同一项工作的两面。

## 13. 曲面生成（NURBS / B-Rep）在你的系统里具体是哪个模块？

是 Geometry Specialist 层。v0 阶段它由 build123d 程序 + 标准件检索组成，保证可执行和可验证；当出现程序难以表达的自由曲面，或测量显示曲面不达标时，才调用 B-Rep/Flow Matching 生成器（DualBrep、BrepGen、NURBGen 或微调模型）局部重新生成该零件面，并重新过 harness。也就是说曲面模型是受 harness 调度的专家工具，不是系统的最终输出层。
