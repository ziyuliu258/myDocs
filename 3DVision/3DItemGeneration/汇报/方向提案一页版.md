# 方向提案一页版（v1，2026-08-20）

## 方向

> **可信验证驱动的 Articulated CAD 生成（Trusted-Verification-Driven Articulated CAD Generation）**
> Connector-first 规范 + 不可篡改 Harness + 失败归因与局部修复 + 统一 L1–L5 评测协议。

## 一句话研究问题

在 agentic articulated CAD 生成中，把 **spec / 测试设计 / 实现三者分离并冻结**、由**不可篡改 harness** 验收，并在失败时做**归因 + 局部修复**，能否显著提高 URDF 可执行率、运动与物理有效性，同时降低修复轮数与成本？

## 为什么现在做、为什么是我

- 2026 年主线已从"生成 mesh/CAD 序列"转向"生成可执行、可验证的程序系统"（LAM、ArtiCAD、Articraft、CADSmith）。
- 现有系统各缺一块：LAM 只有 VLM 视觉检查；ArtiCAD connector-first 但无开源、验证粒度弱；Articraft 有 compile/probe/test harness，但 spec/test 可被 coder 看到并间接影响，且无系统化失败归因；CADSmith 做静态件且无 spec 冻结。
- 我已有三周产物可直接复用：最小可信 Harness 方案、Unified SDK/Skill/Harness 整合方案、L1–L5 评测协议、数据集选型。

## 系统（v0）

```text
用户文本/参考图
  → Spec Agent（link/joint/connector/限位/碰撞要求）
  → Spec Review + Test Design Agent（声明式测试）
  → Harness 冻结 spec 与 tests（coder 只读，不可改）
  → Coding Agent 写 model.py（Articraft SDK + build123d）
  → Harness：编译 → 几何测量 → 装配检查 → 运动/碰撞 → MuJoCo 物理 → 隐藏复核
  → 失败：普通错误→局部修复；多轮失败→诊断 Agent 归因（spec/几何/测试）
  → 只有 Harness 能发布资产（STEP/URDF/mesh/tests/trace）
```

复用：Articraft（Apache 2.0）SDK+compiler+harness；build123d/OCCT 几何；MuJoCo 物理；PartNet-Mobility 评测。

## 实验（两周 v0）

- 数据集：PartNet-Mobility 选 20–50 个常见 articulated 物体（抽屉/门/盒/夹子/剪刀/笔记本电脑等）。
- 基线：Articraft 原版；LAM 公开结果/复现若可行；单体 LLM agent + 简单 kernel 检查。
- 消融：
  1. Baseline（单体 agent + 编译检查）
  2. + Harness（spec/test 冻结 + L1–L5 验收）
  3. + 归因与局部修复（完整系统）
- 指标（已有协议）：L1 可执行性、L2 结构正确性（joint type/axis/limit）、L3 几何质量、L4 物理与运动有效性（碰撞、稳定性、行程）、L5 语义与下游、pass@k、平均修复轮数、trace 可归因率。

## 预期贡献（按可发表性排序）

1. **系统与消融**：证明"可信验收边界 + 归因修复"对 articulated CAD 有效的第一份系统证据。
2. **Benchmark/协议**：公开可复现的 L1–L5 验收基准与隐藏复核协议（现有协议升级为 artifact）。
3. **方法组件**：counterexample 驱动的失败归因 + 模块级局部修复。
4. **后续**：connector/joint schema 作为生成中间表示；接入 B-Rep/Flow Matching 几何专家。

## 风险与对策

- "只是工程"：把 novelty 放在可测量的三问（冻结是否提升有效性？归因是否降低修复成本？失败主要来自哪一层？），用消融回答。
- Articraft 撞车：我们比它多 spec/test 权限边界、隐藏复核、归因修复和统一 L1–L5 协议。
- 时间紧：第一周只做 Baseline vs +Harness；归因修复第二周，若来不及先报趋势。
- 数据不足：20 个物体足以做机制验证，规模留到后续。
