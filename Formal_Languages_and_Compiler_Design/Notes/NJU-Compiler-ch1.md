## 词法分析器（Lexer）
>[!Note]
>本章包含了NJU课程中所有关于**自动机理论**的内容，补充知识要参考其他内容。

>[!Tip]
>相比XJTU课程主要缺少：
>- 以g-NFA从最小化DFA转RE
>- 隐含表法从DFA化简最小DFA（这里只讲了Hopcroft算法，也就是划分法）


词法分析的输入是什么？
**CharStream + Token的规约。**
所以**有了一种Token规约，就可以设计一个词法分析器**。
有三种设计方法：
- 利用一个自动化的词法分析器生成器（比如利用ANTLR）；
- 手写词法分析器；
- 实现自动化词法分析器（相当于如何设计一个ANTLR？）
>生产环境下的编译器（gcc）更常用的是**手写词法分析器**。
>- 手写可能优化更好
>- 手写可以加入更多错误处理措施
>- 手写的工作量并不大
>但是**语法分析器**的工作量太大，所以一般不选择手写。

#### 词法分析器+语法分析器手写
>若要从头开始写代码，参考视频讲解。

视频中的代码版本无法处理形如`a=a+1;`的语句，这是因为**最长优先匹配原则**。等号后面会被解读成`a`和`+1`，而非`a` `+` `1`。
修改版本如下：
```g4
grammar SimpleExpr;

@header {
package simpleexpr;
}

prog : stat* EOF ;

stat : expr ';'
     | ID '=' expr ';'
     | 'print' expr ';'
     ;

/*
比如以上这个'print'，在输入的时候不会被识别为ID，虽然它符合识别ID的规则。
这是因为：print这种用单引号包裹起来的**字面量**，ANTLR v4会自动为其生成一个词法单元，会自成一类，它会把这些词法单元放在你自己
手动规定的词法单元前面。按照最前优先匹配规则，会先匹配print。
*/

expr : expr ('*' | '/') expr // 乘除的规则写在前面，来保证优先级比加减高；如果加减乘除在一个子规则里都写出（括号里），那么就无法区别优先级。
     | expr ('+' | '-') expr // 如果不明确写左/右结合，那就是默认左结合
     | ('+' | '-') expr
     | '(' expr ')'
     | ID
     | INT
     | FLOAT
     ;

/*
语法结构的描述放在前面（一般小写字母开头），词法结构的描述放在后面（一般是大写字母开头）
*/

SEMI : ';' ;
ASSIGN : '=' ;
PRINT : 'print' ;
MUL : '*' ;
DIV : '/' ;
ADD : '+' ;
SUB : '-' ;
LPAREN : '(' ;
RPAREN : ')' ; // 这几个可以使用 IntelliJ ANTLR v4插件右键Generate直接生成。

ID : ('_' | LETTER) WORD* ;
INT : '0' | [1-9]NUMBER* ; // 加?表示这个规则可以出现0次或者1次，也就是说正负号可以带可以不带。此处去掉了正负号的识别，让正负号被单独识别。
FLOAT : INT '.' NUMBER*
      | '.' NUMBER+
      ;

SL_COMMENT : '//' .*? '\n' -> skip ; // 字面量用单引号包裹。“.”是通配符，表示可以匹配任何除了换行符之外的任何字符。
// 同样应该让识别到的内容skip掉。
// 不加“?”，就是贪婪模式匹配，如果有多个换行符号，那么它会匹配到最后一个换行符为止。所以加上“?”变成非贪婪匹配
SL_COMMENT2 : '//' (~'\n')* '\n' -> skip ; // 这是另一种表达方式
DOCS_COMMENT : '/**' .*? '*/' -> skip ; // 把这个写在ML_COMMENT前面，是因为规则写在前面会被优先匹配，如果多行放在前面，会导致文档注释被识别成多行注释。
ML_COMMENT : '/*' .*? '*/' -> skip ;

WS : [ \t\r\n]+ -> skip ; // whitespace 对于空白符的识别 \r\n和\n是不同的换行形式，在Linux上和Windows上不同。
/* 而这里不能在列表后使用*，因为*表示>=0，而+才表示>=1个，如果用前者，那么没输入空白也会被识别为WS了。
设置-> skip是因为，为了避免在对源代码的词法分析的时候，输入的一个空白符被识别到，从而在语法分析阶段造成干扰。
（“a+b”和“a + b”在本例子中等价，但是如果不加->skip，就会导致后者识别时出错。）
*/

fragment LETTER : [a-zA-Z] ; // []是一种列表
fragment NUMBER : [0-9] ; // fragment是一种辅助的规则
fragment WORD : '_' | LETTER | NUMBER ;
//fragment OP : '+' | '-'; 后面定义的fragment对语法分析器不可见。
```
选择在前面的语法分析器中加入正负号的解析。

##### 最长优先匹配
**最长优先匹配**：如果同样的一个字符流可以被解读成一个合法的token或者一串更短的token，优先匹配那个长度最长的token（前者）。
> 比如`1.23`在示例中可以被解读成`1`和`.23`，但是由于前者长度更长，所以匹配前者。

### 正则表达式 RE
>[!Warning]
>缺简记法的表达。
#### 语法和语义
每个正则表达式$r$对应一个正则语言$L(r)$。
- **正则表达式是语法，正则语言是语义**；
- 例：`ID: [a-zA-Z][a-zA-Z0-9]*`是语法，而`{a1, a2, a3, ...}`是语义
#### 语法（正则表达式）定义
给定字母表$\Sigma$，其上的正则表达式**由且仅由**以下规则定义：
- $\epsilon$是正则表达式
- $\forall a \in \Sigma,\,a$是正则表达式
- 如果$r$是正则表达式，则$(r)$是正则表达式
- 如果$r$和$s$是正则表达式，那么$r|s,\, rs,\, r^*$也是正则表达式
**运算优先级：** $() \succ * \succ 连接 \succ |$
>`\succ`即$\succ$表示**严格偏好/优于**，用于逻辑表示。
#### 语义（正则语言）定义
一一对应以上语法的四条定义，给出以下四条对于正则语言的定义：
$$
\begin{gather}
L(\epsilon) = {\epsilon} \\
L(a) = {a}, \, \forall a \in \Sigma \\ 
L((r)) = L (r) \\
L(r|s) = L(r) \cup L(s) \qquad L(rs) = L(r)L(s) \qquad L(r^*) = (L(r))^*
\end{gather}
$$
> 注意这里$L(rs)$是指$rs$连接而不是求交，所以后面的也不是L与L求交集，而是连接。

### NFA 非确定性有穷自动机
#### 定义
$$A=(\Sigma,S, \delta, s_0, F)$$

- $S$：有限的状态集合；
- $\Sigma$：Input Alphabet，输入符号的集合；注意$\mathbf{\epsilon \notin \Sigma}$
- $\delta$`\delta`：状态转移函数。
	- Input：一个状态 + 一个输入符号；
	- $\delta: S \times (\Sigma \cup \{\epsilon\}) \to 2^S$
	- $\delta(s, a)$：在$s$状态接受符号$a$后DFA走向的下一个状态。下例中$\delta(s_0, a) = \{s_1, s_0\}$
- $s_0$：**唯一的**初始状态。$s_0 \in S$，在图中被一个标注“start”的箭头指向。
- $F$：终止状态集合，$F \subseteq S$，终止状态也称**接受状态**；
![401](../../attachments/Pasted%20image%2020260619131552.png)
>“不确定性”的体现是什么？
> - 如上例，0状态输入a，下一个状态不唯一。自动机在**某个状态面对一个输入可以跳转到的状态不唯一**，这就是NFA的体现。
> - NFA的不确定还体现在$\epsilon-$**转移**上。在一个状态不接受任何输入（也就是接受空串$\epsilon$）的时候，它仍然有可能自发跳转到下一个不同的状态，这就是$\epsilon$-转移。

> 初始状态也可以不标注**唯一**，因为如果不唯一，可以通过一定的方法转化成唯一的初始状态。

### DFA 确定性有穷自动机
#### 定义

$$A=(\Sigma,S, \delta, s_0, F)$$

- $S$：有限的状态集合；
- $\Sigma$：Input Alphabet，输入符号的集合；注意$\mathbf{\epsilon \notin \Sigma}$
- $\delta$`\delta`：状态转移函数。
	- Input：一个状态 + 一个输入符号；
	- $\delta: S \times (\Sigma) \to S$
	- $\delta(s, a)$：在$s$状态接受符号$a$后DFA走向的下一个状态。
- $s_0$：**唯一的**初始状态。$s_0 \in S$，在图中被一个标注“start”的箭头指向。
- $F$：终止状态集合，$F \subseteq S$，终止状态也称**接受状态**；
> **“确定性”** 的体现：
> - 不接受空状态；
> - 状态a对于一个确定的接受输入，只有一个确定的转移状态。

### 从RE到Lexer

- NFA简洁，便于理解，便于描述语言；
- DFA便于判断某个串是否属于该语言，从而适合产生Lexer。

##### 转换方法
寻找（构造）**状态子集**。
NFA多个状态如何被放入同一子集？通过**空转移**能到达的就属于同一子集。
所以可以这样表达：
***DFA 的一个状态 = NFA 在某一状态下，读完某个输入字符后，所有可能所在状态的集合。***
###### $\varepsilon-$闭包
从 q 出发，只经过 0 条或多条 $\varepsilon$-transition 能到达的所有状态集合，称之为$\varepsilon\text{-closure}(q)$。
###### $\varepsilon-$闭包的拓展
闭包的输入状态从单状态变成了一个状态集。下图的T就是一个状态集。

##### 说人话解题步骤
- DFA的初始状态就是对NFA初始状态求闭包的结果，也可以看成转移函数中的$a$为空$\varepsilon$。
- 后续从DFA的初始状态开始，**对每一个可能的输入字**，遍历该状态子集中的每个状态，检查它们在接受这个输入字母并再次经过空闭包时候得到的状态集，然后并成一个大状态子集。如果当前没发现这个子集合，就给它起新编号，作为DFA的新节点；否则就匹配已经找出来的节点。
- 重复上一条这个过程，对每个已经划分出来的状态子集都检查所有可能的输入，直到不再变化，找出所有DFA状态为止。
- 最后谁是接受态？只要状态子集包含原NFA的任何接受态，那就是新DFA的接受态。
##### 复杂度分析
$|S_N|= n$，$|S_D| =\Theta(2^n)=O(2^n)\cap \Omega(2^n)$
对于任何算法，最坏情况下，$|S_D| =\Theta(2^n)$
容易解释。构造出的DFA的每个状态都是原先的一个子集，所以上限是不超过$2^N$。

#### DFA最小化
> 注意：本校 Slides `第三章RL2026.pdf` 里 DFA 最小化讲了两类方法：
> - **填表算法**，也常叫隐含表法/表填充法：枚举状态对，标记可区分状态对，最后未标记的状态对等价。
> - **划分法/Hopcroft算法**：从接受态/非接受态的初始划分开始，不断按转移目标细分等价类。
>
> 下面这段笔记描述的是“划分细化”的思路，更接近 Hopcroft/划分法；如果考试要求“隐含表”，应按状态对填表来写。

##### 等价
![669](../../attachments/Pasted%20image%2020260621182304.png)
也就是说，两个状态对于同一个输入，达到的状态等价。这是一个递归定义，更类似于一条性质。但是可以利用这个解题
##### 解题
![599](../../attachments/Pasted%20image%2020260621190754.png)
>首先，**接受状态**和非接受状态一定是不等价的。
>所以，最开始将接受状态划一类（有可能不止一个接受态，所以这个等价类有可能不止一个状态成员），然后剩下所有状态归一类；
> 接下来对每个等价类，遍历字母表中每一个可能的输入字符，只要找出不可能属于当前等价类的状态，**就可以停止遍历**，进行划分后重新对新等价类遍历字母表（即如果当前同一划分类中出现了对于某个转换到达状态所属类不同的情况，就要继续划分）
> 然后对得到的新的状态继续遍历字母表的元素，直到划分结果不再变化，分无可分。

>[!Tip]
>这里实际上还要加上一个等价类，就是在状态转移图中被忽略的空转移，也就是$\{\varnothing\}$。

##### 等价（Equivalent）的正式定义
如果存在某个能区分$s$与$t$的字符串，那么称$s$和$t$是**可区分的**（Distinguishable）；否则就称二者为**等价**的。
##### 区分
如果分别从$s$和$t$出发，沿着标号$x$的路径到达的两个状态中只有一个是接收状态，那么就称$x$**区分**了$s$和$t$。
