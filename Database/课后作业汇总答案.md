## 第 2 章作业

### 7. 关系代数与关系演算

#### （1）求关系表达式的值

**$E_1$**

先选出 $A>\text{'a1'}$ 且 $B<\text{'b4'}$ 的元组，再投影到 $(C,D)$，投影结果去重：

| $C$ | $D$ |
| --- | --- |
| c2 | d1 |
| c2 | d2 |
| c2 | d3 |
| c2 | d4 |
| c3 | d2 |

**$E_2$**

$R\bowtie S\bowtie T$ 按公共属性自然连接，即 $R.D=S.D$ 且 $S.D=T.D,\ S.F=T.F$。再满足：

$$
A<\text{'a3'}\wedge E<\text{'e3'}\wedge G\ne\text{'g3'}
$$

投影到 $(A,B,E,G)$ 后结果为：

| $A$ | $B$ | $E$ | $G$ |
| --- | --- | --- | --- |
| a1 | b1 | e1 | g2 |
| a1 | b1 | e2 | g1 |
| a2 | b2 | e2 | g1 |
| a2 | b3 | e1 | g2 |

**$E_3$**

先求：

$$
\Pi_D(\sigma_{F=\text{'f1'}}(T))=\{d1,d3\}
$$

因此：

$$
E_3=R\div \{d1,d3\}
$$

即找出在 $d1$ 和 $d3$ 上都出现过的 $(A,B,C)$。结果为：

| $A$ | $B$ | $C$ |
| --- | --- | --- |
| a4 | b3 | c2 |

**$E_4$**

根据元组关系演算条件：

$$
u[3]>\text{'c1'},\quad v[2]\ne\text{'e2'},\quad w[3]\ne\text{'g2'}
$$

$$
u[4]=v[1],\quad v[3]>w[2]
$$

且输出：

$$
t=(u[2],u[3],v[1],w[3],w[2])
$$

结果为：

| $B$ | $C$ | $D$ | $G$ | $F$ |
| --- | --- | --- | --- | --- |
| b2 | c3 | d2 | g1 | f1 |
| b2 | c3 | d2 | g3 | f1 |
| b3 | c2 | d2 | g1 | f1 |
| b3 | c2 | d2 | g3 | f1 |
| b4 | c2 | d2 | g1 | f1 |
| b4 | c2 | d2 | g3 | f1 |

#### （2）将 $E_4$ 转化为等价的关系代数表达式

为避免同名属性混淆，使用 $R,S,T$ 的关系名限定属性：

$$
E_4=
\Pi_{R.B,\ R.C,\ S.D,\ T.G,\ T.F}
\left(
\sigma_{
R.C>\text{'c1'}\wedge
S.E\ne\text{'e2'}\wedge
T.G\ne\text{'g2'}\wedge
R.D=S.D\wedge
S.F>T.F
}
(R\times S\times T)
\right)
$$

### 8. Student、Course、SC 上的关系代数查询

以下假设：

$$
\text{Student}(S\#,Sname,Class,\ldots)
$$

$$
\text{Course}(C\#,Cname,Teacher,\ldots)
$$

$$
\text{SC}(S\#,C\#,Grade)
$$

#### （1）查询“计算机 07”班同学的学号及姓名

$$
\Pi_{S\#,Sname}\left(
\sigma_{Class=\text{'计算机07'}}(\text{Student})
\right)
$$

#### （2）学号为“01055107”的同学所选修的课程名称及成绩

$$
\Pi_{Cname,Grade}
\left(
\sigma_{S\#=\text{'01055107'}}(\text{SC})
\bowtie
\text{Course}
\right)
$$

#### （3）未选修编号为“CS05”课程的学生学号

$$
\Pi_{S\#}(\text{Student})
-
\Pi_{S\#}\left(
\sigma_{C\#=\text{'CS05'}}(\text{SC})
\right)
$$

#### （4）选修了“张华”老师所开设课程的学生姓名、课程名称及成绩

$$
\Pi_{Sname,Cname,Grade}
\left(
\text{Student}\bowtie\text{SC}\bowtie
\sigma_{Teacher=\text{'张华'}}(\text{Course})
\right)
$$

#### （5）选修了全部课程的学生姓名及班级

先求选修全部课程的学生学号：

$$
X=
\Pi_{S\#,C\#}(\text{SC})
\div
\Pi_{C\#}(\text{Course})
$$

再连接学生表：

$$
\Pi_{Sname,Class}
\left(
\text{Student}\bowtie X
\right)
$$

## 第 3 章作业

为避免属性名中的 `#` 引起歧义，下面 SQL 使用双引号表示属性名，例如 `"S#"`。

本节给多种写法。考试里最稳的是：会写 `JOIN`，也会写不用 `JOIN` 的“多表逗号 + `WHERE` 连接条件”、`IN/EXISTS`、`GROUP BY/HAVING`。

### （1）查询选修课程“CS-02”的学生学号、成绩

写法 1：直接查 `SC`

```sql
SELECT "S#", Grade
FROM SC
WHERE "C#" = 'CS-02';
```

写法 2：如果题目要求确认课程存在，可用 `IN`

```sql
SELECT "S#", Grade
FROM SC
WHERE "C#" IN (
  SELECT "C#"
  FROM Course
  WHERE "C#" = 'CS-02'
);
```

写法 3：`EXISTS`

```sql
SELECT X."S#", X.Grade
FROM SC AS X
WHERE EXISTS (
  SELECT *
  FROM Course AS C
  WHERE C."C#" = X."C#"
    AND C."C#" = 'CS-02'
);
```

解析：本题只需要课程号和成绩，信息都在 `SC` 表里，所以写法 1 最简洁。

### （2）查询选修课程“EE-01”的女学生姓名

写法 1：显式 `JOIN`

```sql
SELECT S.Sname
FROM Student AS S
JOIN SC AS SC
  ON S."S#" = SC."S#"
WHERE SC."C#" = 'EE-01'
  AND S.Sex = '女';
```

写法 2：不用 `JOIN`，用 `WHERE` 写连接条件

```sql
SELECT DISTINCT S.Sname
FROM Student AS S, SC AS X
WHERE S."S#" = X."S#"
  AND X."C#" = 'EE-01'
  AND S.Sex = '女';
```

写法 3：嵌套 `IN`

```sql
SELECT Sname
FROM Student
WHERE Sex = '女'
  AND "S#" IN (
    SELECT "S#"
    FROM SC
    WHERE "C#" = 'EE-01'
  );
```

写法 4：`EXISTS`

```sql
SELECT S.Sname
FROM Student AS S
WHERE S.Sex = '女'
  AND EXISTS (
    SELECT *
    FROM SC AS X
    WHERE X."S#" = S."S#"
      AND X."C#" = 'EE-01'
  );
```

解析：学生性别在 `Student`，选课信息在 `SC`，所以必须通过学号关联。连接写法要加 `DISTINCT` 防止重复；`IN/EXISTS` 写法更像“筛选学生”。

### （3）查询未选修课程“CS-02”的学生姓名

写法 1：`NOT EXISTS`，最稳

```sql
SELECT S.Sname
FROM Student AS S
WHERE NOT EXISTS (
  SELECT 1
  FROM SC AS SC
  WHERE SC."S#" = S."S#"
    AND SC."C#" = 'CS-02'
);
```

写法 2：`NOT IN`

```sql
SELECT Sname
FROM Student
WHERE "S#" NOT IN (
  SELECT "S#"
  FROM SC
  WHERE "C#" = 'CS-02'
);
```

写法 3：用集合差思路，先找未选课学生学号

```sql
SELECT Sname
FROM Student
WHERE "S#" IN (
  SELECT "S#"
  FROM Student
  WHERE "S#" NOT IN (
    SELECT "S#"
    FROM SC
    WHERE "C#" = 'CS-02'
  )
);
```

写法 4：用分组统计，没选 `CS-02` 的计数为 0

```sql
SELECT S.Sname
FROM Student AS S
WHERE (
  SELECT COUNT(*)
  FROM SC AS X
  WHERE X."S#" = S."S#"
    AND X."C#" = 'CS-02'
) = 0;
```

解析：否定类查询优先考虑 `NOT EXISTS`，因为它不怕子查询里出现空值。`NOT IN` 更短，但如果子查询结果含 `NULL`，某些数据库会出问题；考试题一般不设置这个坑，但知道最好。

### （4）查询身高高于“王涛”同学的男生学号、姓名及生日

写法 1：标量子查询

```sql
SELECT S."S#", S.Sname, S.Bdate
FROM Student AS S
WHERE S.Sex = '男'
  AND S.Height > (
    SELECT W.Height
    FROM Student AS W
    WHERE W.Sname = '王涛'
  );
```

写法 2：不用 `JOIN`，自连接用逗号表 + `WHERE`

```sql
SELECT S."S#", S.Sname, S.Bdate
FROM Student AS S, Student AS W
WHERE S.Sex = '男'
  AND W.Sname = '王涛'
  AND S.Height > W.Height;
```

写法 3：如果可能有多个叫“王涛”的学生，用 `MAX`

```sql
SELECT "S#", Sname, Bdate
FROM Student
WHERE Sex = '男'
  AND Height > (
    SELECT MAX(Height)
    FROM Student
    WHERE Sname = '王涛'
  );
```

写法 4：如果理解为高于任意一个“王涛”，用 `ANY`

```sql
SELECT "S#", Sname, Bdate
FROM Student
WHERE Sex = '男'
  AND Height > ANY (
    SELECT Height
    FROM Student
    WHERE Sname = '王涛'
  );
```

解析：若默认“王涛”唯一，写法 1 最标准；若可能重名，要说明用 `MAX` 或 `ANY/ALL` 的语义。

### （5）查询选修课程“CS-01”的学生中成绩最高的学生学号

写法 1：`MAX`

```sql
SELECT SC."S#"
FROM SC AS SC
WHERE SC."C#" = 'CS-01'
  AND SC.Grade = (
    SELECT MAX(SC2.Grade)
    FROM SC AS SC2
    WHERE SC2."C#" = 'CS-01'
  );
```

写法 2：`>= ALL`

```sql
SELECT "S#"
FROM SC
WHERE "C#" = 'CS-01'
  AND Grade >= ALL (
    SELECT Grade
    FROM SC
    WHERE "C#" = 'CS-01'
  );
```

写法 3：`NOT EXISTS`，不存在同课成绩更高的人

```sql
SELECT X."S#"
FROM SC AS X
WHERE X."C#" = 'CS-01'
  AND NOT EXISTS (
    SELECT *
    FROM SC AS Y
    WHERE Y."C#" = 'CS-01'
      AND Y.Grade > X.Grade
  );
```

写法 4：按成绩降序，只取第一名，部分数据库支持

```sql
SELECT "S#"
FROM SC
WHERE "C#" = 'CS-01'
ORDER BY Grade DESC
FETCH FIRST 1 ROW ONLY;
```

解析：如果最高分有并列，写法 1、2、3 会返回所有并列最高分学生；写法 4 通常只返回一条，不一定保留并列，考试不如前三种稳。

### （6）查询学生姓名及其所选修课程的课程号、学分和成绩

写法 1：显式 `JOIN`

```sql
SELECT S.Sname, SC."C#", C.Credit, SC.Grade
FROM Student AS S
JOIN SC AS SC
  ON S."S#" = SC."S#"
JOIN Course AS C
  ON SC."C#" = C."C#";
```

写法 2：不用 `JOIN`，多表逗号 + `WHERE`

```sql
SELECT S.Sname, X."C#", C.Credit, X.Grade
FROM Student AS S, SC AS X, Course AS C
WHERE S."S#" = X."S#"
  AND X."C#" = C."C#";
```

写法 3：以 `SC` 为主表，用相关子查询取姓名和学分

```sql
SELECT
  (SELECT S.Sname
   FROM Student AS S
   WHERE S."S#" = X."S#") AS Sname,
  X."C#",
  (SELECT C.Credit
   FROM Course AS C
   WHERE C."C#" = X."C#") AS Credit,
  X.Grade
FROM SC AS X;
```

写法 4：派生表写法，不用显式 `JOIN`

```sql
SELECT T.Sname, T."C#", C.Credit, T.Grade
FROM (
  SELECT S.Sname, X."C#", X.Grade
  FROM Student AS S, SC AS X
  WHERE S."S#" = X."S#"
) AS T,
Course AS C
WHERE T."C#" = C."C#";
```

解析：本题输出列来自三张表，所以必须把 `Student`、`SC`、`Course` 关联起来。考试最推荐写法 2：不用 `JOIN`，但连接条件清楚。

### （7）查询平均成绩超过 80 分的学生姓名和平均成绩

写法 1：显式 `JOIN`

```sql
SELECT S.Sname, AVG(SC.Grade) AS AvgGrade
FROM Student AS S
JOIN SC AS SC
  ON S."S#" = SC."S#"
GROUP BY S."S#", S.Sname
HAVING AVG(SC.Grade) > 80;
```

写法 2：不用 `JOIN`，`WHERE + GROUP BY + HAVING`

```sql
SELECT S.Sname, AVG(X.Grade) AS AvgGrade
FROM Student AS S, SC AS X
WHERE S."S#" = X."S#"
GROUP BY S."S#", S.Sname
HAVING AVG(X.Grade) > 80;
```

写法 3：先在 `SC` 中分组，再用 `IN` 查姓名

```sql
SELECT Sname
FROM Student
WHERE "S#" IN (
  SELECT "S#"
  FROM SC
  GROUP BY "S#"
  HAVING AVG(Grade) > 80
);
```

如果必须同时输出平均成绩，可写成：

```sql
SELECT S.Sname, T.AvgGrade
FROM Student AS S,
     (
       SELECT "S#", AVG(Grade) AS AvgGrade
       FROM SC
       GROUP BY "S#"
       HAVING AVG(Grade) > 80
     ) AS T
WHERE S."S#" = T."S#";
```

写法 4：相关子查询

```sql
SELECT S.Sname,
       (SELECT AVG(X.Grade)
        FROM SC AS X
        WHERE X."S#" = S."S#") AS AvgGrade
FROM Student AS S
WHERE (
  SELECT AVG(X.Grade)
  FROM SC AS X
  WHERE X."S#" = S."S#"
) > 80;
```

解析：一看见“平均成绩超过 80”，就想到 `GROUP BY "S#" HAVING AVG(Grade)>80`。如果输出姓名，要再和 `Student` 用学号关联。

### （8）查询选修三门以上课程的学生已获得的学分数，并按学号升序排列

写法 1：显式 `JOIN`

```sql
SELECT SC."S#", SUM(C.Credit) AS TotalCredit
FROM SC AS SC
JOIN Course AS C
  ON SC."C#" = C."C#"
GROUP BY SC."S#"
HAVING COUNT(*) > 3
ORDER BY SC."S#" ASC;
```

写法 2：不用 `JOIN`，多表逗号 + `WHERE`

```sql
SELECT X."S#", SUM(C.Credit) AS TotalCredit
FROM SC AS X, Course AS C
WHERE X."C#" = C."C#"
GROUP BY X."S#"
HAVING COUNT(*) > 3
ORDER BY X."S#" ASC;
```

写法 3：相关子查询计算学分

```sql
SELECT X."S#",
       SUM((
         SELECT C.Credit
         FROM Course AS C
         WHERE C."C#" = X."C#"
       )) AS TotalCredit
FROM SC AS X
GROUP BY X."S#"
HAVING COUNT(*) > 3
ORDER BY X."S#" ASC;
```

写法 4：先找选修三门以上的学生，再统计学分

```sql
SELECT X."S#", SUM(C.Credit) AS TotalCredit
FROM SC AS X, Course AS C
WHERE X."C#" = C."C#"
  AND X."S#" IN (
    SELECT "S#"
    FROM SC
    GROUP BY "S#"
    HAVING COUNT(*) > 3
  )
GROUP BY X."S#"
ORDER BY X."S#" ASC;
```

如果题目里的“三门以上”被老师按“三门及以上”理解，把 `COUNT(*) > 3` 改成：

```sql
HAVING COUNT(*) >= 3
```

如果按“成绩及格才获得学分”理解，可在连接后加：

```sql
WHERE SC.Grade >= 60
```

对应不用 `JOIN` 的完整写法是：

```sql
SELECT X."S#", SUM(C.Credit) AS TotalCredit
FROM SC AS X, Course AS C
WHERE X."C#" = C."C#"
  AND X.Grade >= 60
GROUP BY X."S#"
HAVING COUNT(*) > 3
ORDER BY X."S#" ASC;
```

解析：统计学分需要 `Course.Credit`，选课门数来自 `SC`。注意 `WHERE` 先筛选记录，`GROUP BY` 分学生分组，`HAVING` 筛选“选课门数超过 3”的学生。

## 第 4 章作业

### 4.4 属性集闭包

已知：

$$
R(A,B,C,D,E,G)
$$

$$
F=\{A\to B,\ C\to G,\ E\to A,\ CE\to D\}
$$

#### （1）求 $(AG)^+$

初始：

$$
(AG)^+=\{A,G\}
$$

由 $A\to B$ 得：

$$
(AG)^+=\{A,B,G\}
$$

不能继续推出其他属性，因此：

$$
(AG)^+=\{A,B,G\}
$$

#### （2）求 $(CE)^+$

初始：

$$
(CE)^+=\{C,E\}
$$

由 $C\to G$、$E\to A$ 得：

$$
(CE)^+=\{A,C,E,G\}
$$

由 $A\to B$ 得：

$$
(CE)^+=\{A,B,C,E,G\}
$$

由 $CE\to D$ 得：

$$
(CE)^+=\{A,B,C,D,E,G\}
$$

因此：

$$
(CE)^+=R
$$

### 4.5 最小覆盖与候选键

已知：

$$
R(A,B,C,D,E,G,H)
$$

$$
F=\{CD\to B,\ CDE\to A,\ A\to B,\ B\to E,\ G\to AEH,\ H\to EG\}
$$

#### （1）判断 $F$ 是否为最小函数依赖集，并求最小覆盖

$F$ 不是最小函数依赖集，原因包括：

- $G\to AEH$、$H\to EG$ 的右部不是单属性。
- $CDE\to A$ 中的 $E$ 是冗余属性，因为 $CD\to B$ 且 $B\to E$，所以 $CD$ 可推出 $E$，进而推出 $A$。
- 部分依赖可由其他依赖推出，例如 $CD\to B$ 可由 $CD\to A$ 和 $A\to B$ 推出。

先拆右部：

$$
G\to AEH
$$

拆为：

$$
G\to A,\quad G\to E,\quad G\to H
$$

$$
H\to EG
$$

拆为：

$$
H\to E,\quad H\to G
$$

将 $CDE\to A$ 化简为：

$$
CD\to A
$$

删去冗余依赖 $CD\to B$、$G\to E$、$H\to E$，可得一个最小覆盖：

$$
F_{\min}=\{CD\to A,\ A\to B,\ B\to E,\ G\to A,\ G\to H,\ H\to G\}
$$

#### （2）求 $R$ 的所有候选键

属性 $C,D$ 不出现在任何依赖右部，因此每个候选键都必须包含 $C,D$。

计算：

$$
(CD)^+=\{A,B,C,D,E\}
$$

不能推出 $G,H$，所以 $CD$ 不是候选键。

加入 $G$：

$$
(CDG)^+=\{A,B,C,D,E,G,H\}=R
$$

且 $C,D,G$ 中任一属性都不能删去，因此 $CDG$ 是候选键。

加入 $H$：

$$
(CDH)^+=\{A,B,C,D,E,G,H\}=R
$$

且 $C,D,H$ 中任一属性都不能删去，因此 $CDH$ 是候选键。

所以全部候选键为：

$$
\{CDG,\ CDH\}
$$

### 4.6 无损连接判断

已知：

$$
R(A,B,C,D,E,G)
$$

$$
F=\{B\to E,\ D\to G,\ A\to B,\ E\to A,\ DE\to C\}
$$

分解：

$$
\rho=\{R_1(D,G),\ R_2(B,E),\ R_3(C,D,E),\ R_4(A,B)\}
$$

用表格法判断。初始时各子模式包含的属性填对应的 $a$，不包含的属性填不同的 $b$。追踪关键推导：

1. $R_2$ 与 $R_4$ 在 $B$ 列同为 $a_B$，由 $B\to E$，可令 $R_4.E=a_E$。
2. $R_2$、$R_3$、$R_4$ 在 $E$ 列同为 $a_E$，由 $E\to A$，可令相关行的 $A$ 列为 $a_A$。
3. $R_3$ 与 $R_4$ 在 $A$ 列同为 $a_A$，由 $A\to B$，可令 $R_3.B=a_B$。
4. $R_1$ 与 $R_3$ 在 $D$ 列同为 $a_D$，由 $D\to G$，可令 $R_3.G=a_G$。

此时 $R_3$ 行变为：

$$
(a_A,a_B,a_C,a_D,a_E,a_G)
$$

出现全 $a$ 行，因此分解 $\rho$ 是无损连接分解。

### 4.7 无损连接与依赖保持

已知：

$$
R(A,B,C,D)
$$

$$
F=\{C\to D,\ D\to A,\ C\to B,\ B\to A\}
$$

分解：

$$
\rho=\{R_1(A,C),\ R_2(B,D),\ R_3(C,D)\}
$$

#### （1）判断是否无损连接

用表格法追踪后，不能得到任一全 $a$ 行。例如最终可得到的典型行形态为：

$$
(a_A,b_B,a_C,a_D)
$$

$$
(a_A,a_B,b_C,a_D)
$$

没有一行同时包含：

$$
(a_A,a_B,a_C,a_D)
$$

因此该分解不是无损连接分解。

#### （2）求投影并判断是否保持函数依赖

在 $R_1(A,C)$ 上：

$$
\pi_{R_1}(F)=\{C\to A\}
$$

因为：

$$
C\to D,\quad D\to A
$$

所以：

$$
C\to A
$$

在 $R_2(B,D)$ 上，没有非平凡函数依赖：

$$
\pi_{R_2}(F)=\varnothing
$$

在 $R_3(C,D)$ 上：

$$
\pi_{R_3}(F)=\{C\to D\}
$$

因此投影依赖的并集为：

$$
G=\{C\to A,\ C\to D\}
$$

但 $G$ 不能推出原依赖中的：

$$
D\to A,\quad C\to B,\quad B\to A
$$

所以分解 $\rho$ 不保持函数依赖。

### 4.9 范式判断

#### （1）$R_1(A,B,C)$，$F=\{C\to B,\ B\to A\}$

候选键为：

$$
C
$$

非主属性为：

$$
A,\ B
$$

存在传递依赖：

$$
C\to B,\quad B\to A
$$

所以 $A$ 传递依赖于候选键 $C$。由于候选键是单属性，不存在部分依赖，故满足 $2NF$，但不满足 $3NF$。

最高属于：

$$
2NF
$$

#### （2）$R_2(A,B,C)$，$F=\{B\to C,\ B\to A\}$

候选键为：

$$
B
$$

所有非平凡函数依赖的左部都是超键 $B$，因此满足 $BCNF$。

最高属于：

$$
BCNF
$$

#### （3）$R_3(A,B,C)$，$F=\{B\to C,\ AC\to B\}$

候选键为：

$$
AB,\ AC
$$

所以 $A,B,C$ 都是主属性。

依赖 $B\to C$ 中，$B$ 不是超键，因此不满足 $BCNF$；但右部 $C$ 是主属性，满足 $3NF$ 的判定条件。

最高属于：

$$
3NF
$$

#### （4）$R_4(A,B,C,D)$，$F=\{A\to C,\ B\to D\}$

候选键为：

$$
AB
$$

非主属性为：

$$
C,\ D
$$

存在非主属性对候选键的部分依赖：

$$
A\to C,\quad B\to D
$$

因此不满足 $2NF$，只满足 $1NF$。

最高属于：

$$
1NF
$$

#### （5）$R_5(A,B,C,D)$，$F=\{B\to D,\ AB\to C\}$

候选键为：

$$
AB
$$

非主属性为：

$$
C,\ D
$$

存在非主属性 $D$ 对候选键 $AB$ 的部分依赖：

$$
B\to D
$$

因此不满足 $2NF$，只满足 $1NF$。

最高属于：

$$
1NF
$$

## 第 8 章作业

### 8.21 两段封锁、wait-die 与 wound-wait

已知：

$$
ts(T_1)=20,\quad ts(T_2)=30
$$

时间戳越小，事务越老，因此 $T_1$ 比 $T_2$ 老。

加锁请求顺序为：

$$
T_1\ Xlock\ R_1
$$

$$
T_2\ Xlock\ R_2
$$

$$
T_1\ Xlock\ R_2
$$

$$
T_2\ Xlock\ R_1
$$

#### （1）一般的两段封锁

执行过程：

1. $T_1$ 对 $R_1$ 加 $X$ 锁，成功。
2. $T_2$ 对 $R_2$ 加 $X$ 锁，成功。
3. $T_1$ 请求对 $R_2$ 加 $X$ 锁，但 $R_2$ 已被 $T_2$ 加锁，所以 $T_1$ 等待 $T_2$。
4. $T_2$ 请求对 $R_1$ 加 $X$ 锁，但 $R_1$ 已被 $T_1$ 加锁，所以 $T_2$ 等待 $T_1$。

于是产生死锁：

$$
T_1\leftrightarrow T_2
$$

一般两段封锁本身不能避免该死锁，需要死锁检测与解除。

若系统撤销 $T_2$，则等效串行顺序为：

$$
T_1\to T_2
$$

若系统撤销 $T_1$，则等效串行顺序为：

$$
T_2\to T_1
$$

因此一般两段封锁下不唯一，取决于死锁处理时选择的牺牲事务。

#### （2）具有 wait-die 策略的两段封锁

wait-die 策略规则：

- 老事务请求年轻事务持有的锁时，老事务等待。
- 年轻事务请求老事务持有的锁时，年轻事务回滚。

执行过程：

1. $T_1$ 对 $R_1$ 加 $X$ 锁，成功。
2. $T_2$ 对 $R_2$ 加 $X$ 锁，成功。
3. $T_1$ 请求 $R_2$，该锁由更年轻的 $T_2$ 持有，因此 $T_1$ 等待。
4. $T_2$ 请求 $R_1$，该锁由更老的 $T_1$ 持有，因此 $T_2$ 回滚。
5. $T_2$ 回滚释放 $R_2$，$T_1$ 获得 $R_2$ 并完成。
6. $T_2$ 以原时间戳重新启动，之后执行。

等效串行顺序为：

$$
T_1\to T_2
$$

#### （3）具有 wound-wait 策略的两段封锁

wound-wait 策略规则：

- 老事务请求年轻事务持有的锁时，老事务抢占，年轻事务回滚。
- 年轻事务请求老事务持有的锁时，年轻事务等待。

执行过程：

1. $T_1$ 对 $R_1$ 加 $X$ 锁，成功。
2. $T_2$ 对 $R_2$ 加 $X$ 锁，成功。
3. $T_1$ 请求 $R_2$，该锁由更年轻的 $T_2$ 持有，因此 $T_1$ wound $T_2$，$T_2$ 回滚并释放 $R_2$。
4. $T_1$ 获得 $R_2$ 并完成。
5. $T_2$ 以原时间戳重新启动，之后执行。

等效串行顺序为：

$$
T_1\to T_2
$$

### 8.22 修改后的 wait-die 策略

修改后的策略为：

$$
\text{若 }ts(T_A)>ts(T_B)\text{，则 }T_A\text{ 等待}
$$

否则：

$$
T_A\text{ 回滚，并以原来的 }ts(T_A)\text{ 重新启动}
$$

其中 $T_A$ 是请求锁的事务，$T_B$ 是已经持有该锁的事务。

#### （1）此策略能否避免死锁？

能避免死锁。

因为只有当：

$$
ts(T_A)>ts(T_B)
$$

时，$T_A$ 才等待 $T_B$。也就是说，等待边总是从时间戳较大的年轻事务指向时间戳较小的年老事务。沿等待边时间戳严格减小，不可能形成环，因此不会发生死锁。

#### （2）此策略的主要问题

主要问题是可能造成事务反复回滚，甚至饥饿。

如果较老事务 $T_A$ 请求的锁被较年轻事务 $T_B$ 持有，则由于：

$$
ts(T_A)<ts(T_B)
$$

$T_A$ 会被回滚。题目又规定 $T_A$ 以原来的时间戳重新启动，因此它重新启动后仍然是较老事务；如果再次遇到同类冲突，仍会再次回滚。

因此，老事务可能长期不能完成。

#### （3）如何改进

一种改进方法是：事务回滚后不要保留原时间戳，而是重新赋予新的时间戳，使其不再因“始终较老”而反复回滚。

另一种更常见的改进是直接采用 wound-wait 策略：

$$
\text{老事务请求年轻事务持有的锁时，回滚年轻事务；年轻事务请求老事务持有的锁时，年轻事务等待。}
$$

这样既能避免死锁，又能避免老事务由于保持原时间戳而反复被回滚。
