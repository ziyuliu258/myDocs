## 第一章 数据库系统概述

### 数据管理技术发展的三个阶段

| 阶段 | 核心特点 | 主要问题/优势 |
| --- | --- | --- |
| 人工管理阶段 | 没有操作系统和数据管理软件；数据不长期保存在计算机中；数据组织由程序员负责；数据面向程序 | 数据和程序强绑定，几乎没有共享性 |
| 文件系统阶段 | 有操作系统和文件系统；以文件为单位长期保存数据；数据存取以记录为单位；数据与程序有一定独立性 | 独立性仍然差；共享性差、冗余大；容易不一致；查询和完整性维护困难 |
| 数据库系统阶段 | 由 DBMS 统一管理数据；数据面向整个系统；结构化、共享性好、冗余少、独立性高 | 需要 DBMS 提供安全性、完整性、并发控制、恢复等统一控制 |

例子：

- 文件系统阶段：教务处有一个学生文件，图书馆也有一个学生文件。学生改名时两个文件都要改，漏改就会数据不一致。
- 数据库系统阶段：学生信息统一放在数据库中，教务系统、图书馆系统通过 DBMS 访问同一份数据，减少重复和不一致。

### 数据库系统的组成

数据库系统通常包括：

- `DB`：数据库。统一管理、长期存储、可共享的数据集合。
- `DBMS`：数据库管理系统。数据库系统的核心软件，介于用户和操作系统之间。
- 用户：数据库管理员 `DBA`、终端用户、应用程序员。

容易混淆：

- 数据库 `DB` 是数据本身。
- 数据库管理系统 `DBMS` 是管理数据库的软件。
- 数据库系统 `DBS` 是 DB、DBMS、用户、软硬件环境的整体。

### 数据、信息、语法、语义

- 数据是信息的符号表示或载体。
- 信息是数据的内涵，是对数据语义的解释。
- 语法：数据格式，例如数值型、字符型、日期型。
- 语义：数据代表什么含义。

例子：`<02055001, 张明, 男, 1984.5, 计算机系>` 这串数据本身只是符号；如果知道每一列分别是学号、姓名、性别、出生年月、院系，才有语义。

### 数据模型三要素

数据模型是对现实世界数据特征的抽象，三要素是重点：

1. 数据结构：描述数据对象以及对象之间的联系。例如关系模型用二维表表示实体和联系。
2. 数据操作：描述可以对数据做什么操作，主要包括检索和更新，更新又包括插入、删除、修改。
3. 数据完整性约束：描述数据必须满足的规则。例如主键不能为空且不能重复，外键必须引用已有记录或为空。

例子：学生选课系统中，学生表、课程表、选课表属于数据结构；查询某学生成绩、插入一条选课记录属于数据操作；成绩必须在 0 到 100 之间属于完整性约束。

### 数据抽象层次与数据模型级别

现实世界到数据库中的数据通常经过三层抽象：

- 现实世界：真实存在的对象和业务，例如学生、课程、选课。
- 信息世界：概念模型，例如 E-R 模型。
- 机器世界：DBMS 支持的数据模型，例如关系模型、层次模型、网状模型。

数据模型按使用目的可分为：

- 概念数据模型：面向用户和现实世界，与具体 DBMS 无关。例如 E-R 模型。
- 逻辑数据模型：用户从数据库系统看到的数据模型，与 DBMS 相关。例如关系模型。
- 物理数据模型：反映数据如何存储。

### 模式、实例与三级模式结构

模式 `Schema`：

- 数据库中全体数据的逻辑结构和特征的描述。
- 只描述“型”，不涉及具体值。

实例 `Instance`：

- 模式在某一时刻的具体值。

例子：

- 模式：$\text{学生}(\text{学号}, \text{姓名}, \text{年龄})$
- 实例：$(2024001,\text{张三},20)$、$(2024002,\text{李四},19)$ 这些具体记录。

三级模式结构：

| 层次  | 又称           | 含义                        | 数量        |
| --- | ------------ | ------------------------- | --------- |
| 外模式 | 子模式、用户模式、视图层 | 某类用户能看到和使用的局部数据视图         | 一个数据库可有多个 |
| 模式  | 逻辑模式         | 全体数据的逻辑结构和特征，是所有用户的公共数据视图 | 一个数据库只有一个 |
| 内模式 | 存储模式、物理层     | 数据在数据库内部的物理组织和存储方式        | 一个数据库只有一个 |

两级映像：

- 外模式/模式映像：保证逻辑独立性。模式改变时，调整映像使外模式不变，应用程序尽量不用改。
- 模式/内模式映像：保证物理独立性。存储结构改变时，调整映像使模式不变，应用程序不用改。

例子：

- 物理独立性：数据库从顺序存储改成 B+ 树索引存储，用户写的 SQL 不需要改变。
- 逻辑独立性：学生表增加一列 `电话`，某个只查询 `学号、姓名` 的外模式保持不变，对应程序不需要改。

### DBMS 的主要功能

DBMS 是管理数据库的软件系统，主要功能包括：

- 提供用户接口：程序员用户、终端用户、DBA。
- 数据库运行管理：安全性、完整性、并发控制、故障恢复、查询优化。
- 数据目录管理：管理元数据，即“关于数据的数据”。

## 第二章 关系模型

### 关系模型的基本概念

| 概念             | 含义                  | 例子                                                      |
| -------------- | ------------------- | ------------------------------------------------------- |
| 域 `Domain`     | 一组相同类型值的集合          | 性别域 `{男, 女}`，年龄域 `{18, 19}`                             |
| 笛卡尔积           | 多个域所有可能组合的集合        | `姓名域 x 性别域 x 年龄域`                                       |
| 元组 `Tuple`     | 笛卡尔积中的一个元素，也就是表中的一行 | $(\text{张三}, \text{男}, 20)$                             |
| 分量 `Component` | 元组中的某个值             | `张三`、`男`、`20`                                           |
| 关系 `Relation`  | 笛卡尔积的任意子集，直观上是一张二维表 | 学生表                                                     |
| 属性 `Attribute` | 关系中列的名字             | 学号、姓名、年龄                                                |
| 关系模式           | 对关系“型”的描述           | $\text{Student}(\text{Sno}, \text{Sname}, \text{Sage})$ |
| 关系             | 关系模式某一时刻的值          | Student 表中当前所有学生记录                                      |

关系模式是静态的，关系是动态的。表结构通常相对稳定，表中的记录会随插入、删除、修改而变化。

### 键：超键、候选键、主键、外键

- 超键 `SK`：能唯一标识一个元组的属性或属性集。
- 候选键 `CK`：最小的超键，去掉任一属性后就不能唯一标识元组。
- 主键 `PK`：从候选键中选定的一个键。
- 外键 `FK`：关系 R1 的某个属性集引用另一个关系 R2 的候选键，则该属性集是 R1 的外键。

例子：

$$
\begin{aligned}
\text{Student}(&\text{Sno}, \text{Sname}, \text{Sage})\\
\text{Course}(&\text{Cno}, \text{Cname}, \text{Credit})\\
\text{SC}(&\text{Sno}, \text{Cno}, \text{Grade})
\end{aligned}
$$

- `Student` 中 `Sno` 可以唯一标识学生，是候选键，也常作为主键。
- $(\text{Sno},\text{Sname})$ 也能唯一标识学生，但不是最小的，所以是超键，不是候选键。
- `SC.Sno` 引用 `Student.Sno`，所以 `SC.Sno` 是外键。
- `SC.Cno` 引用 `Course.Cno`，所以 `SC.Cno` 是外键。
- $\text{SC}$ 的主键通常是 $(\text{Sno},\text{Cno})$，表示一个学生选一门课只有一条记录。

### 关系的特征

关系模型中的关系有这些特征：

- 元组不重复且无序。
- 属性不重名且无序。
- 同一属性下的值来自同一域，即同一类型。
- 每个分量必须是**原子的**，不允许“表中有表”。
- 属性值可以为空值 `NULL`，表示未知或不适用。

考试易错点：投影后如果出现重复元组，要合并去重，因为关系不允许重复元组。

### 关系完整性约束

| 类型 | 要求 | 例子 |
| --- | --- | --- |
| 域完整性 | 属性取值必须在其值域内，是否允许 NULL 由语义决定 | 成绩应在 0-100 或 NULL |
| 实体完整性 | 主键值不可重复，且不能为 NULL | 学号不能重复、不能为空 |
| 参照完整性 | 外键值要么等于被引用表中某个候选键值，要么为 NULL | `SC.Sno` 必须存在于 `Student.Sno` |
| 用户定义完整性 | 具体应用的业务规则 | 选课成绩只能是 0-100；性别只能是男/女 |

### ⚠️关系模型三要素

关系模型由三部分组成：
![](../attachments/Pasted%20image%2020260620154411.png)
1. 关系数据结构：二维表、域、笛卡尔积、关系、关系模式。
2. 关系操作集合：关系代数、关系演算，以及查询、插入、删除、修改等操作。
3. 关系完整性约束：域完整性、实体完整性、参照完整性、用户定义完整性。

这和第一章“数据模型三要素”是一一对应的：数据结构、数据操作、完整性约束。

### 关系代数总览

关系代数的特点：运算对象是关系，运算结果仍是关系。
![424](../attachments/Pasted%20image%2020260626012324.png)
关系代数运算大致分两类：

| 类型     | 运算符       | 含义           |
| ------ | --------- | ------------ |
| 传统集合运算 | $\cup$    | 并            |
| 传统集合运算 | $-$       | 差            |
| 传统集合运算 | $\cap$    | 交            |
| 传统集合运算 | $\times$  | 广义笛卡尔积       |
| 专门关系运算 | $\sigma$  | 选择，筛选行       |
| 专门关系运算 | $\pi$     | 投影，筛选列并去重    |
| 专门关系运算 | $\bowtie$ | 连接，把相关元组拼接起来 |
| 专门关系运算 | $\div$    | 除，表达“全部”“所有” |

并、差、交要求两个关系“并兼容”：属性个数相同，且对应属性来自相同域。

$$
R(A_1,A_2,\ldots,A_n),\quad S(B_1,B_2,\ldots,B_n)
$$

如果 $A_i$ 和 $B_i$ 对应的域相同，则 $R$ 和 $S$ 可以做 $\cup$、$-$、$\cap$。

笛卡尔积 $\times$ 不要求并兼容。若 $R$ 有 $m$ 个属性、$|R|$ 个元组，$S$ 有 $n$ 个属性、$|S|$ 个元组，则：

$$
R\times S \text{ 有 } m+n \text{ 个属性，且 } |R\times S|=|R|\cdot|S|
$$

注意：笛卡尔积不会自动合并同名属性。如果两个关系都有属性 $A$，结果里要用 $R.A$、$S.A$ 或重命名来区分。

### 选择、投影、连接、除

#### 选择 $\sigma$

从关系中选出满足条件的行。

一般形式：

$$
\sigma_F(R)=\{t\mid t\in R\land F(t)\}
$$

例子：

$$
\sigma_{\text{Sdept}=\text{CS}}(\text{Student})
$$

含义：选择计算机系学生。

#### 投影 $\pi$

从关系中选出若干列，并去掉重复元组。

一般形式：

$$
\pi_X(R)=\{t[X]\mid t\in R\}
$$

例子：

$$
\pi_{\text{Sno},\text{Sname}}(\text{Student})
$$

含义：只保留学生的学号和姓名。

投影的结果是集合，所以重复行会被消去。例如两个学生重名，$\pi_{\text{Sname}}(\text{Student})$ 里同一个姓名只出现一次。

#### 连接 $\bowtie$

连接可以看作“笛卡尔积 + 选择”。

##### $\theta$ 连接

$\theta$ 连接是在笛卡尔积后按某个比较条件筛选，$\theta$ 可以是 $=$、$>$、$<$、$\ge$、$\le$、$\ne$。

$$
R\bowtie_{A\theta B}S=\sigma_{R.A\theta S.B}(R\times S)
$$

例子：

$$
\text{Student}\bowtie_{\text{Student.Sno}=\text{SC.Sno}}\text{SC}
$$

含义：把学生表和选课表按学号匹配起来。

##### 等值连接

等值连接是 $\theta$ 连接的特殊情况，连接条件只使用等号。

$$
R\bowtie_{R.A=S.B}S=\sigma_{R.A=S.B}(R\times S)
$$

注意：等值连接通常保留两边的连接属性。例如 $R.A$ 和 $S.B$ 虽然值相等，但结果里仍可以同时保留 $R.A$ 和 $S.B$。

##### 自然连接

自然连接是“按所有同名属性相等连接，并且同名属性只保留一份”。

设：

$$
C=\operatorname{Attr}(R)\cap\operatorname{Attr}(S)
$$

则自然连接可写成：

$$
R\bowtie S
=
\pi_{\operatorname{Attr}(R)\cup(\operatorname{Attr}(S)-C)}
\left(
\sigma_{\bigwedge_{A\in C}R.A=S.A}(R\times S)
\right)
$$

如果只有一个同名属性 $A$，就退化为 PPT 里的形式：

$$
R\bowtie S
=
\pi_{\operatorname{Attr}(R)\cup(\operatorname{Attr}(S)-\{A\})}
\left(
\sigma_{R.A=S.A}(R\times S)
\right)
$$

这个公式分三步看：

1. 先做 $R\times S$，得到所有可能配对。
2. 再做 $\sigma_{R.A=S.A}$，只保留同名属性值相等的配对。
3. 最后做 $\pi$，把重复出现的同名属性删掉，只保留一份。

例子：

$$
\text{Student}(\text{Sno},\text{Sname})\bowtie\text{SC}(\text{Sno},\text{Cno})
$$

自然连接会按 $\text{Sno}$ 相等连接，结果模式是：

$$
(\text{Sno},\text{Sname},\text{Cno})
$$

如果两个关系属性名和数量完全相同，且每个同名属性语义也相同，则自然连接等价于交：

$$
R\bowtie S=R\cap S
$$

但如果只是“碰巧同名”，自然连接可能会错连。考试写关系代数时，条件不明确的情况下，等值连接比自然连接更不容易产生歧义。

##### 外连接

外连接不是最基本的传统关系代数运算，但和 SQL 很相关。

| 类型 | 含义 |
| --- | --- |
| 左外连接 | 保留左关系 $R$ 中所有元组；右边匹配不到的属性补 $\text{NULL}$ |
| 右外连接 | 保留右关系 $S$ 中所有元组；左边匹配不到的属性补 $\text{NULL}$ |
| 全外连接 | 左右两边匹配不到的元组都保留，缺失部分补 $\text{NULL}$ |

内连接只保留能匹配上的元组，外连接会额外保留某一侧或两侧未匹配的元组。

##### 半连接

半连接只保留左关系中能与右关系匹配的元组，并且结果只含左关系的属性。

$$
R\ltimes S=\pi_{\operatorname{Attr}(R)}(R\bowtie S)
$$

例子：

$$
\text{Student}\ltimes\text{SC}
$$

含义：保留至少有选课记录的学生，但结果里只保留 $\text{Student}$ 的属性。

##### 自连接

自连接是一个关系和它自己的副本连接。做题时必须重命名，否则左右两份属性分不清。

例子：查询至少选修两门课程的学生。

$$
\pi_{A.\text{Sno}}\left(
  \sigma_{A.\text{Sno}=B.\text{Sno}\land A.\text{Cno}\ne B.\text{Cno}}
  \left(\rho_A(\text{SC})\times\rho_B(\text{SC})\right)
\right)
$$

$\rho_A(\text{SC})$ 和 $\rho_B(\text{SC})$ 表示把 $\text{SC}$ 重命名成两个副本，条件 $A.\text{Sno}=B.\text{Sno}$ 保证是同一个学生，条件 $A.\text{Cno}\ne B.\text{Cno}$ 保证是两门不同课程。

#### 除 $\div$

除法常用于“全部”“所有”类查询。

给定：

$$
R(X,Y),\quad S(Y)
$$

其中 $X$ 和 $Y$ 都可以是一组属性。$R\div S$ 的结果只保留 $X$ 属性：

$$
R\div S=\{x\mid x\in \pi_X(R)\land \forall y\in S,\ (x,y)\in R\}
$$

这句话的意思是：找出那些 $x$，它和 $S$ 中每一个 $y$ 的组合都出现在 $R$ 里。

PPT 里的 $t[X]s$ 表示“把元组 $t$ 在 $X$ 上的分量，和 $S$ 中元组 $s$ 拼成一个新元组”。例如：

$$
t[X]=(\text{S1}),\quad s=(\text{C1})
$$

则：

$$
t[X]s=(\text{S1},\text{C1})
$$

所以 PPT 公式可以理解为：

$$
T=R\div S=\{t[X]\mid t\in R\land \forall s\in S,\ t[X]s\in R\}
$$

也就是说，某个 $t[X]$ 能进结果，当且仅当它和 $S$ 里的每个 $s$ 拼起来之后，都能在 $R$ 里找到。

除法也可以用基本关系代数表示：

$$
R\div S=\pi_X(R)-\pi_X\left((\pi_X(R)\times S)-R\right)
$$

这个公式是最适合手算的版本：

1. $\pi_X(R)$：列出所有候选 $x$。
2. $\pi_X(R)\times S$：列出每个候选 $x$ 理论上应该具备的全部 $(x,y)$ 组合。
3. $(\pi_X(R)\times S)-R$：找出缺失的组合。
4. $\pi_X((\pi_X(R)\times S)-R)$：找出有缺失组合的“坏候选” $x$。
5. $\pi_X(R)-\pi_X((\pi_X(R)\times S)-R)$：所有候选减去坏候选，剩下的就是满足“全部”的 $x$。

也可以用“象集”理解。对每个 $x$，令：

$$
Y_x=\{y\mid (x,y)\in R\}
$$

那么：

$$
x\in R\div S \Longleftrightarrow S\subseteq Y_x
$$

例子：$\text{SC}$ 表示学生选课。

| Sno | Cno |
| --- | --- |
| S1 | C1 |
| S1 | C2 |
| S2 | C1 |
| S3 | C1 |
| S3 | C2 |

$S$ 表示要求选过的课程：

| Cno |
| --- |
| C1 |
| C2 |

则：

$$
\text{SC}(\text{Sno},\text{Cno})\div S(\text{Cno})=\{\text{S1},\text{S3}\}
$$

因为：

$$
Y_{\text{S1}}=\{\text{C1},\text{C2}\},\quad
Y_{\text{S2}}=\{\text{C1}\},\quad
Y_{\text{S3}}=\{\text{C1},\text{C2}\}
$$

$S1$ 和 $S3$ 的课程集合都包含 $\{\text{C1},\text{C2}\}$，$S2$ 不包含。

典型考试表达式：

$$
\pi_{\text{Sno},\text{Cno}}(\text{SC}) \div \pi_{\text{Cno}}(\text{Course})
$$

含义：选修了全部课程的学生学号。

这里：

$$
X=\{\text{Sno}\},\quad Y=\{\text{Cno}\}
$$

被除数 $\pi_{\text{Sno},\text{Cno}}(\text{SC})$ 表示“谁选了哪门课”，除数 $\pi_{\text{Cno}}(\text{Course})$ 表示“全部课程”。结果就是那些对每门课都存在选课记录的学生。

### 自然语言转关系代数的做题套路

统一使用这个模式：

$$
\begin{aligned}
\text{Student}(&\text{Sno}, \text{Sname}, \text{Sex}, \text{Age})\\
\text{Course}(&\text{Cno}, \text{Cname}, \text{Teacher})\\
\text{SC}(&\text{Sno}, \text{Cno}, \text{Grade})
\end{aligned}
$$

步骤：

1. 先判断要输出什么列，用 $\pi$。
2. 再判断筛选条件，用 $\sigma$。
3. 如果条件或输出跨多个表，先连接相关关系。
4. 出现“不”“未”“没有”，优先考虑差 $-$ 或 `NOT EXISTS` 思路。
5. 出现“至少两门”“同时选 C2 和 C4”，常用同一关系自乘或自连接。
6. 出现“所有”“全部”，优先考虑除 $\div$。

常见题型：

#### 查询王老师开设课程的编号和课程名

$$
\pi_{\text{Cno},\text{Cname}}\left(\sigma_{\text{Teacher}=\text{王}}(\text{Course})\right)
$$

先在 $\text{Course}$ 中选教师为王的课程，再投影课程编号和课程名。

#### 查询至少选修了一门王老师课程的学生学号

写法 1：

$$
\pi_{\text{Sno}}\left(\sigma_{\text{Teacher}=\text{王}}(\text{SC}\bowtie\text{Course})\right)
$$

写法 2：

$$
\pi_{\text{Sno}}\left(\text{SC}\bowtie\pi_{\text{Cno}}\left(\sigma_{\text{Teacher}=\text{王}}(\text{Course})\right)\right)
$$

第二种写法更清楚：先找王老师课程编号，再和选课表连接。

#### 查询李同学未选课程的编号

$$
\pi_{\text{Cno}}(\text{Course})-\pi_{\text{Cno}}\left(\sigma_{\text{Sname}=\text{李}}(\text{Student}\bowtie\text{SC})\right)
$$

含义：所有课程编号减去李同学已经选的课程编号。

#### 查询至少选修两门课程的学生学号

$$
\pi_1\left(\sigma_{1=4 \land 2\ne5}(\text{SC}\times\text{SC})\right)
$$

这里把 $\text{SC}(\text{Sno},\text{Cno},\text{Grade})$ 自乘：

- 左边 $\text{SC}$ 的第 1 列是学生号，第 2 列是课程号。
- 右边 $\text{SC}$ 的第 4 列是学生号，第 5 列是课程号。
- $1=4$ 表示同一个学生。
- $2\ne5$ 表示两门不同课程。

更易读的写法：

$$
\pi_{A.\text{Sno}}\left(
  \sigma_{A.\text{Sno}=B.\text{Sno}\land A.\text{Cno}\ne B.\text{Cno}}
  \left(\rho_A(\text{SC})\times\rho_B(\text{SC})\right)
\right)
$$

其中 $\rho_A(\text{SC})$ 和 $\rho_B(\text{SC})$ 表示把同一个 $\text{SC}$ 关系分别重命名为两个副本，方便区分左右两边的属性。

#### 查询全部学生均选修了的课程编号及名称

$$
\pi_{\text{Cno},\text{Cname}}\left(
  \text{Course}\bowtie
  \left(\pi_{\text{Sno},\text{Cno}}(\text{SC}) \div \pi_{\text{Sno}}(\text{Student})\right)
\right)
$$

解释：

- $\pi_{\text{Sno},\text{Cno}}(\text{SC})$ 表示“谁选了哪门课”。
- $\pi_{\text{Sno}}(\text{Student})$ 表示“全部学生”。
- 除法结果是“被所有学生都选了的课程号”。
- 再与 $\text{Course}$ 连接得到课程名。

### 关系代数表达式计算方法

计算表达式时按内到外做：

1. 先算括号里的关系。
2. 选择 $\sigma$：删行。
3. 投影 $\pi$：删列并去重。
4. 连接 $\bowtie$：先按条件配对，再保留需要的属性。
5. 差 $-$：从左关系中删除也在右关系中的元组。
6. 除 $\div$：对每个候选 $X$ 看其象集是否包含 $S$ 的所有 $Y$。

小例子：

$\text{SC}$ 中有：

| Sno | Cno |
| --- | --- |
| S1 | C1 |
| S1 | C2 |
| S2 | C1 |

$\text{Course}$ 中有：

| Cno |
| --- |
| C1 |
| C2 |

则：

$$
\pi_{\text{Sno},\text{Cno}}(\text{SC}) \div \pi_{\text{Cno}}(\text{Course})
$$

结果是 $S1$，因为 $S1$ 同时有 $C1$、$C2$；$S2$ 只有 $C1$，不满足“所有课程”。

### 关系演算：与关系代数的区别

关系代数偏“过程”：说明怎么通过选择、投影、连接等运算得到结果。

关系演算偏“描述”：说明结果元组应满足什么谓词条件。

分类：

- 元组关系演算：以元组变量为基本对象。
- 域关系演算：以域变量为基本对象。

### 元组关系演算

一般形式：

$$
\{\,t \mid P(t)\,\}
$$

含义：所有使谓词 $P(t)$ 为真的元组 $t$。

常见原子公式：

- $R(t)$：元组 $t$ 属于关系 $R$。
- $s[i]\ \theta\ t[j]$：元组 $s$ 的第 $i$ 个分量与元组 $t$ 的第 $j$ 个分量满足比较关系。
- $s[i]\ \theta\ c$：元组分量与常量比较。

常用符号：

- $\exists$：存在。
- $\forall$：任意/所有。
- $\land$：并且。
- $\lor$：或者。
- $\neg$：非。

常用关系运算在元组关系演算中的等价表示：

#### 选择

$$
\sigma_F(R)\equiv \{\,t\mid R(t)\land F(t)\,\}
$$

含义：先让元组 $t$ 属于关系 $R$，再加上筛选条件 $F(t)$。

#### 投影

$$
\pi_{i_1,i_2,\ldots,i_k}(R)\equiv
\left\{\,t\ \middle|\ \exists u\big(R(u)\land t[1]=u[i_1]\land t[2]=u[i_2]\land \cdots \land t[k]=u[i_k]\big)\right\}
$$

含义：结果元组 $t$ 的各分量，分别取自原元组 $u$ 的指定列。

#### 并

$$
R\cup S\equiv \{\,t\mid R(t)\lor S(t)\,\}
$$

#### 差

$$
R-S\equiv \{\,t\mid R(t)\land \neg S(t)\,\}
$$

#### 交

$$
R\cap S\equiv \{\,t\mid R(t)\land S(t)\,\}
$$

![360](../attachments/Pasted%20image%2020260620171753.png)

例 1：查询课程名为“数据结构”的学生学号和姓名。
$$
\begin{aligned}
\text{Student}(&\text{Sno}, \text{Sname}, \text{Sex}, \text{Age})\\
\text{Course}(&\text{Cno}, \text{Cname}, \text{Teacher})\\
\text{SC}(&\text{Sno}, \text{Cno}, \text{Grade})
\end{aligned}
$$
$$
\left\{\,t\ \middle|\ 
\begin{aligned}
&\exists u\,\exists v\,\exists w\big(
  \text{Student}(u)\land \text{SC}(v)\land \text{Course}(w)\\
&\land\ u[1]=v[1]
 \land\ v[2]=w[1]
 \land\ w[2]=\text{'数据结构'}\\
&\land\ t[1]=u[1]
 \land\ t[2]=u[2]
\big)
\end{aligned}
\,\right\}
$$

理解：

- $u$ 是学生元组，$v$ 是选课元组，$w$ 是课程元组。
- $u[1]=v[1]$ 把学生和选课按学号连接。
- $v[2]=w[1]$ 把选课和课程按课程号连接。
- $w[2]=\text{数据结构}$ 限定课程名。
- 最后用 $t[1]$、$t[2]$ 指定输出列。

例 2：查询选修课程号为 C2 或 C4 的学生学号。

$$
\left\{\,t\ \middle|\ 
\exists u\left(
  \text{SC}(u)
  \land (u[2]=\text{C2} \lor u[2]=\text{C4})
  \land t[1]=u[1]
\right)
\,\right\}
$$

例 3：查询至少同时选修 C2 和 C4 的学生学号。

$$
\left\{\,t\ \middle|\ 
\begin{aligned}
&\exists u\,\exists v\big(
  \text{SC}(u)\land\text{SC}(v)
  \land u[2]=\text{C2}\\
&\land\ v[2]=\text{C4}
  \land u[1]=v[1]
  \land t[1]=u[1]
\big)
\end{aligned}
\,\right\}
$$

这个例子和关系代数中的 $\text{SC}\times\text{SC}$ 自连接对应。

### 域关系演算

一般形式：

$$
\{\,x_1,x_2,\ldots,x_k \mid P(x_1,x_2,\ldots,x_k)\,\}
$$

域演算以单个属性值为变量，而不是以整条元组为变量。

例：检索学习课程号为 C2 的学生学号与成绩。

完整写法：

$$
\left\{\,t_1,t_2\ \middle|\ 
\exists u_1\,\exists u_2\,\exists u_3\big(
  \text{SC}(u_1,u_2,u_3)
  \land u_2=\text{C2}
  \land t_1=u_1
  \land t_2=u_3
\big)
\,\right\}
$$

可简化为：

$$
\{\,t_1,t_2 \mid \text{SC}(t_1,\text{C2},t_2)\,\}
$$

元组演算和域演算的区别：

- 元组演算变量代表一整行，所以用 $u[1]$、$u[2]$ 取分量。
- 域演算变量代表某个属性值，所以直接写在关系谓词的位置上。

### 建表语法补充：CREATE TABLE

`CREATE TABLE` 不只是定义表名和列名，还要定义完整性约束。完整性约束的作用是防止数据库中出现不合法数据。

基本格式：

```sql
CREATE TABLE 表名 (
  列名 数据类型 [列级完整性约束],
  列名 数据类型 [列级完整性约束],
  [表级完整性约束]
);
```

完整性约束主要分三类：

| 类型      | 作用                      | 常见 SQL 写法                             |
| ------- | ----------------------- | ------------------------------------- |
| 实体完整性   | 保证每个元组可唯一识别，主键不能为空且不能重复 | `PRIMARY KEY`                         |
| 参照完整性   | 保证外键值必须能在被参照表中找到，或为空    | `FOREIGN KEY ... REFERENCES ...`      |
| 用户定义完整性 | 根据具体业务限制属性取值            | `NOT NULL`、`UNIQUE`、`CHECK`、`DEFAULT` |

#### 列级约束和表级约束

列级约束写在某一列定义后面，只约束这一列。

```sql
Sname CHAR(20) NOT NULL, -- NULL/NO NULL指定是否可以取空值
Sage INT UNIQUE, -- 指定当前列取值不可重复
Cname CHAR(10) DEFAULT NULL -- DEFAULT <expr> 指定该列的缺省值是<expr>
```

表级约束写在所有列定义后面，可以约束一列，也可以约束多列。联合主键、联合外键通常必须写成表级约束。

```sql
PRIMARY KEY (Sno, Cno),
FOREIGN KEY (Sno) REFERENCES Student
ON DELETE RESTRICT/CASCADE/SET NULL
CHECK (Sage >= 0)
```
>- RESTRICT：只要子表还有记录引用父表记录，就不能删除父表记录；
>- CASCADE：删除父表时也删除子表
>- SET NULL：删除父表时把子表的外键值改成NULL

#### 实体完整性

实体完整性主要靠主键保证。

```sql
PRIMARY KEY (Sno)
```

含义：

- `Sno` 不能为 `NULL`。
- `Sno` 不能重复。
- 每个学生能被学号唯一标识。

联合主键：

```sql
PRIMARY KEY (Sno, Cno)
```

含义：单独的 `Sno` 可以重复，单独的 `Cno` 也可以重复，但同一个 `(Sno, Cno)` 组合不能重复。选课表 `SC` 常用这种写法，表示同一学生不能重复选同一门课。

#### 参照完整性

参照完整性主要靠外键保证。

```sql
FOREIGN KEY (Sno) REFERENCES Student(Sno)
```

含义：`SC.Sno` 的值必须已经存在于 `Student.Sno` 中，否则这条选课记录就是“没有学生的选课记录”，不合法。

删除或修改父表记录时，常见处理方式：

| 写法 | 含义 |
| --- | --- |
| `ON DELETE CASCADE` | 删除父表记录时，自动删除子表中引用它的记录 |
| `ON DELETE RESTRICT` | 如果子表中仍有引用，拒绝删除父表记录 |
| `ON DELETE SET NULL` | 删除父表记录时，把子表外键设为 `NULL`，前提是该列允许空值 |

例如：

```sql
FOREIGN KEY (Sno) REFERENCES Student(Sno) ON DELETE CASCADE
```

这里父表是 `Student`，子表是 `SC`。删除 `Student` 中某个学生时，会自动删除 `SC` 中该学生的选课记录；但删除 `SC` 中一条选课记录，不会影响 `Student` 中的学生。

#### 用户定义完整性

用户定义完整性是根据业务规则限制取值。

```sql
Grade DEC(4,1) CHECK (Grade IS NULL OR Grade BETWEEN 0 AND 100)
```

含义：成绩可以为空；如果不为空，必须在 0 到 100 之间。

```sql
Ssex CHAR(2) CHECK (Ssex IN ('男', '女'))
```

含义：性别只能取指定值。

```sql
Sdept CHAR(20) DEFAULT 'CS'
```

含义：插入学生时如果没有给出系别，默认填 `CS`。

例子：

```sql
CREATE TABLE SC (
  Sno CHAR(7) NOT NULL,
  Cno CHAR(6) NOT NULL,
  Grade DEC(4,1) DEFAULT NULL,
  PRIMARY KEY (Sno, Cno),
  FOREIGN KEY (Sno) REFERENCES Student(Sno) ON DELETE CASCADE,
  FOREIGN KEY (Cno) REFERENCES Course(Cno) ON DELETE RESTRICT,
  CHECK (Grade IS NULL OR Grade BETWEEN 0 AND 100)
);
```

解释：

- $(\text{Sno},\text{Cno})$ 是联合主键，表示同一学生同一课程只能出现一次。
- 删除学生时，`ON DELETE CASCADE` 表示该学生的选课记录级联删除。
	> 删除主表中的一条记录时，数据库自动把依赖它的子表记录一起删除。这里主表指外键Sno所述的Student，而子表指本表。
- 删除课程时，`ON DELETE RESTRICT` 表示如果有选课记录引用该课程，则限制删除。
- 成绩可以为空，也可以是 0-100。
>对其他数据库对象的CREATE看PPT


### 查询：SELECT

基本格式：

```sql
SELECT [ALL | DISTINCT] 目标列表达式
FROM 表名或视图名
[WHERE 条件表达式]

[ORDER BY 列名 [ASC | DESC]];
```

1. `FROM`：确定数据来源。
2. `WHERE`：筛选行。
3. `GROUP BY`：分组。

5. `SELECT`：确定输出列或表达式。
6. `ORDER BY`：排序。

##### 聚集函数
具有**统计性质**的一类函数，其运算对象通常是记录的集合或一组记录在某个列上的全部取值，聚集函数的返回结果一般将会是唯一的一个确定值。

##### GROUP BY

##### HAVING
作用于**分组后**的各个组，筛选**符合要求的组**。

>- `WHERE` 作用于分组前的行。
>- `HAVING` 作用于分组后的组。

#### `FROM` 中的派生表

有些题目需要先算一个中间结果，再拿它继续查询。考试里通常不用 `WITH`，可以直接把子查询放进 `FROM`，这就是派生表，也可以理解成临时表。

例如：查询平均成绩高于 80 的学生学号和平均成绩。

```sql
SELECT T.Sno, T.AvgGrade
FROM (
  SELECT Sno, AVG(Grade) AS AvgGrade
  FROM SC
  GROUP BY Sno
  HAVING AVG(Grade) > 80
) AS T;
```

这类写法的要点是：

- 子查询放在 `FROM` 里，外层把它当成一张临时表。
- 派生表必须起别名，比如这里的 `T`。
- 考试里如果题目能一条 SQL 直接写出来，优先直接写，不要绕成多层 CTE。

### 嵌入式 SQL（了解概念）

嵌入式 SQL 是把 SQL 语句嵌入到高级语言程序中使用，例如 C、COBOL、FORTRAN。

为什么需要嵌入式 SQL：

- SQL 擅长集合操作。
- 高级语言擅长过程控制、复杂业务逻辑、界面和输入输出。
- 嵌入式 SQL 用高级语言补足 SQL 的过程控制能力。

基本形式：

```c
EXEC SQL <SQL语句>;
```

核心概念：

| 概念 | 含义 |
| --- | --- |
| 主语言/宿主语言 | 嵌入 SQL 的高级语言，如 C |
| `EXEC SQL` | 区分 SQL 语句与主语言语句的前缀 |
| 预处理 | 先把嵌入式 SQL 转换成主语言函数调用，再交给主语言编译器 |
| SQLCA | SQL 通信区，保存 SQL 执行状态信息 |
| SQLCODE | SQLCA 中的返回代码，用来判断执行成功或失败 |
| 主变量 | SQL 中引用的宿主语言变量，SQL 语句中前面加冒号 |
| 指示变量 | 用于表示主变量是否为空、是否被截断等状态 |
| 游标 | 处理多行查询结果的缓冲区和指针机制 |

主变量例子：

```c
EXEC SQL SELECT Sno, Sname
  INTO :Hsno, :Hname
  FROM Student
  WHERE Sno = :givensno;
```

解释：

- `:givensno` 是输入主变量，由程序提供查询条件。
- `:Hsno`、`:Hname` 是输出主变量，用来接收查询结果。

游标使用步骤：

1. `DECLARE CURSOR`：声明游标，对应一条 `SELECT`。
2. `OPEN`：打开游标，执行查询，把结果放入缓冲区。
3. `FETCH`：逐条取结果到主变量。
4. `CLOSE`：关闭游标，释放资源。

游标模板：

```c
EXEC SQL DECLARE C CURSOR FOR
  SELECT Cno, Grade
  FROM SC
  WHERE Sno = :Hsno;

EXEC SQL OPEN C;

EXEC SQL FETCH C INTO :Hcno, :Hgrade;

EXEC SQL CLOSE C;
```

什么时候不需要游标：

- 数据定义语句，如 `CREATE TABLE`、`DROP TABLE`。
- 数据控制语句，如授权、收权。
- 结果为单记录的 `SELECT INTO`。
- 普通 `INSERT`、`UPDATE`、`DELETE`。

什么时候需要游标：

- `SELECT` 查询结果可能有多条记录，而宿主语言一次只能处理一条记录。

### 函数依赖基本概念

函数依赖写作：

$$
X \rightarrow Y
$$

含义：在关系模式 $R(U)$ 中，任意两个元组如果在属性集 $X$ 上取值相同，则在属性集 $Y$ 上取值也必须相同。此时称 $X$ 函数决定 $Y$，或 $Y$ 函数依赖于 $X$。
> ![389](../attachments/Pasted%20image%2020260623003851.png)

常见类型：

- 平凡函数依赖：若 $Y \subseteq X$，则 $X \rightarrow Y$ 是平凡依赖。
- 非平凡函数依赖：若 $Y \nsubseteq X$，则 $X \rightarrow Y$ 是非平凡依赖。
- **完全函数依赖**：$X \rightarrow Y$ 成立，但任意真子集 $X' \subset X$ 都不能推出 $Y$。（去掉某几个属性）
- **部分函数依赖**：$X \rightarrow Y$ 成立，且存在真子集 $X' \subset X$，使 $X' \rightarrow Y$ 成立。
- 传递函数依赖：若 $X \rightarrow Y$，$Y \rightarrow Z$，且 $Y \nrightarrow X$，则 $Z$ 传递依赖于 $X$。

例子：

$$
(\text{Sno},\text{Cno}) \rightarrow \text{Grade}
$$

表示一个学生选一门课后成绩唯一确定。

$$
\text{Cno} \rightarrow \text{Teacher}
$$

表示课程号唯一决定任课教师。如果在关系

$$
R(\text{Sno},\text{Cno},\text{Grade},\text{Teacher})
$$

中候选键是 $(\text{Sno},\text{Cno})$，那么 $\text{Teacher}$ 对候选键存在部分依赖，因为只靠 $\text{Cno}$ 就能决定它。

#### 逻辑蕴涵
![326](../attachments/Pasted%20image%2020260623011334.png)

### Armstrong公理
> 了解
- 自反律：$\text{if}\; Y\; \subseteq X \subseteq U,\; \text{then}\; X\rightarrow Y$
- 增广率：$\text{if}\; X\to Y \land Z\subseteq U,\; \text{then}\; XZ\to YZ$
- 传递率：$\text{if} \; X\to Y \land Y\to Z,\; \text{then}\; X\to Z$
#### 性质
- 正确性：使用规则从FD集F推出的FD必定在F闭包中；
- 完备性：若函数依赖 X→Y 不能由 F 从 Armstrong 公理导出，那么它必然不为 F 所蕴含
#### 函数依赖的推理规则
![325](../attachments/Pasted%20image%2020260623101919.png)
#### 逻辑导出
如果$F$根据Armstrong公理导出$X\to Y$，则$X\to Y$是$F$的逻辑导出，记作$F\Rightarrow X\to Y$。
### 属性集闭包

属性集 $X$ 关于函数依赖集 $F$ 的闭包记为：

$$
X_F^+=\{A\mid A\in U,\ F\models X\rightarrow A\}
$$

直观理解：从 $X$ 出发，利用 $F$ 中的函数依赖，最多能推出哪些属性。
> 这个东西的存在意义是为了代替求闭包/函数依赖（因为求闭包是NP完全问题）。
> ![307](../attachments/Pasted%20image%2020260623112753.png)
> ![520](../attachments/Pasted%20image%2020260623113132.png)

算法步骤：

1. 初始令 $X^+=X$。
2. 扫描函数依赖集 $F$，若存在 $Y\rightarrow Z$ 且 $Y\subseteq X^+$，则把 $Z$ 加入 $X^+$。
3. 重复第 2 步，直到 $X^+$ 不再变化。
4. 若最终 $X^+=U$，则 $X$ 是超键。

例子：

$$
U=\{A,B,C,D,E\}
$$

$$
F=\{AB\rightarrow C,\ B\rightarrow D,\ C\rightarrow E,\ EC\rightarrow B,\ AC\rightarrow B\}
$$

求 $(AB)_F^+$：
> 这里AB是一种并集，$\{A, B\}$，所以左部是$A$或者$B$都属于其子集。

$$
X^+=AB
$$

由 $AB\rightarrow C$、$B\rightarrow D$：

$$
X^+=ABCD
$$

由 $C\rightarrow E$：

$$
X^+=ABCDE
$$
所以：

$$
(AB)_F^+=ABCDE
$$
用途：

- 判断 $X\rightarrow Y$ 是否被 $F$ 蕴含：只要看 $Y\subseteq X_F^+$。
- 判断 $X$ 是否为超键：只要看 $X_F^+=U$。
- 求候选键、判断无损连接和依赖保持时都要反复用闭包。

### 函数依赖集闭包与等价
#### 闭包

![329](../attachments/Pasted%20image%2020260623011748.png)
函数依赖集 $F$ 的闭包记为：

$$
F^+
$$

它表示由 $F$ **能推出的所有函数依赖**。
#### 等价覆盖
两个函数依赖集 $F$ 和 $G$ 等价/互相覆盖，当且仅当：

$$
F^+=G^+
$$

实际判断时不用真的求完整闭包，而是互相检查覆盖：

$$
F\subseteq G^+ \quad \text{且} \quad G\subseteq F^+
$$
> 充要性质证明：
> ![](../attachments/Pasted%20image%2020260623122940.png)

做题方法：

- 对 $F$ 中每个 $X\rightarrow Y$，用 $G$ 求 $X_G^+$，看 $Y$ 是否包含在其中。
- 对 $G$ 中每个 $X\rightarrow Y$，用 $F$ 求 $X_F^+$，看 $Y$ 是否包含在其中。

### ⚠️⚠️⚠️最小函数依赖集
**最小覆盖**也叫**最小函数依赖集**。它通常满足：

- 每个函数依赖右部只有一个属性。
- F 中不存在这样的函数依赖 $X\to A$ 及 $Z\subset X$ ，使得
	$$F^+ = (F - \{X\to A\} \cup \{Z \to A\})^+$$
- 没有多余的函数依赖$X\to A$。
	$$F^+ = (F - \{X\to A\})^+$$
> ![472](../attachments/Pasted%20image%2020260623101212.png)

求最小覆盖步骤：

 1. 拆右部：
$$
X\rightarrow A_1A_2\cdots A_k
$$

改成：

$$
X\rightarrow A_1,\ X\rightarrow A_2,\ \ldots,\ X\rightarrow A_k
$$

2. 消左部冗余属性：对每个 $X\rightarrow A$，若 $B\in X$ 且

$$
A\in (X-\{B\})_F^+
$$

则 $B$ 是多余属性，可以从左部删去。

3. 删除冗余依赖：对每个 $X\rightarrow A$，令

$$
G=F-\{X\rightarrow A\}
$$

若：

$$
A\in X_G^+
$$

则 $X\rightarrow A$ 是冗余依赖，可以删除。

注意：最小覆盖不一定唯一，和处理依赖、处理属性的顺序有关。
### 多值依赖（了解）

#### 直观理解

多值依赖（MVD，Multi-Valued Dependency）描述的是：**给定 X 的值，Y 的取值集合就完全确定了，而与其余属性 Z 无关**。

与函数依赖的区别：
- FD：X→Y，给定 x，Y 只有**一个值**。
- MVD：X→→Y，给定 x，Y 有**一组值**，但这组值与 Z 没关系。

**直观条件**：关系至少要有三个属性，其中两个是"多值的"，且它们的值只依赖于第三个属性，才会产生多值依赖。

#### 定义

**定义 4.10（直观）**：设 $R(U)$ 是属性集 $U$ 上的关系模式，$X,Y,Z$ 是 $U$ 的子集，且 $Z=U-X-Y$。若对 $R(U)$ 的任一关系 $r$，给定一对 $(x,z)$ 值有一组 $Y$ 的值，**这组值仅仅决定于 $x$ 而与 $z$ 无关**，则称多值依赖 $X\twoheadrightarrow Y$ 成立。

**定义 4.11（形式化）**：若 $r$ 中存在 $s,t$ 两个元组使得 $s[X]=t[X]$，则 $r$ 中必存在 $u,v$ 使得：

$$
u[X]=v[X]=s[X]=t[X]
$$

$$
u[Y]=t[Y],\quad u[Z]=s[Z]
$$

$$
v[Y]=s[Y],\quad v[Z]=t[Z]
$$

即：**交换 $s,t$ 在 $Y$ 上的值所得到的两个新元组，也必须在 $r$ 中**。

#### 平凡多值依赖

**定义 4.12**：若 $X\twoheadrightarrow Y$，且 $Z=U-XY=\varnothing$，则称 $X\twoheadrightarrow Y$ 为**平凡的多值依赖**。

> 平凡 MVD 总是成立的，没有实质意义。如果关系中存在**非平凡非 FD 的 MVD**，则会导致数据冗余和更新异常。

#### 举例

**例1：WSC(W,S,C)** —— W=仓库，S=保管员，C=商品

业务规则：每个仓库有若干保管员和若干商品，每个保管员保管所在仓库的所有商品。

| W | S | C |
|---|---|---|
| W1 | S1 | C1 |
| W1 | S1 | C2 |
| W1 | S1 | C3 |
| W1 | S2 | C1 |
| W1 | S2 | C2 |
| W1 | S2 | C3 |

对于 W1，S 的集合 $\{S1,S2\}$ 仅由 W 决定，不管 C 取什么值。所以 $W\twoheadrightarrow S$（同理 $W\twoheadrightarrow C$）。

这张表有大量冗余：加一个商品 C4，就要为每个保管员都加一行。

**例2：R(A,B,C)**，有 MVD $A\twoheadrightarrow B$。已有元组 $(a,b1,c1),(a,b2,c2),(a,b3,c3)$，则至少还存在：

$$
(a,b1,c2),(a,b2,c1),(a,b1,c3),(a,b3,c1),(a,b2,c3),(a,b3,c2)
$$

共 6 个额外元组（把 B 和 C 的值两两配对）。

#### 推理规则

**基本公理（A4–A8）**：

| 规则 | 条件 | 结论 |
|------|------|------|
| **A4 互补律** | $X\twoheadrightarrow Y$ | $X\twoheadrightarrow (U-X-Y)$ |
| **A5 扩展律(MVD)** | $X\twoheadrightarrow Y$，$V\subseteq W\subseteq U$ | $WX\twoheadrightarrow VY$ |
| **A6 传递律(MVD)** | $X\twoheadrightarrow Y$，$Y\twoheadrightarrow Z$ | $X\twoheadrightarrow (Z-Y)$ |
| **A7 FD→MVD** | $X\rightarrow Y$ | $X\twoheadrightarrow Y$ |
| **A8 混合** | $X\twoheadrightarrow Y$，$Z\subseteq Y$，$W\cap Y=\varnothing$，$W\rightarrow Z$ | $X\rightarrow Z$ |

**派生规则**：

1. **MVD 合并**：若 $X\twoheadrightarrow Y$ 且 $X\twoheadrightarrow Z$，则 $X\twoheadrightarrow YZ$
2. **MVD 伪传递**：若 $X\twoheadrightarrow Y$ 且 $WY\twoheadrightarrow Z$，则 $WX\twoheadrightarrow (Z-WY)$
3. **混合伪传递**：若 $X\twoheadrightarrow Y$ 且 $XY\rightarrow Z$，则 $X\rightarrow (Z-Y)$
4. **MVD 分解**：若 $X\twoheadrightarrow Y$ 且 $X\twoheadrightarrow Z$，则 $X\twoheadrightarrow (Y\cap Z)$，$X\twoheadrightarrow (Y-Z)$，$X\twoheadrightarrow (Z-Y)$ 均成立

#### 性质

1. **对称性**：若 $X\twoheadrightarrow Y$，则 $X\twoheadrightarrow (U-XY)$（即 A4 互补律）
2. **传递性**：若 $X\twoheadrightarrow Y$，$Y\twoheadrightarrow Z$，则 $X\twoheadrightarrow (Z-Y)$
3. **FD 是 MVD 的特例**：若 $X\rightarrow Y$，则 $X\twoheadrightarrow Y$（一个值是一组值的特例）
4. 若 $X\twoheadrightarrow Y$ 且 $X\twoheadrightarrow Z$，则 $X\twoheadrightarrow YZ$
5. 若 $X\twoheadrightarrow Y$ 且 $X\twoheadrightarrow Z$，则 $X\twoheadrightarrow Y\cap Z$
6. 若 $X\twoheadrightarrow Y$ 且 $X\twoheadrightarrow Z$，则 $X\twoheadrightarrow Y-Z$，$X\twoheadrightarrow Z-Y$

#### MVD 与 FD 的区别

|     | FD $X\rightarrow Y$                          | MVD $X\twoheadrightarrow Y$           |
| --- | -------------------------------------------- | ------------------------------------- |
| 本质  | 等值产生依赖：禁止某些元组出现                              | 元组产生依赖：要求某些元组必须出现                     |
| 有效性 | 只要 $XY\subseteq W\subseteq U$，在任何超集 $W$ 上都成立 | **有效性与属性集范围有关**，在 $W$ 上成立不代表在 $U$ 上成立 |

**有效性范围要点**：
- $X\twoheadrightarrow Y$ 在 $U$ 上成立 $\Rightarrow$ 在任何 $W$（$XY\subseteq W\subseteq U$）上也成立
- 反过来**不成立**：$X\twoheadrightarrow Y$ 在 $W$ 上成立，但在 $U$ 上不一定成立

### 无损连接分解

分解：

$$
\rho=\{R_1,R_2,\ldots,R_k\}
$$

是无损连接分解，直观意思是：原关系投影到各个子模式后，再自然连接回来，不产生错误元组，也不丢信息。
![](../attachments/Pasted%20image%2020260623142649.png)
#### 二元分解快速判定

若：

$$
\rho=\{R_1,R_2\}
$$

则无损连接的充要条件是：

$$
(R_1\cap R_2)\rightarrow (R_1-R_2)
$$

或：

$$
(R_1\cap R_2)\rightarrow (R_2-R_1)
$$

例子：

$$
R(A,B,C),\quad \rho=\{AB,BC\}
$$

公共属性是：

$$
AB\cap BC=B
$$

若 $F$ 中能推出：

$$
B\rightarrow A
$$

或：

$$
B\rightarrow C
$$

则该二元分解无损。

#### 多元分解表格法

假设有$R(A_1, A_2, ..., A_n)$ 及其上之函数依赖集$F$，$\rho=\{R_1,\ldots,R_k\}$，判断$\rho$是否无损分解。

步骤：

1. 建一个 $k$ 行、$n$ 列的符号表。列对应 $R$ 的全部属性 $A_1,\ldots,A_n$，行对应每个子模式 $R_i$。
2. 如果属性 $A_j\in R_i$，该格填 $a_j$；否则填 $b_{ij}$。**（归类属性）**
3. 反复使用函数依赖 $X\rightarrow Y$：若$\geq2$行在 $X$ 属性列上的符号相同，就把这些行在 $Y$ 属性列上的符号改成一致。
4. 如果某一行变成：

$$
a_1,a_2,\ldots,a_n
$$

则分解无损。

5. 若表不再变化且没有全 $a$ 行，则不是无损连接分解。

![416](../attachments/Pasted%20image%2020260623175314.png)

### 保持函数依赖

分解 $\rho=\{R_1,\ldots,R_k\}$ 保持函数依赖，意思是：原来的依赖 $F$ 能由各子模式上的依赖投影联合推出。

形式上：

$$
\left(\bigcup_i \pi_{R_i}(F)\right)^+ \supseteq F
$$
或者：
$$
\bigcup_i \pi_{R_i}(F) \models F
$$

做题判断方法：
>![594](../attachments/Pasted%20image%2020260623183503.png)
>图中是原始的算法，以下是避免求属性集闭包的做法。
1. 对 $F$ 中每个依赖 $X\rightarrow Y$ 逐个检查。
2. 令 $Z=X$。
3. 对每个子模式 $R_i$，计算：

$$
Z := Z\cup((Z\cap R_i)^+\cap R_i)
$$

并加入 $Z$。
4. 反复步骤123，直到 $Z$ 不再变化，此时$Z$就是$X^+_G$。
5. 若 $Y\subseteq Z$，则该依赖（$X\rightarrow Y$）被保持；所有依赖都被保持，则分解保持函数依赖。

### 求候选键
![356](../attachments/Pasted%20image%2020260623192952.png)
> $(K \rightarrow U） \in F^+$，意思是K能推出全部属性U，而这个可以用$F^+$（闭包）中推出来。这个式子等价于，**算K的属性集闭包可以涵盖全集$U$中的所有属性。**

候选键是最小超键：能推出全部属性，且去掉任意属性后不能推出全部属性。

课件给出的常用分类方法：
关系模式$R(U,F)$，其中$F$是最小覆盖
- $C_1$：不在任何函数依赖中出现的属性。
- $C_2$：只在函数依赖左部出现的属性（左部就是函数决定子）。
- $C_3$：只在函数依赖右部出现的属性。
- $C_4$：左右部都出现的属性。

关键结论：

$$
C_1\cup C_2
$$

一定包含在任何候选键中。

算法步骤：

1. 先计算：

$$
(C_1\cup C_2)^+
$$

若等于 $U$，或者$C_4=\emptyset$，则 $C_1\cup C_2$ 是唯一候选键。

2. 若不等于 $U$，遍历$C_4$ 中成员分别与$C_1\cup C_2$求并集，计算闭包。
3. 某次加入属性后能推出 $U$ ，则$C_1\cup C_2$和这个属性构成一个CK。
4. 重复步骤2、3,换一个$C_4$的成员并上去，直到找全所有候选键。

例子：

$$
R(A,B,C,D),\quad F=\{A\rightarrow B,\ B\rightarrow C,\ BD\rightarrow A\}
$$

分类：

$$
C_1=\varnothing,\quad C_2=\{D\},\quad C_3=\{C\},\quad C_4=\{A,B\}
$$

先看：

$$
D^+=D
$$

不是超键。加入 $A$：

$$
(AD)^+=ADBC=U
$$

加入 $B$：

$$
(BD)^+=BDAC=U
$$

所以候选键为：

$$
AD,\ BD
$$

### 范式判断

常用范式关系：

$$
\text{BCNF}\Rightarrow \text{3NF}\Rightarrow \text{2NF}\Rightarrow \text{1NF}
$$
![335](../attachments/Pasted%20image%2020260623192059.png)
#### 1NF
每个属性值都是**不可再分**的原子值。
如果一个属性里存了”多个电话””多个课程列表”，就不满足 1NF。
满足1NF的关系是规范化的关系，否则是非规范化的。
>![348](../attachments/Pasted%20image%2020260623192636.png)
#### 2NF
在 1NF 基础上，所有**非主属性**都*完全函数依赖*于**所有** **候选键**。
>完全函数依赖：就是CK的所有属性才能确定依赖关系，少其中一条就不行；部分函数依赖 就是说可以用部分的CK的属性来决定某个非主属性。

违反 2NF 的典型情况：组合键的一部分就能决定某个非主属性，也就是有**部分函数依赖**的问题。
例子：

$$
R(\text{Sno},\text{Cno},\text{Grade},\text{Teacher},\text{Dept})
$$
![](../attachments/Pasted%20image%2020260623202242.png)
候选键是 $(\text{Sno},\text{Cno})$，但：

$$
\text{Cno}\rightarrow \text{Teacher}
$$

所以 $\text{Teacher}$ 部分依赖于候选键，$R$ 不满足 2NF。
![376](../attachments/Pasted%20image%2020260623202456.png)
![377](../attachments/Pasted%20image%2020260623202511.png)
#### 3NF
![482](../attachments/Pasted%20image%2020260623201639.png)
在 2NF 基础上，消除非主属性对候选键的传递依赖。
等价判定条件：对每个非平凡函数依赖 $X\rightarrow A$，至少满足下列之一：

1. $X$ 是超键。
2. $A$ 是主属性。

例子：
$$
R(\text{Sno},\text{Cno},\text{Grade},\text{Teacher},\text{Dept})
$$

上文分解出来的$R_1$是
![377](../attachments/Pasted%20image%2020260623202511.png)
而这不满足3NF，因为$Dept$对于CK是部分依赖：
$$
\text{Cno}\rightarrow \text{Teacher},\quad \text{Teacher}\rightarrow \text{Dept}
$$

则：

$$
\text{Cno}\rightarrow \text{Dept}
$$

是**传递依赖**，通常违反 3NF。
解决方法是继续分解。
![](../attachments/Pasted%20image%2020260623203033.png)
#### BCNF
##### 定义
对每个非平凡函数依赖：

$$
X\rightarrow Y
$$

都要求 $X$ 必须是超键（必须包含$R$的某个候选键）。

BCNF 比 3NF 更严格。3NF 允许右部是主属性的某些情况，但 BCNF 不允许”决定子不是超键”。
> 备选定义：
> ![400](../attachments/Pasted%20image%2020260623203942.png)

>[!Tip]
>不是BCNF而是3NF的例子：ABCD是属性，其中AB和AC是CK，然后存在$B\rightarrow C$的情况。


范式判断套路：

1. 先求所有候选键。
2. 标出主属性和非主属性。
3. 看是否 1NF。
4. 看是否存在非主属性对候选键的部分依赖，判断 2NF。
5. 看是否存在非主属性对候选键的传递依赖，判断 3NF。
6. 看每个非平凡依赖的左部是否都是超键，判断 BCNF。

### 既无损连接又保持函数依赖的 3NF 分解算法（3NF合成算法）

PDF/PPT 里的标题是“**分解成 3NF 模式集的算法**”，原文称为：

> 算法 4.4：既无损连接又保持函数依赖的 3NF 分解算法

这个算法也常被叫作 **3NF 合成算法** 或 **3NF 综合算法**。考试里如果题目要求“分解为 3NF，且既无损连接又保持函数依赖”，优先用这个算法，而不是 BCNF 分解算法。

#### 输入输出

输入：

$$
R_R(U_R,F_R)
$$

其中 $U_R$ 是原关系模式的全部属性，$F_R$ 是原关系模式上的函数依赖集。

输出：

$$
\rho=\{R_0,R_1,\ldots,R_k,R_{ck}\}
$$

其中 $R_{ck}$ 表示必要时额外加入的候选键关系模式。

#### PDF 原算法步骤

1. 先把 $F_R$ 转换成等价的最小覆盖，记为 $F$。

2. 把**不在 $F$ 中出现的属性**单独构成一个关系模式：

$$
R_0(U_0)
$$

其余属性记为：

$$
U=U_R-U_0
$$

于是得到第一个分解：

$$
\rho=\{R_0,R\}
$$

其中：

$$
R(U,F)
$$

如果没有这种“不在 $F$ 中出现的属性”，则 $R_0$ 为空，可以省略。

3. 如果 $R$ 中有某一个函数依赖包含 $U$ 中的全部属性，则算法终止，输出当前 $\rho$。

直观理解：如果某个依赖已经把剩余属性全集覆盖了，当前模式不需要继续按依赖拆分。

4. 否则，将 $F$ 中的函数依赖**按照左部相同原则分组**。假设共分为 $k$ 组，则每一组生成一个关系模式：

$$
R_i(U_i,F_i)
$$

其中 $U_i$ 是该组函数依赖涉及的全部属性，$F_i$ 是该组中的函数依赖集。加入后得到：

$$
\rho=\{R_0,R_1,\ldots,R_k\}
$$

5. 上一步按函数依赖分组生成的关系模式会保持函数依赖。为了同时保证无损连接，需要再加入一个由任一候选键构成的关系模式：

$$
R_{ck}
$$

如果这个候选键关系模式已经包含在前面的某个 $R_i$ 中，则可以省略。

6. 输出：

$$
\rho=\{R_0,R_1,\ldots,R_k,R_{ck}\}
$$

算法结束。

#### 做题简化版

实际做题时通常按下面几步写就够：

1. 求 $F_{\min}$。
2. 按左部相同合并依赖，例如 $A\rightarrow B,\ A\rightarrow C$ 合并为 $A\rightarrow BC$。
3. 每组依赖 $X\rightarrow Y$ 生成一个关系模式 $XY$。
4. 删除被其他关系模式包含的子模式。
5. 若所得关系模式中没有任何一个包含原关系候选键，则补一个候选键关系模式。

#### 例子模板

若有：

$$
F_{\min}=\{A\rightarrow B,\ A\rightarrow C,\ D\rightarrow E\}
$$

按左部分组：

$$
A\rightarrow BC,\quad D\rightarrow E
$$

生成：

$$
R_1(A,B,C),\quad R_2(D,E)
$$

如果这两个都不含原关系的候选键，还要加一个候选键模式：

$$
R_{ck}
$$

#### 2024 回忆卷对应例子

设：

$$
R(A,B,C,D,E,G,H)
$$

$$
F_{\min}=\{EH\rightarrow A,\ A\rightarrow G,\ G\rightarrow D,\ B\rightarrow A,\ B\rightarrow C,\ C\rightarrow B\}
$$

先按左部相同分组：

$$
EH\rightarrow A
$$

$$
A\rightarrow G
$$

$$
G\rightarrow D
$$

$$
B\rightarrow AC
$$

$$
C\rightarrow B
$$

生成：

$$
R_1(E,H,A),\quad R_2(A,G),\quad R_3(G,D),\quad R_4(B,A,C),\quad R_5(C,B)
$$

其中 $R_5(C,B)\subseteq R_4(B,A,C)$，可以删去：

$$
R_1(E,H,A),\quad R_2(A,G),\quad R_3(G,D),\quad R_4(B,A,C)
$$

原关系候选键为：

$$
BEH,\ CEH
$$

上面生成的关系模式都不包含候选键，因此补一个候选键模式，例如：

$$
R_5(B,E,H)
$$

最终得到：

$$
\rho=\{R_1(E,H,A),R_2(A,G),R_3(G,D),R_4(B,A,C),R_5(B,E,H)\}
$$

这个分解保持函数依赖，并且由于补入了候选键关系模式，所以无损连接。

### BCNF 分解算法

目标：得到无损连接的 BCNF 模式集，但不一定保持函数依赖。

步骤：

1. 初始：

$$
\rho=\{R(U)\}
$$

2. 若 $\rho$ 中每个子模式都是 BCNF，结束。
3. 若某个子模式 $R_i$ 不满足 BCNF，则存在非平凡依赖：

$$
X\rightarrow A
$$

且 $X$ 不是 $R_i$ 的超键。

4. 将 $R_i$ 分解为：

$$
R_{i1}=X\cup A
$$

$$
R_{i2}=R_i-\{A\}
$$

5. 用 $R_{i1},R_{i2}$ 替换 $R_i$，继续检查。

考试易错点：BCNF 分解一般保证无损连接，但可能不保持函数依赖。若要求“无损且保持依赖”，通常优先用 3NF 合成算法。

## 第五章 数据库设计

考试注意事项：先画 ER 图再写关系模式；不考虑弱实体；联系和实体最好体现属性；$1:1$ 和 $1:N$ 不考虑部分参与和全参与；只有 $M:N$ 的二元联系才转化成额外关系模式；不要求会画扩展 ER 图。

本章按“考试版规则”复习即可：普通实体、普通属性、普通二元联系是重点；弱实体、扩展 ER、部分参与/全参与不作为本次考试处理对象。

### ER 模型基本元素

ER 模型主要包括：

- 实体：现实世界中可区分的对象，如学生、课程、教师。
- 属性：实体或联系的特征，如学号、姓名、成绩。
- 联系：实体之间的关联，如学生选修课程。

基本规定：
- **主键/候选键**：属性名**加下划线**
- **外键**：下加波浪线
- 实体矩形、联系菱形、属性椭圆
- 联系连线的基数约束：
	- `1:1`
	- `1:N`：如果一个A对应N个B，那么在A连线一端写1，B连线一段写N；
	- `M:N`：M个A对应N个B；

画 ER 图时要注意：

- 实体要有属性，最好标出键。
- 联系如果自身有属性，也要画出来。例如“选课”联系有成绩。
- 联系要标明基数约束：$1:1$、$1:N$、$M:N$。

### ER 设计步骤

做题建议：

1. 读题找名词，先确定实体。
2. 找动词或业务事件，确定联系。
3. 给实体补属性，给联系补联系属性。
4. 标基数：一对一、一对多、多对多。
5. 再转换成关系模式。

例子：

“学生选修课程，并记录成绩。”

实体：

$$
\text{学生}(\text{学号},\text{姓名},\text{性别})
$$

$$
\text{课程}(\text{课程号},\text{课程名},\text{学分})
$$

联系：

$$
\text{选修}(\text{成绩})
$$

基数：

$$
\text{学生} \ M:N \ \text{课程}
$$

1. 实体：

- 实体各自转换。
- $1:1$ 联系并入任一端。
- $1:N$ 联系并入 $N$ 端。
- $M:N$ 联系生成额外关系模式。
- 不写弱实体、扩展 ER、全参与/部分参与相关规则。

### 查询处理基本流程

SQL 查询一般经过：

1. 词法分析、语法分析。
2. 生成内部表示，通常是语法树或查询树。
3. 代数优化：用关系代数等价变换改写表达式。
4. 物理优化：选择具体存取路径和操作算法。
5. 生成执行计划并执行。

语法树中常见对应关系：

- `FROM`：形成关系来源，朴素形式可看成笛卡尔积。
- `WHERE`：选择条件，对应 $\sigma$。
- `SELECT`：输出列，对应 $\pi$。

语法优化和代数优化的关系：

- 语法优化：从 SQL 语句或语法树出发，识别 `SELECT-FROM-WHERE` 的结构，把它转换成关系代数表达式或查询树，并尽量避免明显低效的语法结构。
- 代数优化：在已经得到的关系代数表达式上，用等价变换规则进行改写，例如选择下推、投影下推、把笛卡尔积加选择改成连接。
- 物理优化：不再只是改写表达式，而是选择具体执行方法，例如用索引扫描、排序归并连接、散列连接等。

例子：

```sql
SELECT Sname
FROM Student, SC
WHERE Student.Sno = SC.Sno
  AND Cno = 'C2';
```

朴素关系代数可写成：

$$
\pi_{\text{Sname}}\left(
  \sigma_{\text{Student.Sno}=\text{SC.Sno}\land \text{Cno}=\text{C2}}
  (\text{Student}\times \text{SC})
\right)
$$

优化后应把选择和连接提前：

$$
\pi_{\text{Sname}}\left(
  \text{Student}\bowtie_{\text{Student.Sno}=\text{SC.Sno}}
  \sigma_{\text{Cno}=\text{C2}}(\text{SC})
\right)
$$

### 代数优化原则

代数优化是不考虑具体存储路径，仅根据关系代数**等价变换**优化表达式。

核心原则：

1. **尽可能早地执行选择** $\sigma$，减少行数。
2. 尽可能早地执行投影 $\pi$，减少列数，但不能删掉后续连接、选择、输出需要的属性；**投影和选择同时进行**。
3. 把**选择和笛卡尔积合并成连接**。
4. **投影**尽量与前后的操作合并，减少中间结果。
5. 找出**公共子表达式**，避免重复计算。

为什么避免笛卡尔积：

若 $R$ 有 $n$ 行，$S$ 有 $m$ 行：

$$
|R\times S|=n\cdot m
$$

中间结果可能巨大。连接本质上是带条件的笛卡尔积：

$$
R\bowtie_{\theta}S=\sigma_{\theta}(R\times S)
$$

所以应尽量先选择、投影，再连接。

#### 规则罗列

#### 常用
选择串接：

$$
\sigma_{F_1\land F_2}(E)
\equiv
\sigma_{F_1}(\sigma_{F_2}(E))
$$

选择交换：

$$
\sigma_{F_1}(\sigma_{F_2}(E))
\equiv
\sigma_{F_2}(\sigma_{F_1}(E))
$$

$$
\sigma_{F_R}(R\bowtie S)

(\sigma_{F_R}(R))\bowtie S
$$

其中 $F_R$ 只涉及 $R$ 的属性。

选择和笛卡尔积合并：

$$
\sigma_{R.A=S.B}(R\times S)
\equiv
R\bowtie_{R.A=S.B}S
$$

### 关系表达式优化算法
- Input：表达式的语法树
- Output：计算该表达式的程序
课件给出的算法思路：

1. 把复杂选择拆成多个选择：

$$
\sigma_{F_1\land F_2\land\cdots\land F_n}(E)
\Rightarrow
\sigma_{F_1}(\sigma_{F_2}(\cdots\sigma_{F_n}(E)\cdots))
$$

2. 把每个选择尽可能移向语法树叶端。
3. 把每个投影尽可能移向语法树叶端，但保留后续需要属性。
4. 把串接的选择、投影合并成单个选择、单个投影，或者选择后接投影。多个选择/投影能同时执行，或者争取一次扫描完成。
5. 把上述得到的语法树的内节点分组。每一二元运算 (×,∩ ,∪ ， -) 和它所有的直接祖先 ( 包括 σ , π 运算 ) 为一组。如果其后代直到叶子全是单目运算则也将它们并入该组，但当双目运算是笛卡尔积 (×) ，而且其后的选择不能与它结合为等值连接时除外。把这些单目运算单独分为一组
> 语法树里：
> - **叶节点**：基本关系（表名）
> - **内节点**：关系代数运算符，即 $\sigma$（选择）、$\pi$（投影）、$\bowtie$（连接）、$\times$（笛卡尔积）等
> ![522](../attachments/Pasted%20image%2020260624105157.png)
### 物理优化

物理优化是根据存取路径、索引、统计信息和操作算法选择执行策略。

常见选择操作实现：

- 全表扫描：没有索引或选择条件不适合索引时。
- 索引扫描：选择条件涉及有索引属性，尤其是等值条件或范围条件时。

常见连接算法：

| 算法 | 适用情况 |
| --- | --- |
| 嵌套循环连接 | 一个表很小，或外表筛选后很小时 |
| 索引嵌套循环连接 | 内表连接属性有索引 |
| 排序归并连接 | 两表已经按连接属性排序，或排序代价可接受 |
| 散列连接 | 等值连接，且能用哈希把数据较好分桶 |

物理优化使用时机：

- 选择条件有索引：优先考虑索引。
- 两表连接属性已排序：优先考虑排序归并连接。
- 一个关系很小，另一个关系连接属性有索引：优先考虑索引嵌套循环。
- 等值连接且无可用排序/索引优势：可考虑散列连接。

#### 连接算法代价计算

设 $b_R$、$b_S$ 为两个关系的块数，$n_B$ 为内存可用块数。

**嵌套循环法**（$R$ 为外关系，$S$ 为内关系）：

$$
b_R + \left\lceil \frac{b_R}{n_B - 1} \right\rceil \times b_S
$$

逻辑：每批读 $n_B-1$ 块外表，留 1 块给内表；每批完整扫一遍内表，整个过程下来外表只扫一遍。**外关系选小的代价更低**。

**排序归并（Merge）法**（两表已按连接属性排序）：

$$
b_R + b_S
$$
![520](../attachments/Pasted%20image%2020260624115216.png)
这个就是左右都排好序，用两个指针从小到大开始遍历，当前如果R大于S，S指针向下；如果S大，那就R指针向下。这样只需要扫 两遍。
各扫一遍即可。若未排序还需另加排序代价。
**哈希连接**法：
>**第一步：分桶**

对R 和 S 的连接属性用**同一个哈希函数** $h$ 计算哈希值，把两张表的元组分别散列到若干个"桶"里。
关键性质：如果 $R.A = S.B$，则 $h(R.A) = h(S.B)$，它们一定落在**同一个桶**里。
>**第二步：桶内匹配**

只需在每对对应桶内做连接，不同桶之间的元组不可能匹配，直接忽略。
```
R的桶1←→  S的桶1   只在桶内配对
R的桶2  ←→  S的桶2
...
```
**为什么快**：把大问题拆成很多小问题，每个桶可以装进内存单独处理，避免全表两两比对。
⚠️**适用条件**：等值连接（因为哈希只对等值有效，$>$、$<$ 这类条件用不了散列连接）。


**例（作业 7.5）**：Course $b_C=1000$，SC $b_{SC}=40$，内存 $n_B=6$，两表连接属性已有序。

- 嵌套循环（SC 为外，Course 为内）：$40 + \lceil 40/5 \rceil \times 1000 = 40 + 8000 = 8040$ 块
- 排序归并（Sort-merge）：$1000 + 40 = 1040$ 块

#### 连接启发式规则（课件）

1. 两表已按连接属性排序 → 排序归并法。
2. 一表连接属性有顺序索引或散列 → 另一表为外关系顺序扫，用索引查匹配。
3. 上述均不满足且两表较小 → 嵌套循环法。
4. 以上均不适用 → 散列连接法。

考试注意事项：并发控制、故障恢复、故障日志、REDO/UNDO、锁机制。
![500](../attachments/Pasted%20image%2020260625010206.png)
### 事务与 ACID
#### 事务
事务是数据库中一组操作构成的逻辑工作单位，要么全部成功，要么全部失败。

事务通常以：

```sql
BEGIN TRANSACTION;
COMMIT;
ROLLBACK;
```

相关语句表示。
#### 事务四性质（ACID）

| 特性              | 含义                |
| --------------- | ----------------- |
| 原子性 Atomicity   | 事务中操作要么全做，要么全不做   |
| 一致性 Consistency | 事务执行前后数据库都应处于一致状态 |
| 隔离性 Isolation   | 并发事务之间不能互相干扰      |
| 持久性 Durability  | 事务提交后结果应永久保存      |

恢复技术保证故障时的原子性和持久性；并发控制保证并发执行时的隔离性和一致性。

### 故障分类

| 故障类型 | 含义 | 恢复思路 |
| --- | --- | --- |
| 事务故障 | 单个事务未到正常终点就失败 | 撤销该事务，做 UNDO |
| 系统故障 | 系统停止运行，内存内容丢失，磁盘未坏 | 对未完成事务 UNDO，对已提交但可能未写盘事务 REDO |
| 介质故障 | 磁盘等外存损坏 | 装入备份，再利用日志 REDO 已提交事务 |

### 日志与先写日志原则
#### 日志
##### 格式
两种格式：
- 记录为单位；
- 数据块为单位。

日志用于记录事务对数据库的更新操作，是恢复的基础。
##### 内容组织
（以记录为单位的）日志内容：
- 事务开始标记 `BEGIN TRANSACTION`。
- 事务结束标记 `COMMIT` 或 `ROLLBACK`。
- 更新操作记录：事务标识、数据项、旧值、新值。

#### 先写日志原则

$$
\text{先写日志，再写数据库}
$$

原因：如果先改数据库但日志没写，故障后系统不知道如何撤销或重做该更新。

### 恢复策略

#### 事务故障恢复

只涉及一个失败事务。

步骤：

1. 反向扫描日志，找到该事务的更新操作。
2. 对每个更新执行逆操作，即把“更新前的值”写回数据库。
3. 直到读到该事务的开始标记。
![441](../attachments/Pasted%20image%2020260624123033.png)
本质：

$$
\text{UNDO}
$$

#### 系统故障恢复

重启后自动完成：

1. 正向扫描日志。
2. 有 `BEGIN` 且有 `COMMIT` 的事务放入 REDO 队列。
3. 有 `BEGIN` 但没有 `COMMIT` 的事务放入 UNDO 队列。
4. 对 UNDO 队列事务反向撤销。
5. 对 REDO 队列事务正向重做。

记忆：

$$
\text{未提交} \Rightarrow \text{UNDO}
$$

$$
\text{已提交} \Rightarrow \text{REDO}
$$

### 检查点
![322](../attachments/Pasted%20image%2020260624131041.png)
检查点用于减少恢复时扫描日志的范围，提高恢复效率。
检查点记录通常包括：

- 检查点时正在执行的事务清单。
- 这些事务最近日志记录的地址。

恢复时：

1. 找到最后一个检查点。
2. 从检查点开始扫描日志。由检查点记录得到当时所有正在执行的事务清单ACTIVE-LIST
3. 建立 UNDO-LIST 和 REDO-LIST。初始REDO-LIST是空，ACTIVE-LIST放到UNDO-LIST；
4. 从检查点开始正向扫描日志文件
	- 如果有新开始的$T_i$，把$T_i$暂时放入UNDO-LIST；
	- 如果有要提交的$T_j$，把它从UNDO-LIST移动到REDO-LIST；
	- 直到日志文件结束
5. 对 UNDO-LIST 执行 UNDO，对 REDO-LIST 执行 REDO。

典型判断：

- 检查点前已提交，且数据已写盘：通常不需要 REDO。
- 检查点后提交：需要 REDO。
- 故障时未提交：需要 UNDO。

### 并发执行可能导致的问题

| 问题    | 含义                                            |
| ----- | --------------------------------------------- |
| 丢失修改  | 两个事务写同一数据，后写覆盖先写                              |
| 读脏数据  | 一个事务读到一个临时被改变的数据（比如先被写回新值，然后事务ROLLBACK）       |
| 不可重复读 | 同一事务两次读同一数据，中间被其他事务修改，就是**不可复现**              |
| 幻读    | 同一事务按条件读一批记录，中间被其他事务插入/删除符合条件的记录；或者算是不可重复读的一种 |

并发控制目标：**让并发调度的结果等价于某个串行调度**。
*将所有事务串行起来的调度策略一定是正确的调度策略。*

### 锁类型
目前 DBMS 普遍采用**加锁方法**实现并发操作调度的可串行性，从而保证调度的正确性。

| 锁   | 又称     | 作用                                                     |
| --- | ------ | ------------------------------------------------------ |
| X 锁 | 排它锁、写锁 | 加锁事务对数据对象A可读可写，其他事务不能对A再加任何锁，也不能R/W这个数据                |
| S 锁 | 共享锁、读锁 | 加锁事务对数据对象A可读不可写，其他事务可对A再加 S 锁但不能加 X 锁，也就是说A对于其他事务也都是只读 |
| U 锁 | 更新锁    | 先声明可能更新，之后需要写时升级为 X 锁，提高并发度；被加U锁的时候别的事务还可以对数据A加S锁      |

相容性核心：

- $S$ 与 $S$ 相容。
- $S$ 与 $X$ 不相容。
- $X$ 与任何锁都不相容。
- $U$和$U$不相容
![553](../attachments/Pasted%20image%2020260624201456.png)
### 三级加锁协议
指定了3种基本加锁，还需要约定一些规则，指明加锁释放锁的时机等。

| 协议     | 规则                                                | 能解决的问题            |
| ------ | ------------------------------------------------- | ----------------- |
| 一级加锁协议 | 修改数据R前就要加 X 锁，事务结束（正常结束是COMMIT，非正常结束是ROLLBACK）才释放 | 防止丢失修改            |
| 二级加锁协议 | 一级加锁 + 加锁事务读数据A前加 S 锁，读完即可释放                      | 防止丢失修改、读脏数据       |
| 三级加锁协议 | 二级加锁 + 事务读数据A前加锁，一直保持到事务结束释放                      | 防止丢失修改、读脏数据、不可重复读 |

### 两段锁协议 2PL

两段锁协议把事务加锁过程分为两个阶段：

1. 扩展阶段/获得封锁：只能申请获得任何数据项上的任何锁，但是不能释放锁。
2. 收缩阶段：只能释放任何锁，不能再申请任何锁。
一个事务全程只有一个周期的两阶段，也就是前半段拓展，后半段收缩。
结论：

***若所有事务都遵守两段锁协议，则并发调度一定是可串行化的。***

注意：

- 2PL 保证**可串行化**。
- 2PL **不保证不会死锁**。
- **一次封锁法**一定满足 2PL，但 2PL 不要求一次性拿到所有锁。
>一次封锁法要求每个事务必须一次将所有要使用的数据全部加锁，否则就不能继续执行；***它可以防止死锁***！！！
### 基于时间戳的并发控制

每个事务在开始时获得一个唯一时间戳 $TS(T)$，越早开始时间戳越小。
- $tr(X)$：数据对象X的读时间戳，记录最后一次被读
- $tw(X)$：写时间戳，最后一次被写
- $ts(T)$：事务T的时间戳，一般取它被创建时的时刻。
#### 基本规则
- 若 $T$ 要读 $X$：若 $ts(T) < tw(X)$（有更新的事务已写过 $X$），则 $T$ 过时，撤销后赋予新时间戳重新交付；否则允许读，并更新**读时间戳**。
- 若 $T$ 要写 $X$：若 $ts(T) < tw/tr(X)$ ，则 $T$ 不可以执行，撤销并用新时间戳重新交付；否则允许写，并更新**写时间戳**。

特点：**无死锁**（不等待，直接回滚），但可能导致**饥饿（活锁）**。

### 乐观并发控制（了解）

假设冲突发生概率很低，事务执行时**不加锁**，事务对数据对象的修改不直接写入数据库，而是在内存中保存修改的副本。修改操作如果经过检查不违反可串行性，就写入数据库中并commit，否则撤销重新交付。分三个阶段：

1. **读阶段**：事务读数据到自己私有执行空间（副本），所有修改在本地副本上进行。
2. **检验阶段**：提交前检查本事务的更新操作是否与其他检验阶段/已提交事务冲突，保证不违反可串行性。
3. **写阶段**：验证通过则将修改写入数据库；冲突则回滚重做。
![551](../attachments/Pasted%20image%2020260625005025.png)
特点：适合读多写少场景；冲突少时效率高；冲突多时回滚代价大。与锁机制（悲观控制）的区别是**事后检验**而非**预防冲突**。

### 活锁与死锁

活锁：某事务长期等待，总是被其他事务插队（比如是LCFS的策略），或称为**饥饿**。解决思路：先来先服务（FCFS）。

死锁：事务之间形成**循环等待**。
![430](../attachments/Pasted%20image%2020260624202656.png)
死锁处理两种方法：

- 防止死锁：一次封锁法、顺序封锁法。
- 检测并处理死锁：构造事务等待图，若有环则死锁。选择代价较小的事务撤销，释放其锁。
#### 死锁预防
要破坏产生死锁的条件。
##### 一次封锁法
- 要求每个事务必须一次把所有要用到的数据都加锁，否则不能执行。
- 缺点：降低系统并发度
##### 顺序封锁法
- 预先对数据对象指定封锁顺序，按照事务顺序进行封锁。
- 缺点：事务的加锁请求会变化，所以很难实现确定事务封锁对象的范围，也很难规定封锁的顺序

#### 死锁检测
- 超时法：超时就算死锁。缺点就是会误判，或者时限设置太长不能及时检测

## 第九章 数据库完整性和安全性

>[!Note]
>考试注意事项：基本概念掌握。不考大题！

### 完整性与安全性的区别

- 完整性：保证数据正确、有效、相容。
- 安全性：防止非法用户非法使用数据库，避免数据泄露、篡改、破坏。

对比：

| 概念 | 关注点 | 例子 |
| --- | --- | --- |
| 完整性 | 数据是否正确 | 成绩必须在 0-100；外键必须引用已有学生 |
| 安全性 | 谁能访问/修改数据 | 普通学生不能修改成绩表 |

### 完整性约束分类

完整性约束按作用对象可分为：

- 列约束：类型、长度、取值范围、是否允许空值。
- 元组约束：同一元组各列之间的关系。
- 关系约束：元组之间、关系之间的约束。

按状态变化可分为：

- 静态约束：数据库某一确定状态必须满足的约束。
- 动态约束：数据库从一种状态变到另一种状态时，新旧值之间必须满足的约束。

六类完整性约束：

| 类型 | 例子 |
| --- | --- |
| 静态列级约束 | 年龄不能为负，成绩在 0-100 |
| 静态元组约束 | 开始日期不能晚于结束日期 |
| 静态关系约束 | 实体完整性、参照完整性、函数依赖 |
| 动态列级约束 | 工资修改后不能低于原工资 |
| 动态元组约束 | 新工资不得低于原工资加某个计算值 |
| 动态关系约束 | 事务一致性、原子性 |

### 完整性控制机制

DBMS 的完整性控制应包括：

1. 定义功能：允许用户定义完整性约束。
2. 检查功能：检查操作是否违反约束。
3. 违约处理：拒绝操作、级联处理、置空、回滚等。

检查时机：

- 立即执行约束：语句执行后立即检查。
- 延迟执行约束：事务提交前统一检查。

### 参照完整性处理策略

删除被引用关系元组时，常见策略：

- `CASCADE`：级联删除引用关系中的相关元组。
- `RESTRICT`：若存在引用元组，则拒绝删除。
- `SET NULL`：删除被引用元组，同时把引用关系中对应外键置空。

例子：

$$
\text{Student}(\underline{\text{Sno}},\text{Sname})
$$

$$
\text{SC}(\underline{\text{Sno}},\underline{\text{Cno}},\text{Grade})
$$

若删除某个学生：

- `CASCADE`：同时删除该学生所有选课记录。
- `RESTRICT`：若该学生有选课记录，就不允许删除学生。
- `SET NULL`：把选课记录中的学号置空，但前提是外键允许空值。

### 完整性约束说明方式

隐含约束：

- 数据类型、长度。
- 主键。
- 外键。
- `NOT NULL`。

显式约束：

- `CHECK` 子句。
- 断言 `ASSERTION`。
- 触发器 `TRIGGER`。
- 存储过程。

例子：

```sql
CHECK (Grade IS NULL OR Grade BETWEEN 0 AND 100)
```

表示成绩要么为空，要么在 0 到 100 之间。

### 安全性控制

常见安全措施：

1. 用户标识与鉴别：用户名、口令等。
2. 存取控制：定义用户权限并检查请求是否合法。
3. 视图机制：通过视图隐藏敏感数据。
4. 审计：记录用户操作，事后追踪非法访问。
5. 加密：保护敏感数据。

### 自主存取控制与强制存取控制

自主存取控制 DAC：

- 用户权限由授权机制控制。
- SQL 中常用 `GRANT`、`REVOKE`。
- 用户可在允许时把权限转授给别人。

强制存取控制 MAC：

- 系统为主体和客体分配安全级别/密级。
- 用户不能自主改变访问规则。
- 安全级别更高，适合严格保密场景。
![454](../attachments/Pasted%20image%2020260626015253.png)
![451](../attachments/Pasted%20image%2020260626015142.png)
>总结：低密级写高密级别的，是为了防止让更高密级的对象写低密集对象，导致泄露更机密信息。
>**高密等密读低密，等密（低密）写高密。**

SQL 授权例子：

```sql
GRANT SELECT, UPDATE(Grade) ON TABLE SC TO Wang;
```

```sql
REVOKE UPDATE(Grade) ON TABLE SC FROM Wang;
```
