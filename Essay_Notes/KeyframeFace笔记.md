## 一、摘要

本文提出了 **KeyframeFace**，一个基于语义关键帧的语言驱动面部动画生成框架。与传统文本到连续帧的密集回归范式不同，该方法将面部动画建模为 **可解释的 ARKit blendshape 空间中的稀疏关键帧序列**，从而将高层次语义意图与低层次运动细节解耦，赋予了精确的编辑能力和可解释性。框架分为两个阶段：**输入标准化**阶段利用大语言模型将多样化的用户输入统一为结构化脚本；**文本到动画**阶段通过微调 LLM，将关键帧描述转换为 ARKit 系数。为支持这一范式，作者构建了一个包含 **2,100** 条表情脚本的大规模多模态数据集，每条数据包含单目视频、逐帧 ARKit 系数和人工标注的语义关键帧。实验表明，语义关键帧监督与语言先验的结合显著提升了表情保真度和语义对齐性，优于不使用面部动作语义的方法。

## 二、背景

### 2.1 行业痛点

在专业动画制作流程中，面部表演通常通过**关键帧驱动的工作流**构建：动画师在语义关键的时刻定义稀疏的关键表情状态，中间运动通过插值获得。这种方式提供了对表情时机、强度和过渡的显式控制。然而，现有文本驱动面部动画方法大多采用**文本到连续帧**的直接回归范式，存在以下问题：

- **语义与运动纠缠**：高层语义意图与低层逐帧运动细节混合，缺乏可解释性。
- **编辑困难**：用户难以精确指定或编辑关键表情时刻（如微笑的开始、眉毛扬起的时机）。
- **标注成本高**：大多数数据集要么是语音驱动，要么仅含离散情绪类别，缺乏细粒度的语义描述。

### 2.2 现有数据集局限

如表 1 所示，现有 3D 面部运动数据集普遍存在以下不足：

| 局限      | 说明                                    |
| ------- | ------------------------------------- |
| 标注粒度过粗  | 仅有离散情绪类别（如 BU-4DFE、BP4D+），无法捕捉细微表情差异  |
| 缺少场景上下文 | 无情景背景描述，无法建模复合情绪                      |
| 缺少关键帧标注 | 仅有逐帧参数，缺乏语义关键帧的结构化标注                  |
| 设备昂贵    | 依赖 DI3D、3dMD 等专业实验室设备，难以扩展            |
| 缺乏自由文本  | 仅 Express4D 和 MMHead 提供自由文本，但前者提示过于简短 |

**KeyframeFace 数据集**是首个同时提供视频输入、文本标注、情景标签、**关键帧标注**、情绪标签和详细面部描述的数据集。

### 2.3 相关工作对比

- **KeyFace**：虽采用关键帧插值思路，但缺乏直接的文本条件控制。
- **Express4D**：使用自由文本提示驱动表情，但提示简短，难以建模复杂多阶段动态。
- **CTEG（When Words Smile）**：端到端的文本到 3D 表情生成，但仍是连续帧回归范式。

## 三、方法

### 3.1 问题形式化

受动画制作中关键帧范式的启发，本文将文本到面部动画重新形式化为**稀疏关键帧生成**问题。给定用户输入 $T$（范围从情绪词到详细行为描述），目标是预测一个结构化的动作-数值集合：

$$O = \left\{ \{(a_k, v_k^n)\}_{k=1}^{K} \right\}_{n=1}^{N}$$

其中：
- $N$：生成的关键帧数量，由 $T$ 的复杂度动态决定
- $K = 61$：ARKit blendshape 动作总数（如 `jawOpen`、`mouthSmile`、`browInnerUp` 等）
- $a_k$：第 $k$ 个 blendshape 动作名称，构成动作集 $A = \{a_k\}_{k=1}^{K}$
- $v_k^n \in [-1, 1]$：第 $k$ 个 blendshape 在第 $n$ 个关键帧处的激活值

这一形式化将高层语义意图与低层运动**显式解耦**，实现了可解释且可精确控制的面部动画合成。

### 3.2 整体架构

KeyframeFace 框架分为两个阶段：

**阶段一：输入标准化（Input Standardization）**

使用预训练 LLM 将任意格式的用户输入 $T$ 标准化为结构化脚本 $S$，从中提取情绪上下文、时序结构和表情细节。$S$ 在进入下一阶段前呈现给用户确认和调整，确保对动画意图的完全可控性。由于该阶段仅利用 LLM 固有的语义理解能力，无需额外训练即可泛化到任意输入格式。

**阶段二：文本到动画（Text-To-Animation）**

该阶段通过微调 LLM，将标准化后的关键帧描述转换为精确的 ARKit 参数序列，包含三个组件。

### 3.3 提示工程（Prompt Engineering）

设计结构化的系统提示 $P$，包含三个部分：
- **系统概述**：定义模型角色为专业面部表情专家
- **参数说明**：为全部 61 个 ARKit 系数构建语义映射，将每个参数与其对应的面部肌肉激活模式以文本形式关联
- **输出规范**：指定结构化输出格式

这使得模型能够利用预训练的面部解剖学知识进行精确的参数生成。

### 3.4 文本到 ARKit 的递归生成策略

如算法 1 所示，采用**递归关键帧生成策略**以保证生成质量和时序一致性：

1. **关键帧提取**：从脚本 $S$ 中提取关键帧描述序列：
   $$\{(F_n, n)\}_{n=1}^{N} \leftarrow f_{\text{key}}(S)$$

2. **目标帧指令构建**：对于每个关键帧描述 $F_n$，通过 $f_{\text{task}}$ 格式化为目标帧指令 $I_n$，引导模型专注于生成第 $n$ 个关键帧的 ARKit 系数。

3. **组合输入**：构造完整输入：
   $$U_n = P \oplus S \oplus I_n$$
   其中 $\oplus$ 表示拼接操作，$P$ 为系统提示，$S$ 为完整脚本上下文，$I_n$ 为当前帧指令。

4. **逐帧生成**：LLM 接收 $U_n$，生成第 $n$ 个关键帧的结构化动作-数值集合 $\{(a_k, v_k^n)\}_{k=1}^{K}$。

5. **迭代构建**：对所有 $N$ 个关键帧迭代执行，构造完整输出 $O$。

通过以全局上下文 $S$ 和特定帧指令 $I_n$ 为条件，模型生成既**局部精确**又**全局连贯**的参数。

### 3.5 训练目标

LLM 使用标准的**因果语言建模目标**进行微调：

$$\mathcal{L}_{\text{causal}} = -\frac{1}{L} \sum_{l=1}^{L} \log \frac{\exp(z_{l, x_l})}{\sum_{v \in \mathcal{V}} \exp(z_{l, v})}$$

其中：
- $L$：token 序列长度
- $z_{l, v}$：位置 $l$ 处词汇 $v$ 的预测 logit
- $x_l$：位置 $l$ 处的真实 token
- $\mathcal{V}$：词汇表

### 3.6 ARKit 到视觉动画的渲染

生成的 ARKit 参数序列 $O$ 通过 Epic Games 的 **MetaHuman** 系统渲染为高保真视觉动画。利用系统内置的动画曲线后处理实现时序平滑，并在关键帧样本之间进行**线性插值**，确保自然的时序过渡同时保持语义表情的完整性。

### 3.7 数据集构建

**脚本收集**：使用 ChatGPT-5 生成 2,100 条独特的表情脚本，每条包含三层结构：
- 情景背景（如"受试者生病但不想让家人担心"）
- 复合情绪状态（如"被压抑的痛苦"）
- 显式的关键帧级描述（如"嘴角抬起形成勉强的微笑，而目光依然虚弱，眉间保留细微皱纹"）

**运动采集**：21 名专业演员，iPhone TrueDepth 摄像头 60Hz 录制，ARKit 61 维 blendshape 格式。

**关键帧选择**：人工标注员审查每个视频，识别与文本关键帧描述精确匹配的帧，存储帧索引、对应 ARKit 系数向量和帧图像。

**数据增强**：通过两种方式丰富标注：
- **ARKit 标注**：利用 Qwen3-30B 将 ARKit 系数转换为肌肉级别的文本描述
- **图像标注**：利用 Qwen3-VL-30B 从关键帧图像合成描述，捕捉皮肤变形、眶周张力等 blendshape 几何之外的信息

## 四、结论

### 4.1 主要贡献

1. **关键帧中心范式**：提出将面部动画建模为语义关键帧而非密集运动轨迹，弥合了高层语言语义与低层面部运动之间的鸿沟。

2. **KeyframeFace 框架**：在可解释的 ARKit blendshape 空间中生成语义关键帧，实现对表情时机和强度的精确、可编辑控制。

3. **大规模多模态数据集**：2,100 条表情脚本，21 位专业演员，含脚本级语义监督、对齐的 ARKit 系数和人工标注的关键帧。

4. **LLM 先验的有效利用**：证明了 LLM 关于情绪和表情语义的预训练知识可以有效应用于面部动画生成。

### 4.2 关键实验结果

| 发现 | 说明 |
|------|------|
| ARKit 标注最优 | ARKit-based 标注在所有模型中一致优于 Original 和 Image-based 标注 |
| 语义配置至关重要 | 语义模型在 R-Precision 上接近翻倍，Semantic-4B 甚至超过 Non-Semantic-14B |
| 超越扩散模型 | MDM 在语义对齐上远逊于语义模型，仅在简单表情上表现尚可 |
| 语义监督 > 模型缩放 | 语义信息的贡献大于单纯增加模型参数量 |

### 4.3 局限与未来方向

**局限**：
- 依赖 ARKit blendshape 空间，限制了对细粒度面部动态（如舌位）的表征
- 模板化脚本限制了对无约束真实场景的泛化

**未来方向**：
- 扩展到更具表现力的面部表示
- 实现交互式或实时的语言驱动动画编辑
- 关键帧中心语义控制有望成为连接语言意图与面部运动的通用桥梁

---

> **个人评注**：KeyframeFace 的核心洞察在于**将问题形式化从"密集回归"提升到"语义关键帧"的抽象层次**，这与专业动画师的工作流天然对齐。相比 Express4D 的简短提示和 CTEG 的连续帧生成，该方法在可控性和可编辑性上具有明显优势。值得关注的是其使用的"递归生成策略"——以全局脚本 $S$ 为条件逐帧生成，既保证了局部精度又维护了全局连贯性，这是一种简洁而有效的设计。但也应注意到，该方法本质上是一个基于 LLM 微调的"文本到参数"映射，对于超出训练分布的复杂面部动态可能存在泛化瓶颈。
