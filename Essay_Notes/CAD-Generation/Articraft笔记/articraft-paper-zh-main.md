# 第 1 部分：摘要至 3.3

## Articraft：用于可扩展可动 3D 资产生成的智能体系统

**图 1：**我们提出 Articraft——一个用于可扩展生成可动 3D 资产的智能体系统。借助 Articraft，我们构建了 Articraft-10K：一个包含超过 1 万个可动 3D 资产的大规模数据集，覆盖广泛的日常物体类别。

## 摘要

学习理解可动 3D 物体的一个瓶颈，是缺少规模大且多样的数据集。本文提出利用大语言模型（LLM）填补这一缺口，并以大规模方式生成可动资产。我们将生成一个可动 3D 资产的问题，化约为编写一个能够构建该资产的程序的问题。随后，我们提出新的智能体系统 Articraft，使其能够自动编写这类程序。

我们设计了一个程序化接口和一个 harness，以帮助 LLM 有效完成这一任务。LLM 面向一个领域专用 SDK 编写代码，用于定义部件、组合几何体、指定关节，以及编写测试以验证生成的资产。harness 向 LLM 暴露受限的工作区和接口，验证最终资产，并返回结构化反馈。这样，LLM 就不必被诸如编写 URDF 文件或管理复杂软件环境等细节分散注意力。

我们表明，该方法生成的资产质量高于当前最先进的可动资产生成器和通用编码智能体。借助 Articraft，我们构建了经过筛选的 Articraft-10K 数据集，其中包含超过 1 万个、覆盖 245 个类别的可动资产；并展示了它在训练可动资产模型，以及机器人仿真、虚拟现实等下游应用中的价值。

## 1　引言

橱柜、钳子、台灯、婴儿车、折叠椅和工业工具等可动物体在现实世界中无处不在，因此对 3D 内容创作、游戏、物理设计和机器人学等应用都很重要。由于它们的功能既取决于部件运动，也取决于几何形状，仅建模形状是不够的：一个有用的表示还必须刻画部件层级、关节和运动范围。

该领域的一个核心障碍是数据。现有可动资产数据集规模较小、覆盖面有限，而且质量不均衡 [30, 55, 51, 31, 11, 50]。尤其是，许多在实际应用中很重要的物体类别代表不足。因此，基于学习的方法会对已有数据过拟合，无法泛化到新类别 [22]。

弥补这一缺口的一种方法是合成生成可动资产。这本身很困难，但近期的智能体系统提供了一条可行路径。Claude Code [1] 和 Codex [38] 等工具能在很少人工监督的情况下规划、编写、调试并迭代改进软件。我们假设，这些进展能够迁移到 3D 生成中，因为可动物体与程序一样，都具有递归式、组合式结构。设计一个物体包含一系列决策：将物体分解为部件，决定部件如何连接，指定关节和运动限位，实例化几何体，验证行为，并在失败后修订。这一工作流比起一次性生成，更像智能体式编程。

为验证这一假设，我们提出 Articraft：一个通过生成代码来大规模构建可动 3D 物体的智能体。Articraft 的设计遵循三项原则：

- **自动化：**给定物体描述，无需人工干预即可生成可动资产。
- **轻量化：**为保持较低的单资产推理成本并使大规模数据生成可行，它避免使用 Blender 等重量级外部图形软件以及基于图像的反馈。
- **表达力：**它覆盖广泛的可动物体类别，包括复杂机械结构。

我们的关键技术创新是智能体的设计，它由两个组成部分构成：一个智能体 harness，以及一个对 LLM 友好的软件开发工具包（SDK）。二者共同使现成的大语言模型（LLM）无需重新训练，就能生成可动 3D 资产；该方法利用了 LLM 的编码能力，以及其关于日常物体结构和运动方式的先验知识。这种设计使我们的方法区别于先前基于 LLM 的可动资产生成方法 [57, 13, 20]。

SDK 使 LLM 更容易理解如何生成资产。LLM 被要求针对该 SDK 编写一个单独的程序；程序一旦执行，便会产生完整的可动资产。该 SDK 聚焦、富有表达力且对 LLM 友好：它覆盖广泛的可动物体类别，同时又足够接近熟悉的编码模式，从而保持生成的可靠性。它同时暴露低层原语（例如添加圆柱体）和高层抽象（例如添加铰链），使程序保持紧凑、可读；它还允许 LLM 编写并执行面向特定物体的验证代码，以测试结构完整性。

harness 将 LLM 变成迭代式智能体，而不是单次生成器。它提供最小化的工作区和接口：编辑一个程序、执行它，并接收或请求关于生成 3D 资产的反馈。其设计中包含了有意的取舍：向模型暴露多少上下文、如何组织这些上下文、如何验证生成资产，以及何时停止迭代。聚焦的 SDK 和最小化 harness 共同降低每个资产的推理成本，这正是大规模生成得以实现的原因。

这种设计能够在多种类别中生成逼真的可动物体。它优于该领域的既有工作，也优于 Codex [39]、Claude Code [1] 等通用编码智能体。它还显著更轻量，避免了既有方法通常依赖的 Blender 等重量级外部图形软件。我们使用 Articraft 构建了经过筛选的 Articraft-10K，其中含有超过 1 万个、跨越 245 个类别的可动物体。作为一项应用，我们重新训练了用于估计 3D 物体可动结构的模型 Particulate [22]，获得了显著性能提升；我们还展示了机器人仿真和虚拟现实中的应用。

我们将公开发布 Articraft-10K，以及所有资产的代码表示、智能体的推理轨迹和智能体环境本身；该环境可与不同的 LLM 后端配合使用。

## 2　相关工作

### 生成可动物体

近来的工作已经开始直接生成可动 3D 资产。NAP [21] 和 CAGE [28] 提出了可通过去噪扩散 [46] 生成的、针对可动物体定制的表示。ArtFormer [47] 和 MeshArt [9] 则使用基于 token 的表示和自回归生成 Transformer 来完成这一任务。

URDFormer [6]、URDF-Anything [24] 和 URDF-Anything+ [54] 学习将图像映射为 URDF 代理表示；其中后者建立在 AutoPartGen [5] 之上，按一次一个部件的方式顺序提取 URDF 物体。Real2Code [60] 首先从图像重建 3D 结构并进行部件分割，随后使用基于 LLM 的代码生成来推断关节参数。SINGAPO [29] 从单张图像生成可动物体的部件。PhysX-3D [3] 扩展了结构化 3D latent [56]，使其除 3D 形状外还能生成物理属性；PhysX-Anything [4] 则从单张图像预测可用于仿真的几何、关节和物理属性。

与我们的方法更相近的是 Articulate-Anything [20]：它使用视觉语言模型（VLM）智能体生成 Python 代码，以从文本、图像或视频构建带关节的 URDF 资产。然而，该方法依赖从既有 3D 资产库中检索部件网格，这限制了类别多样性。更近的一项工作 ArtiCAD [45] 使用多智能体流水线生成可动 CAD 装配体，但其审查阶段依赖多视图渲染图像和关节运动关键帧提供的视觉反馈。相比之下，Articraft 完全基于代码，避免图像反馈，从而保持大规模生成的轻量性。

### 程序化与智能体式 3D 设计

一些先前工作通过控制 CAD 软件来生成 3D 物体。ShapeAssembly [16] 引入 SDK，以简化与 CAD 软件的交互，并使用一个定制代码生成器来调用它。ShapeMOD [17] 进一步在这一空间中发现可复用的程序化原语。DeepCAD [53] 和 Text2CAD [19] 使用自回归 Transformer 生成经过适当编码的 CAD 命令。Text-to-CadQuery [57] 和 CAD-Coder [13] 则面向 CadQuery API 编写 Python 代码。我们的智能体面向这些 API 的超集，并生成可动、可用于仿真的资产，而非静态资产。

我们的方法也与交错进行推理、行动、工具使用和反馈的语言智能体有关，尤其包括 ReAct [59]、Reflexion [44]、SWE-agent [58]，以及 PAL [10]、Code as Policies [25] 等“代码即行动”方法。SWE-agent 特别表明：当 LLM 使用为任务专门设计、并以良好结构提供反馈的软件接口时，会从中受益。我们遵循同一原则，其中包括提供一个领域专用 SDK，供智能体用来编写程序。

### 可动资产与仿真数据集

PartNet-Mobility [55] 可能是迄今使用最广泛的、基于合成资产的可动物体数据集。AKB-48 [31] 则从真实物体扫描开始；GAPartNet [11] 为 PartNet 扩充了按部件标注的可供性信息。作为 GRUtopia [50] 一部分提出的 GRScenes，生成的是完整场景而非单个物体。RoboCasa365 [34] 为机器人学提供模拟环境，其中有一百多个物体类别，但其中只有十余类是可动的。Infinigen-Sim [18] 延续 Infinigen [43] 的工作，手工定义程序化生成器来生成可动 3D 资产而非场景。PhysX-3D [3] 引入 PhysXNet：一个半自动创建的可动 3D 物体集合。

我们使用新的智能体创建 Articraft-10K——一个经过筛选的、大规模可动资产集合；相较这些先前工作，它具有显著更广的类别覆盖范围（表 1）。

## 3　Articraft

**图 2：**Articraft 概览。智能体在受限工作区中运行，其中只有一个可写的 `model.py`，以及只读的 SDK 文档、经过筛选的示例和一个小型动作空间。在每次迭代中，LLM 编辑程序，通过 harness 编译或探测当前资产，并使用返回的验证信号和反馈来进行下一次修订。详见第 3 节。

我们提出 Articraft：一个编写程序来构建可动 3D 资产的智能体。给定自然语言描述 $x$，以及可选的物体参考图像，Articraft 会编写 Python 程序 $y$；该程序执行后输出一个可动 3D 资产 $a$。该资产由一个 URDF¹ 构成，其中包含 3D 网格、语义部件，以及带有轴和运动范围的可动关节。

Articraft 以迭代方式构建 3D 资产，遵循语言智能体的“推理—行动—观察”模式 [59, 44, 49]。该智能体是一个具备编码能力的现成 LLM $E$。LLM 会获得系统提示词 $p$（见附录 C），其中规定了物体生成任务，以及解决该任务时必须使用的程序化接口和 harness。一个 harness 向 LLM 暴露工作区和接口，以操纵该程序。

工作区维护的状态包括当前程序 $y_t$、当前资产 $a_t$，以及过去修订的历史 $h_t$。LLM $E(p,x,h_t)$ 接收系统提示词 $p$、用户提示词 $x$ 和当前历史 $h_t$，并输出一个或多个供 harness 执行的命令。这些命令通过编辑程序、将其编译成新资产，或探测资产以获得反馈，来作用于当前状态 $(y_t,a_t)$。因此，harness $C$ 输出新状态 $(y_{t+1},a_{t+1})$ 以及反馈 $s_{t+1}$，并将它们追加到下一轮迭代的历史中：

$$
(y_{t+1},a_{t+1},s_{t+1})
=
C(E(p,x,h_t),y_t,a_t),
\qquad
h_{t+1}
=
h_t\cup\{(y_{t+1},a_{t+1},s_{t+1})\}.
$$

当 LLM 不再发出编辑命令、且验证标准已经满足时，该过程终止。最后一个版本的资产 $a_T$ 被接纳为最终输出。

Articraft 的关键创新，是为 LLM 后端提供一个专门面向可动 3D 设计的程序化接口（第 3.1 节）和 harness（第 3.2 节；图 2）。这遵循了一项原则：智能体—计算机接口应当是任务专用的，而非通用的 [58]；这显著提升了后端的效力——后端原本只是通用、现成的编码模型。借此，Articraft 不需要使用先前工作 [20] 所采用的视觉反馈，因为这类反馈生成和使用的成本都很高。相反，harness 和程序化接口提供专门工具，以直接、高效地编写并检查物体几何。

¹**URDF（Unified Robot Description Format，统一机器人描述格式）**：一种常用 XML 格式，用于表示可动 3D 资产。

## 3.1　Articraft 的程序化接口

Articraft 生成的每个 3D 资产 $a$，均由一个程序 $y$ 定义；该程序只包含一个 Python 文件 `model.py`（见图 3 示例）。此文件暴露两个入口点：

- `build_object_model()`：构建可动物体；
- `run_tests()`：记录针对提示词的几何检查，以及明确决定放宽其中某些检查的情况。

随后，该文件将构造出的物体绑定到 Python 变量 `object_model`，harness 可借此提取生成的资产。一个隐式约定将物体创作与系统执行细节分开，例如文件管理、URDF 导出和验证。智能体只需针对下述 SDK 编写代码，指定物体部件、其几何和关节，以及应满足哪些物体专属测试；其余工作由 harness 处理。这样，模型可编辑的目标既富有表达力，又足够小。

### 定义几何与部件

程序 `model.py` 使用 SDK 构建物体。在顶层，程序创建一个 `ArticulatedObject`，并用具名 `Part` 填充它们；这些部件为资产提供语义骨架。部件可通过关节连接，也可作为测试和几何探测的具名目标。

SDK 还包含多种定义部件几何的工具：既有方盒、圆柱和球体等低层原语的生成工具，也有调用类 CAD 工具的能力（暴露 CadQuery [7]），以及能输出支撑结构、面板、铰链、轮子、格栅和扫掠轮廓等复杂结构的高层程序化生成器。这些工具可组合、与类别无关，能够创建广泛的物体类型和形状。通过同时提供低层和高层原语，智能体能编写更简洁、token 效率更高且更可能正确的程序，同时仍保留对几何的细粒度控制。

SDK 还包含一个工具，用于查找与自然语言描述匹配的代码片段示例；智能体可用它从经过筛选的示例库中检索相关代码模式。

### 定义关节

每个 `ArticulatedObject` 在其具名 `Part` 之间保存可动关节。SDK 支持转动（revolute）、移动（prismatic）、连续（continuous）和固定（fixed）关节，并显式指定原点、轴和运动限位。这些关节以 `Articulation` 对象表示，记录父部件、子部件、关节类型、原点、轴和运动限位。

这种表示将每个可动关节与部件及其几何关联起来，使智能体在迭代设计时能一起修订它们。例如，一个抽屉既需要轨道位于正确位置，也需要一个与轨道对齐的移动关节。编译得到的 URDF 保留这种运动学结构，因此输出不仅是视觉几何，也是一种描述部件如何运动的结构化表示。它因此可被机器人仿真器、交互式查看器和下游学习流水线消费。

### 自验证

如下文所述，harness 会自动执行多项默认检查来验证生成资产 $a$，并将反馈返回给智能体。这些检查包括检测程序执行时的运行时错误、断开的部件以及彼此重叠的部件。

不过，生成资产的完整性通常取决于细微且对象专属的关系：抽屉应始终嵌在轨道中；带铰链的盖子应在运动过程中避开底座；旋钮的柄部应始终插在其插座中。因此，`model.py` 包含入口点 `run_tests()`，智能体可利用它测试这些对象专属性质；harness 会在完成自身检查后执行它。

系统提示词和筛选示例会告诉智能体如何完成这一点：实例化 `TestContext(object_model)`，解析具名部件或可视元素，调用断言辅助函数或豁免辅助函数，并返回 `ctx.report()`。断言辅助函数可以表达接触、间隙、重叠、包含关系，以及部件之间依赖姿态的关系等几何约束。例如，`expect_contact(...)` 可用于检查铰链的一片是否接触橱柜框架；`expect_within(...)` 可用于检查抽屉是否仍与轨道保持接合。

`allow_overlap(...)` 和 `allow_isolated_part(...)` 等豁免调用，会指示 harness 有意忽略其自身的一些自动检查；例如，容忍局部设计取舍，或容忍一个有意独立放置的部件。

## 3.2　Articraft Harness

**表 2：**Articraft 使用的受限动作空间。该接口只暴露直接支持可动物体创作和修复的操作。

| 操作族 | 工具名 | 是否编辑？ | 用途 |
|---|---|:---:|---|
| 读取 | `read_file` | × | 读取 `model.py` 和 SDK 参考资料的精确文本。 |
| 编辑 | `apply_patch`、`replace`、`write_file` | ✓ | 对绑定的物体程序应用局部编辑或受控替换。 |

harness 为智能体提供受限的工作区和接口，以操纵程序。

### 受限工作区

不同于通用编码智能体，Articraft 智能体并不直接操作复杂代码库。相反，harness 向智能体呈现一个工作区：其中只有一个可写产物 `model.py`，以及对 SDK 文档和筛选示例的只读访问，如图 2 所示。

### 受限动作空间

同样不同于通用编码智能体，Articraft 智能体不能执行任意 shell 命令、浏览复杂代码仓库，或重构多个文件。harness 去除了这些与任务无关的自由度，只提供少量命令：读取 SDK 文档、修补或替换程序文本、检索代码示例、编译程序，以及运行只读几何探测，如表 2 所概述。

此外，每个非编辑工具都会返回由 harness 传回智能体的反馈。动作空间的简洁性使 Articraft harness 对非最前沿 LLM 也更加友好，从而支持廉价、可扩展的合成数据生成。

### 执行反馈

harness 执行智能体命令时，会提供包括资产质量在内的执行反馈。这些反馈并非原始日志，而是被组织为失败（failure）、警告（warning）和备注（note）信号：

- **失败信号**包括程序执行错误和未通过的验证测试，其中既包括智能体编写的测试，也包括 harness 定义的默认测试；
- **警告**报告非致命的几何、结构或代码质量问题；
- **备注**记录上下文，例如 LLM 发出的豁免声明。

当智能体认为反馈不足时，可以调用 `probe_model`。这是一个只读工具，它检查当前 `object_model` 并返回多种测量结果。智能体可用这些结果调整部件间的距离、重叠、包含关系或姿态等属性。

### 轨迹与元数据记录

harness 运行时会存储可审计的运行记录，包括：输入提示词、对话消息、工具调用、编译和探测反馈、最终 `model.py`、提供商和模型标识符、轮数与成本统计、输出资产路径，以及提示词和生成程序的哈希值。

数据集记录还可以存储人工策展者评分；这些评分用于数据集筛选和分析，而非生成阶段的反馈。

## 3.3　图像条件生成

当提供参考图像时，它被视为几何、比例、关节和材料的首要真实依据，会覆盖类别层面的通用物体先验。该图像在“编辑—执行—修复”循环的全过程中持续保留，使每次迭代都能重新以相同的视觉证据为基础，避免结果漂移到类别默认形态。

一旦智能体生成了具有近似颜色材料的 URDF，我们还可使用 LiteReality [14] 提出的方法，进一步细化资产的基于物理渲染（PBR）材料。最终输出是一个具有完整 PBR 材料的、完全可动的物体，它与参考图像中的物体高度相似，如图 8 所示。
