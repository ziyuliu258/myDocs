# Articulate-Anything 阅读笔记

> 论文：*Articulate-Anything: Automatic Modeling of Articulated Objects via a Vision-Language Foundation Model*
> 作者：Long Le 等
> 会议：ICLR 2025
> 原文：[Essay/3DAssets/Articulate-anything.pdf](../../Essay/3DAssets/Articulate-anything.pdf)
> 阅读范围：正文与附录 A；下文将论文直接报告的结论与“阅读解读”分开。

## 一、一句话摘要

这篇论文把“给物体补上可交互的运动学结构”重写为一个**多模态程序合成 + 仿真视觉反馈**问题：给定文本、图像或视频，VLM 不直接输出冗长的 URDF/XML，而是编写高层 Python 代码；代码经 API 编译为 URDF，并在“检索网格 → 放置部件 → 预测关节”的流水线中由视觉 critic 反复检查和修复。它在 PartNet-Mobility 全类别的关节预测成功率达到 **75.0%**；图 5 中三个基线的对应数值为 **14.6% / 8.7% / 12.2%**。

这里的 actor–critic **不是强化学习中共同训练的 actor/critic 网络**，而是多个通过提示词分工的 VLM agent：actor 提议或改写代码，critic 将输入视觉证据与仿真渲染/运动结果比较后给出自然语言反馈和评分。

## 二、问题、表示与动机

### 2.1 要解决什么

静态 3D 资产很多，但可用于仿真和机器人交互的带关节资产很少，因为人工制作 mesh、部件层级、关节轴、原点和限位都很耗时。本文的目标并非只让物体“看起来像”，而是生成一个能在标准仿真器中运动和交互的 **URDF 数字孪生**。

URDF 将物体表示为一棵树：

- **link**：部件及其网格，例如柜体、抽屉、门；
- **joint**：部件间的运动约束。重点处理平移关节（`prismatic`，如抽屉）和转动关节（`revolute`，如柜门）。

论文将目标形式化为：

$$
L_{\text{total}} = L_{\text{mesh}} + L_{\text{link}} + L_{\text{joint}}.
$$

其中三项分别衡量网格外观、link 的位置/姿态，以及 joint 的类型、轴、原点和运动范围。真实物体通常没有可直接优化的 GT URDF，且三项耦合很强，因此作者不做端到端数值优化，而是依次处理三项：**先取得可用网格mesh，再摆放 link，最后推断 joint**。

### 2.2 关键视角：把运动学建模变成代码编辑

直接让 VLM 写 URDF/XML 有两个问题：文件冗长，且局部坐标系、前向运动学和关节原点计算容易出错。作者提供了一个高层 Python API，让模型通过“相对放置部件”“创建转动/平移关节”等语义操作写程序；碰撞检查、坐标计算和 URDF 导出交给 API/物理引擎。

这使 VLM 的编辑对象从大量低层数字，变成更容易推理的关系，例如“门在柜体前方，铰链在门的左侧边缘”。这是本文很重要但容易被结果数字掩盖的系统设计。

## 三、方法：三个阶段、一个闭环

```text
文本 / 图像 / 视频
        ↓
Mesh Retrieval（得到可用部件网格）
        ↓
Link actor 写摆放代码 → 物理检查与渲染 → Link critic 反馈 → 改写
        ↓
Joint actor 补关节代码 → 仿真运动视频 → Joint critic 反馈 → 改写
        ↓
可交互 URDF 资产
```

主实验中的专职 agent 使用 Gemini Flash-1.5，并采用最多约 20 个 in-context examples；系统本身没有为该任务训练新的端到端预测网络。

### 3.1 Mesh Retrieval：先保证几何质量

| 输入 | 处理方式 |
|---|---|
| 图像 / 视频 | VLM 定位目标（视频还能利用运动线索）；CLIP 先召回最相近的 top-k 类别；`Hierarchical ObjectSelector` 再在一批批候选渲染结果中做淘汰赛式选择。 |
| 文本 | `TaskSpecifier` 将稀疏提示补全；`LayoutPlanner` 产出各部件的名称、描述与尺寸；再用 CLIP 文本嵌入匹配作者为 PartNet-Mobility mesh 预先生成的文字描述，并将 mesh 缩放到规划尺寸。 |

这一步是明确的工程取舍：论文优先从已有 3D 资产库检索高质量网格，而非从零重建形状。因而它特别适合“把已有外观正确地变成可动物体”，不等价于无限制的 text-to-3D 生成。

### 3.2 Link Placement：利用图像校正空间关系

link actor 根据部件名称、已有代码和可选图像写出摆放代码。API 通过对齐部件中心、指定相对方位并做碰撞检查，实现贴合但不相交的组合；视频在此阶段只使用第一帧。

有视觉输入时，link critic 会同时读取：原始图像、预测资产的仿真渲染和 actor 源码。它输出视觉差异、可能出错的代码位置，以及 0–10 的 `realism_rating`（作为 $L_{\text{link}}$ 的视觉代理）；评分不超过 5 时，actor 根据反馈重写代码，超过阈值即停止。

### 3.3 Joint Prediction：用视频消除“看起来都合理”的多解性

joint actor 在已经放置好的 Python 程序上增加关节定义。对视频输入，joint critic 将真实视频与“预测关节在仿真中运动”的视频比较，并按严重程度诊断：

1. 关节类型错误；
2. 关节轴错误；
3. 关节原点错误；
4. 运动限位或方向错误。

同样地，评分不超过 5 就让 actor 继续改写。视频的价值不只是多一帧视觉信息，而是直接消除静态输入的运动歧义：同样外形的窗可能上滑或向外翻；椅子的立柱可能旋转也可能上下调节。文本或单图中的常识猜测未必能判定真实可供性。

### 3.4 Targeted Affordance Extraction（可选）

若只关心视频里实际发生的一个动作，系统可先根据视频和按部件着色的资产图像，选出对应的 child link，只标注该目标关节。论文将其定位为降低 token 成本、减少待调试关节数的可选步骤。

## 四、核心贡献到底是什么

1. **多模态输入的自动关节化。** 文本给出意图，图像给出外观和布局，视频给出运动证据；三者并非可互换，视频尤其解决关节类型和方向的歧义。
2. **高层程序表示。** 把 XML、坐标变换和碰撞处理封装在 API 后，VLM 面对的是较短、可读、可局部修订的 Python 程序。
3. **视觉闭环而非一次性预测。** 渲染/仿真把当前程序的后果暴露给 critic，critic 再把失败归因到可编辑的代码；这比直接回归一组关节参数更可解释。
4. **全类别评测与真实机器人示例。** 不只在少数熟悉类别上比较，也评估 PartNet-Mobility 的 46 个类别，并展示仿真训练到真实 Franka 的流程。

## 五、实验：证据、指标与应如何解读

### 5.1 设置

- 数据集：PartNet-Mobility，约 **2.3K** 个人工标注物体、约 **1.9K** 个转动关节、约 **7.6K** 个平移关节。
- 协议：遮蔽 GT URDF 中的 link/joint 信息，再重建它。对比 URDFormer 和 Real2Code；两者训练/微调过 5 个类别，论文同时报告这 5 个 ID 类和其余 41 个 OOD 类。
- 成功判定：link 的位置和姿态都须达标；joint 的类型、轴、原点、限位都须达标。位置阈值为 **50 mm**，角度阈值为 **0.25 rad**（约 14.3°）。若 link 放置失败，该物体的所有 joint 都记为失败。
- 实现：PyBullet 做物理计算，Sapien 渲染；视频轨迹展示使用 CoTracker。

### 5.2 主要定量结果

| 结论 | 结果 | 含义 |
|---|---:|---|
| 全类别 joint prediction 成功率 | **75.0%** | URDFormer Oracle / DINO / Real2Code Oracle 分别为 **14.6% / 8.7% / 12.2%**；主结果是多项系统设计共同作用的结果。 |
| link placement：文本 → 图像 | **68.6% → 88.6%** | 物体布局不能只依赖类别常识；视觉证据很关键。 |
| joint prediction：文本 / 图像 / 视频 | **48.9% / 54.4% / 77.7%** | 运动信息对判定真实关节最有价值。 |
| critic 迭代收益 | link 约 **+5.8%**；joint 约 **+2.4%** | 闭环修复有效，但提升并非无限大。 |

同模态补充实验也支持高层程序表示本身有价值：在对应基线的 seen 类别上，文本条件的本文方法为 **40.3%**，Real2Code Oracle 为 **13.5%**；图像条件的本文方法为 **48.5%**，URDFormer Oracle / DINO 为 **24.7% / 20.2%**。不过这只是受限类别上的消融，不能单独解释主表中的全部差距。

附录中，本文的关节类型错误率、轴误差和原点误差也均优于两个基线。在 PartNet-Mobility 的检索式 mesh 评估中（作者明确移除了被测对象本身），其 Chamfer distance 为 $0.1007 \pm 0.062$，低于 Real2Code Oracle 的 $0.229 \pm 0.166$ 和 URDFormer 的约 $0.43$；接入生成式 mesh 模型时，论文还展示了更好的外观重建结果。

### 5.3 机器人应用

作者从真实视频生成可动物体，在 Robosuite 中用 PPO 训练 Franka 做 4 个细粒度操作任务，再部署到真实机械臂。生成资产与人工标注资产所训练的策略都达到 **100%** 任务成功；相较人工通过 RialTo GUI 标注，自动方法平均每个任务节省 **40.58 分钟**。

附录的训练细节包括：每任务 3 个随机种子、200 万环境步，并随机化摩擦、阻尼、物体尺度和位姿。这一部分证明了资产可以进入真实的 sim-to-real 工作流；它不意味着对任意物体、任意接触动力学都已具备工程级精度。

## 六、局限、风险与可继续做的方向

### 6.1 论文明确承认的边界

- **依赖 mesh retrieval。** 库中没有足够相似的部件时，几何、类别和内部结构都会受限；作者将上游基础 mesh reconstruction/generation 模型视为下一步。
- **小部件和非常规运动更难。** 分类别结果中，关节成功率的波动很大；例如 FoldingChair、Clock、Globe、Pliers、Fan、Scissors 都为 0，复杂或细小的结构仍是主要失败来源。
- **critic 会把错误判为正确。** 附录中 joint critic 的假阳性占全部样本 **4.57%**；“视觉上似乎合理”不能保证轴、原点和限位在数值与物理意义上都正确。

### 6.2 阅读解读：需要谨慎外推的地方

1. **这是检索 + 装配任务，不是纯粹的新资产生成。** 附录仅在 mesh 评估中明确说明移除了被测精确对象；主 articulation 评测的候选池协议没有同样明确写出。无论如何，候选来自 PartNet-Mobility 的同一资产生态，因此结果强力证明了“选择、摆放、关节化”的能力，却不能直接等同于对长尾新外形的完整重建能力。
2. **比较不完全是同输入条件。** 主结果中，本文可利用视频和闭环反馈，而基线的输入形式更受限。论文在附录给出了同模态对比，仍保持优势；但阅读主表时仍应将“基础模型/高层代码/视频输入/闭环”看成一个联合系统贡献，而非单一模块带来的全部增益。另一个可复现性因素是 Real2Code 的 LLM checkpoint 和训练代码未发布，作者在附录中自行复现了其流水线。
3. **视觉自评可能产生自证循环。** actor 与 critic 都由 VLM 驱动，若二者共享相似的类别先验，就可能把“看起来像常见物体”的错误方案接受为真。可引入独立的几何/运动学验证器、连续碰撞检测、任务级仿真测试或人工高风险复核。
4. **部署成本和稳定性值得单独报告。** 该方法需要检索、多个 VLM 调用、渲染和多轮代码重写；论文重点展示质量，实际大规模使用时还应测量每物体的 token、延迟、迭代次数与随机性。

## 七、与 Articraft 的关系

目录中的 [Articraft 阅读总结](../Articraft笔记/阅读总结articraft-reading-notes.md) 很适合与本文并读：两者都把可动物体表示为程序/URDF，并把生成从一次性预测变成迭代式 agent 工作流。

| 维度 | Articulate-Anything | Articraft |
|---|---|---|
| 主要目标 | 从文本、图像、视频为真实/已有物体补运动学 | 以程序化几何大规模生成可动物体资产 |
| 几何来源 | 以资产库 mesh retrieval 为主，可选接入 mesh generation | SDK / 参数化 CAD 构建几何 |
| 主要反馈 | 输入与仿真渲染/运动视频的视觉 critic | 编译、几何探测、QC 与对象专属测试 |
| 强项 | 视频能消除真实动作歧义；重用资产的外观质量高 | 可生成更多类别、过程可审计，且不依赖渲染视觉反馈做主 QC |
| 典型短板 | 受检索库覆盖限制，视觉 critic 可能漏检参数错误 | 受 SDK 表达能力和测试覆盖率限制 |

阅读解读：两篇论文体现的是同一方向的两种取舍。Articulate-Anything 选择“让 VLM 看输入和渲染图来修复”，因此更擅长根据视频复原已观察到的可供性；Articraft 选择“把正确性尽可能写成可执行约束”，因而更适合大规模、可审计的程序化资产生产。一个有前景的组合是：用视频/多视图决定关节语义，再用独立的几何与物理测试验证其全运动范围。

## 八、总体判断

我认为本文最值得记住的不是“VLM 给 URDF 打了更高分”，而是下面这条系统设计原则：

> 当任务同时要求外观、部件语义、空间布局与运动学时，应该让模型生成一个**可执行、可渲染、可反馈的中间程序**，而不是要求它一次性猜对所有连续参数。

这种表示把模糊的视觉理解转化为可编辑的关系代码，再利用仿真将错误显性化。其目前最适合有相似资产可检索、可由视频提供动作证据的物体数字孪生；要成为更通用、工程可靠的资产生成工具，还需要突破网格库覆盖、独立验证、全姿态物理正确性和运行成本四个方面。
