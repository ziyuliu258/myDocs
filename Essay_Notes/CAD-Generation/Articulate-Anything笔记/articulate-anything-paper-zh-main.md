## Articulate-Anything：通过视觉—语言基础模型自动建模可动物体

> 作者：Long Le、Jason Xie、William Liang、Hung-Ju Wang、Yue Yang、Yecheng Jason Ma、Kyle Vedder、Arjun Krishna、Dinesh Jayaraman、Eric Eaton
> 机构：University of Pennsylvania（宾夕法尼亚大学）
> 项目主页：https://articulate-anything.github.io/
> 预印本标识：arXiv:2410.13882v4 [cs.CV]，2025 年 6 月 2 日；本文以 ICLR 2025 会议论文形式发表。

## 摘要

可在仿真中交互的 3D 物体对于 AR/VR、动画和机器人学至关重要；它们推动沉浸式体验与高级自动化。然而，创建这类可动物体需要大量人工投入和专业知识，从而限制了其更广泛的应用。为克服这一挑战，我们提出 **Articulate-Anything**：一个可从多种输入模态（包括文本、图像和视频）自动完成多样、复杂物体关节化建模的系统。Articulate-Anything 利用视觉—语言模型（VLM）生成代码；这些代码可被编译为可在标准 3D 模拟器中使用、可交互的数字孪生体。

我们的系统通过网格检索机制利用既有 3D 资产数据集，并采用一个动作器—批评器（actor-critic）系统，迭代地提出、评估并改进物体关节化方案；它能自我纠正错误，从而获得稳健结果。定性评估显示，Articulate-Anything 能够借助信息丰富、具有具体依据的输入，为复杂、甚至可供性存在歧义的物体完成关节化。在标准 PartNet-Mobility 数据集上的大规模定量实验中，Articulate-Anything 显著优于先前工作：成功率从 8.7–12.2% 提升至 75%，建立了新的最先进性能标杆。我们还展示了该系统的实用性：从真实环境视频输入生成 3D 资产，并用这些资产训练机器人策略，使其能在仿真中完成超越基本抓取与放置的精细操作任务；随后再将这些策略迁移至真实机器人系统。

**图 1：**给定文本、图像，或展示物体运动的视频，Articulate-Anything 会自动生成其可交互的 3D 数字孪生体，能够处理种类广泛的物体及其可供性。除其他应用外，这些可动物体资产还可用于在 Sim2Real 中训练机器人操作策略。完整视频演示和源代码见项目网站。

图中的流程意为：来自真实环境的物体可由文本（例：“三抽屉文件柜”）、图像或视频描述；系统对其完成关节化；得到的资产可用于 Sim2Real 机器人学习。

## 1　引言

在探索通用能力机器人的过程中，最有前景的路径之一，是扩大机器人在仿真中的训练规模，并将其部署到真实世界。我们已经开发出快速、准确的模拟器，它们可扩展到每秒数百万帧以及数百块 GPU（Xiang et al., 2020；Makoviychuk et al., 2021），从而支持极大规模的策略学习。然而，这一研究方向仍存在一个关键瓶颈：为了构建供这些智能体学习的真实、可交互环境，需要投入大量人工劳动。尽管已有庞大的开放静态物体几何库——最大的开放数据集含有超过一千万个物体（Deitke et al., 2024）——开放的可动物体 3D 库却小得多（仅约 2,300 个物体（Xiang et al., 2020））。这种稀缺源于人工标注过程耗时、劳动密集且需要专业知识。

为解决这一挑战，我们提出 Articulate-Anything：一种新颖的自动关节化方法。它利用领先的基础视觉—语言模型（VLM）的能力，通过迭代反馈为任意复杂度的多样物体完成关节化（图 1）。相较既有工作（Chen et al., 2024；Mandi et al., 2024），Articulate-Anything 在质量、准确性（从 8.7–12.2% 升至 75%）和泛化性方面实现了阶跃式提升，并克服了先前方法只能成功处理狭窄物体类别范围和少数关节类型的局限。不同于先前工作受限于信息贫乏的包围盒或静态图像输入，Articulate-Anything 可以接收来自文本、图像乃至视频的丰富、具有具体依据的输入；因此，用户既能要求不常见的关节化描述，也能消解关节化歧义。例如，图 7 右栏展示了一个窗户的数字模型：它合理地既可能滑动打开，也可能倾转打开；当向 Articulate-Anything 展示真实环境中的视频演示时，系统能够准确生成所需的滑动运动。

为实现这种灵活性和准确性，Articulate-Anything 使用了包含两个核心组成部分的动作器—批评器系统：（1）一个视觉—语言动作器，综合生成高层 Python 代码；这些代码可被编译为统一机器人描述格式（URDF）文件；（2）一个视觉—语言批评器，针对渲染出的预测结果与可获得的真值之间的比较提供反馈。由此得到的是一个智能体式系统：它能自动自评估，并迭代地改进复杂物体的关节化。除机器人学外，Articulate-Anything 输入的灵活性与输出的高质量相结合，使自动生成丰富、高质量、多样化虚拟环境成为可能，并可广泛应用于 3D/VR（Kim et al., 2024）、人机交互（Jiang et al., 2023）和动画（Yang et al., 2022）。

我们的主要贡献如下：

1. **Articulate-Anything：**我们提出一个视觉—语言动作器—批评器系统，可从包括文本、图像和视频在内的多种输入模态中，准确地为物体完成关节化。
2. **将关节化视为程序综合：**我们开发了一个可编译为 URDF 的高层 Python API，使 VLM 动作器能够生成紧凑、易于调试的程序。
3. **基于视觉的输入实现闭环迭代改进（Visually grounded inputs enable closed-loop iterative refinement）：**我们强调具有具体视觉依据的输入在为有歧义和复杂物体完成关节化时的关键作用，并在一个闭环系统中利用这类输入，使系统能自评估、自改进其关节化结果。
4. **大规模评估展示出色性能：**先前自动关节化工作仅在少数物体类别上评估。对完整 PartNet-Mobility 数据集的定量分析表明，我们的方法相较现有方法有显著提升：成功率由先前工作的 8.7–12.2% 提高到 75%。

## 2　相关工作

### 3D 资产数据集

大型开放 3D 物体数据集，例如 3D Warehouse 和 Objaverse（Deitke et al., 2024），提供了由独立艺术家上传的大量 3D 模型集合。然而，这些库中的大多数物体并不具有可动关节。ShapeNet（Chang et al., 2015）和 PartNet（Mo et al., 2018）等数据集将物体分解为部件（link），但不包含运动学关节。一些数据集，例如 PartNet-Mobility（Xiang et al., 2020）和 GAPartNet（Geng et al., 2022），确实包含具有 link 和 joint 的可动物体；但这些标注由人工创建，因此物体数量仍较有限。我们的工作旨在自动创建适合机器人任务的可动物体 3D 资产，减少对人工标注的依赖。

### 可动物体建模

可动物体建模是一个重要研究领域，涵盖感知、重建和生成等任务（Liu et al., 2024）。在感知方面，（Zeng et al., 2021；Hu et al., 2017）等工作聚焦于识别和理解可动物体。从单张 RGB 图像（Chen et al., 2024）、RGBD 图像（Weng et al., 2024）、多视图图像（Liu et al., 2023a）或点云（Jiang et al., 2022）进行重建的工作，旨在重建可动物体模型。生成方法则包括利用连接图的方法（Liu et al., 2023b）和神经方法（Lei et al., 2023）；它们聚焦于创建新的可动物体。我们的目标是开发一条端到端流水线，贯穿感知、重建和生成；它利用人类直观且易于获得的输入（如语言或视频），而不是依赖点云或图等更专门的模态。

## 3　问题表述

为保证与标准 3D 模拟器的兼容性，我们使用统一机器人描述格式（Unified Robot Description Format，URDF）表示 3D 模型。在 URDF 中，一个物体被组织为一棵层级树，其中节点是 link，边是 joint。link 表示物体的部件（例如厨房岛台的抽屉和柜门），而 joint 规定每个部件如何运动。最常见的两类 joint 是：表示平移运动的 prismatic joint（例如滑动抽屉），以及表示旋转运动的 revolute joint（例如可绕轴转动的柜门）。

给定描述某个物体的文本、图像或视频输入 $x$，我们假设存在一个真值 URDF $u^*$（例如，人类能够创建的 URDF）。关节化的目标是自动构建一个 URDF 模型 $\hat{u}$：它包含与 $u^*$ 相同的一组 link，同时通过下述损失最小化两个 URDF 模型之间的差异：

$$
L_{\mathrm{total}} = L_{\mathrm{mesh}} + L_{\mathrm{link}} + L_{\mathrm{joint}} ,
\tag{1}
$$

其中，

$$
L_{\mathrm{mesh}} = \sum_{i=1}^{N} \operatorname{Chamfer}(\hat{P}_i, P_i^*)
$$

使用点云 $\hat{P}_i$ 和 $P_i^*$ 衡量预测 link 与真值 link 在视觉外观上的差异。$N$ 是 link 的数量。$L_{\mathrm{link}}$ 刻画预测 link 与真值 link 之间的 3D 位姿差异：

$$
\begin{aligned}
L_{\mathrm{link}}
&= \sum_{i=1}^{N}
\underbrace{\lVert \hat{x}_i - x_i^* \rVert_2}_{\text{位置误差}}
+
\underbrace{2\arccos\left(\left|\hat{q}_i \cdot q_i^*\right|\right)}_{\text{朝向误差}} ,
\end{aligned}
\tag{2}
$$

其中 $x_i$ 是 3D 坐标，$q_i$ 是四元数。$L_{\mathrm{joint}}$ 量化关节差异：

$$
L_{\mathrm{joint}}
= L_{\mathrm{joint\ type}}
+ L_{\mathrm{joint\ axis}}
+ L_{\mathrm{joint\ origin}}
+ L_{\mathrm{joint\ limit}} ,
\tag{3}
$$

其中 $L_{\mathrm{joint\ type}}$ 是交叉熵损失，$L_{\mathrm{joint\ axis}}$ 是关节轴之间的角度差，$L_{\mathrm{joint\ origin}}$ 是关节原点之间的 3D 位姿差，$L_{\mathrm{joint\ limit}}$ 衡量运动范围和运动方向的差异。实际中，对这一目标进行联合优化是难以处理的。因此，我们改为依次解决每个损失，将问题分解为三个阶段：（1）**网格检索**（Mesh Retrieval），（2）**Link 放置**（Link Placement），以及（3）**关节预测**（Joint Prediction）。

此外，通常难以获得 $u^*$，使得用于计算这些损失的传统优化方法不可行。为克服这一问题，我们利用视觉—语言模型（VLM）智能体，直接根据视觉输入近似这些损失函数。并且，我们不通过常规优化器来改进方案，而是同样使用 VLM 智能体以代码的形式提出方案，并依据批评器模块的反馈迭代改进。后续各节将详细说明这一过程。

## 4　通过 Actor-Critic VLM 生成可动物体

本节介绍 Articulate-Anything：一个能够从多种输入模态生成可动物体的系统。图 2 概述了我们的方法，其中包括三个主要组成部分：（1）**网格检索**（第 4.1 节）：从 3D 资产库中检索网格，重建物体每个部件的 3D 结构；（2）**Link 放置**（第 4.2 节）：在空间中安排这些部件；以及（3）**关节预测**（第 4.3 节）：确定部件之间可能的运动学运动。此外，第 4.4 节还介绍一个可选步骤：**定向可供性提取**（targeted affordance extraction）。我们的系统由许多专门的 VLM 智能体组成。每个智能体均为 Google 的 Gemini Flash-1.5 视觉—语言模型（Team et al., 2023），并以不超过 20 个上下文内示例提示其完成不同任务。所有系统提示词和任务指令提示词均在源代码中提供。

**图 2：方法概览。**给定文本、图像或视频输入，Articulate-Anything 分三阶段运行：（1）网格检索（第 4.1 节）从 3D 资产库中为每个物体部件检索网格；（2）Link 放置（第 4.2 节）将各部件组装到一起；（3）关节预测（第 4.3 节）预测部件间允许的运动学运动。作为可选项，我们可以不生成所有可能的运动学关节，而是从输入视频中定向处理某一个特定关节（第 4.4 节）。Link 放置和关节预测系统均由动作器和批评器构成，二者都是协同工作的 VLM：动作器提出方案，批评器检查方案并给出反馈。

图中以“双悬窗、白色窗框、两块玻璃窗格”为文本输入示例。动作器使用诸如 pred_robot.add_link、pred_robot.place_relative_to 和 pred_robot.make_prismatic_joint 的 API 生成程序；批评器将预测结果与真值比较，例如指出“预测在视觉上与真值完全相同”，或识别“真值窗户沿 $z$ 轴上下滑动、预测却沿 $y$ 轴向前旋转”，并建议改用 make_prismatic_joint。

至关重要的是，我们的系统产出高层 Python 代码；通过我们开发的定制 API，这些代码可以编译为 URDF。直接生成 URDF 很有挑战，原因是：（1）URDF/XML 很冗长，增加了长上下文中产生幻觉的可能性；更重要的是，（2）在许多情形下需要就地进行复杂数学计算。举例来说，若要为一扇门设置绕全局 $z$ 轴的旋转，就需要沿 URDF 树执行正向运动学计算，以将该旋转转换到相对坐标系中。即使是看似简单的任务，例如把马桶座圈放在便盆上方，也可能因网格几何形状并不简单而变得复杂。不过，通过在物理引擎中迭代执行碰撞检测，这些问题都可以轻松解决。

### 4.1　网格检索

我们为从视觉输入（即图像或视频）和文本输入重建网格，分别采用两种机制。图 3 概述了这两个过程。

**视觉输入。**对于视觉输入，我们通过将输入与 PartNet-Mobility 数据集（Mo et al., 2018）中的一个 3D 物体进行匹配来完成网格检索。首先，指示一个 VLM 从输入中检测感兴趣的物体。由于画面中可能有多个物体，当输入为视频时，进一步指示 VLM 利用运动线索，以实现更准确的识别。随后，为缩小搜索空间，我们利用 CLIP 相似度（Radford et al., 2021）找出库中最相似的 top-$k$ 个物体类别。最后，一个名为 **HierarchicalObjectSelector** 的 VLM 智能体会依据与真值的视觉相似度，在若干仿真物体候选中选择一个。该视觉相似度估计是第 3 节所述 $L_{\mathrm{mesh}}$ 损失的代理指标。

为管理可能很大的候选池，我们采用分治式锦标赛方法。具体而言，系统会从每批最多 max_num_images 个图像所对应的候选中递归选出最佳候选，直至只剩一个候选。

**文本输入。**对于文本提示词，我们采用一个由大语言模型（LLM）智能体执行的多步骤过程。首先，一个 **TaskSpecifier** 会对可能较稀疏的提示词进行信息增密（示例见图 3(b)）。然后，指示一个 **LayoutPlanner** 描述每个物体部件及其尺寸。最后，通过余弦相似度将物体部件的 CLIP 语言嵌入与 PartNet-Mobility 数据集中的网格描述进行匹配，从而为每个部件执行网格检索。

**图 3：网格检索。**上、下两幅图分别概述了视觉输入（即图像或视频）和文本输入的重建过程。对于视觉输入，我们用高效的分治检索机制，将真值物体与库中的模板物体进行匹配。对于文本输入，我们首先提示 LLM 预测不同的物体部件及其尺寸；然后使用预计算的 CLIP 嵌入为每个部件检索网格，并将网格按规格缩放。更多细节见第 4.1 节。

图 3 上部示例中，VLM 将视觉输入描述为“一台电脑显示器”，并指出其可供性是“显示器可以被抬起”；系统通过 CLIP 在 Laptop、Camera、Display 等数据集类别中筛选候选。下部示例中，输入“三抽屉文件柜，底部有三个抽屉、顶部有一个柜体”先由 TaskSpecifier 丰富，再由 LayoutPlanner 产生各部件的名称、描述与尺寸（例如 filing_cabinet_body 的尺寸为 $[0.46, 0.38, 0.66]$），然后将部件与数据集部件描述匹配，得到对应的部件 ID。

由于数据集原始网格描述较粗糙，我们通过提示 VLM 根据每个网格的图像描述它（例如材料、形状、功能），来计算自己的标注。最后，将检索到的网格重新缩放，以匹配指定尺寸。

### 4.2　Link 放置

Link 放置系统可处理包含各部件语义名称的文本输入，并可选地接收一张输入图像。对于视频，我们提取第一帧作为图像输入。该系统由一个动作器和一个批评器组成。link 动作器负责将各 link 在 3D 空间中放置在一起。在该 API 中，放置操作通过沿某一轴对齐子 link 和父 link 的中心完成，并执行碰撞检测，以保证部件紧密放置而不相交。

处理视觉输入时，系统还使用批评器来验证动作器的方案。批评器被提示去描述输入图像与在仿真中渲染出的预测 3D 模型之间的任意视觉差异，定位动作器代码中的错误来源，并给出介于 0 到 10 的真实性评分。该真实性评分是 $L_{\mathrm{link}}$ 损失的代理指标。动作器会被指示将反馈考虑在内，并相应调整其 Python 代码。当评分超过阈值 5 时，该过程终止。图 4 左侧给出了这一过程的说明性示例。

### 4.3　关节预测

与 Link 放置类似，关节预测系统接收的输入是：包含 Link 放置 Python 代码的文本，以及可选的输入图像或视频。动作器随后扩展该 Python 代码，以加入部件间运动学关节的预测。对于视频输入，还会使用批评器验证动作器的方案。批评器被指示将输入与预测关节在仿真中运动的视频进行比较，并检查源代码，以判定成功或识别四种失败情形之一。

介于 0 到 10 的真实性评分同样是 $L_{\mathrm{joint}}$ 损失的代理指标，并用于将错误从最严重的错误（关节类型错误）到最轻微的错误（关节限位错误）进行归类。和前文一样，只要真实性评分低于阈值 5，动作器就会在考虑批评器反馈的基础上重写其代码。示例见图 4 右侧。

**图 4：**Link 放置和关节预测系统均由一个动作器和一个批评器组成。动作器产生 Python 代码，该代码会自动编译为 URDF，并在仿真中渲染。源代码、预测结果和输入模态（Link 使用图像，Joint 使用视频）被提供给批评器进行评估。动作器与批评器的协作使系统能够自我纠正错误（红框）并成功完成关节化（绿框）。

图 4(a) 的 Link 放置示意中，动作器先使用 pred_robot.place_relative_to 将 door 放到 furniture_body 的 left；批评器指出门被放在柜体侧面而非前方，真实性评分为 4。动作器改用 placement="front" 后，批评器判定预测在视觉上与真值一致，评分为 10。图 4(b) 的关节预测示意中，动作器用 pred_robot.make_revolute_joint 生成门的转动关节；批评器依次指出枢轴点应移至门的左侧、以及为向外打开应使用 global_axis=[0, 0, -1] 而非 [0, 0, 1]。据此修正后，批评器不再提出改进建议，并给出 10 分。

### 4.4　定向可供性提取

作为可选项，我们不必生成所有可能的运动学关节，而可以从输入视频中定向处理某一个特定关节。这有助于减少输入给 VLM 的 token 数量，进而降低成本，或使预测结果的自动调试更加容易。为此，我们提示一个名为 **targeted affordance extractor** 的 VLM 智能体：给定输入视频和仿真资产的分割图像（其中每个部件均以不同颜色标示），确定应被标注运动学关节的子 link。
